# IDEA-020 · 대화의 특정 지점에서 별도 인스턴스로 분기하고 필요한 결론만 합치기

## 문제와 배경

설계나 구현을 이어가다가 이해되지 않는 부분을 잠깐 깊게 물어보고 싶을 때가 있다. 지금은 그
질문과 답이 본 대화에 계속 쌓여, 본 작업에는 필요 없는 탐색 과정까지 이후 모든 턴의 컨텍스트가
된다. 질문을 참거나, 본류의 집중도와 컨텍스트를 희생하는 두 선택지만 남는다.

사용자가 원하는 것은 단순한 보조 패널이 아니다. **대화의 특정 부분을 출발점으로 독립된 대화
인스턴스를 만들고**, 그곳에서 자유롭게 확인한 다음 결과를 본 에이전트에 합칠지 말지를 직접
결정하는 대화 브랜치다.

## 사용자 경험

1. 본 대화에서 메시지 또는 내용 일부를 선택하고 `여기서 분기`를 누른다.
2. 선택 지점까지의 맥락을 물려받은 별도 인스턴스가 열린다. 분기 안에서 이어진 질문과 답은
   본류의 트랜스크립트와 컨텍스트에 들어가지 않는다.
3. 사용자는 모르는 개념을 묻거나 가정을 검증하고 여러 방향을 탐색한다. 본 에이전트의 작업은
   그대로 유지된다.
4. 탐색이 끝나면 다음 중 하나를 고른다.
   - **폐기**: 분기 대화를 닫고 본류에는 아무것도 남기지 않는다.
   - **보관**: 나중에 다시 볼 수 있도록 분기만 남긴다.
   - **본류에 합치기**: 선택한 메시지나 정리된 결론만 미리 보고 편집한 뒤 본 에이전트의 다음
     컨텍스트에 넣는다.

본류 화면에는 분기가 있었다는 가벼운 표시만 두되, 합치지 않은 대화 전문을 본 에이전트에게
주입하지 않는다. 합친 내용에는 어느 대화 지점과 분기에서 왔는지 출처를 남겨 다시 열어볼 수 있게
한다.

## 원하는 동작과 범위

- **분기 기준점**: 메시지 전체뿐 아니라 사용자가 드래그한 내용 일부를 출발점으로 삼을 수 있다.
- **독립 인스턴스**: 분기 뒤의 턴, 토큰, 모델 상태와 컨텍스트는 본류와 별도로 관리한다. UI만
  갈라놓고 같은 세션에 메시지를 이어 붙이는 방식은 이 기능으로 보지 않는다.
- **명시적 병합**: 자동으로 본류에 요약하거나 동기화하지 않는다. 사용자가 원문 일부 또는
  생성된 결론을 고르고, 실제로 들어갈 병합 내용을 확인한 뒤 승인한다.
- **대화 병합 단위**: Git처럼 기록 전체를 합치는 것이 아니라, 본류가 이후 판단에 사용할 수 있는
  하나의 명시적인 컨텍스트 캡슐을 새 사용자 메시지로 전달한다. 기존 트랜스크립트 이력을 다시
  쓰지 않는다.
- **계보와 비용 표시**: 부모 대화, 분기 지점, 사용 모델, 분기에서 쓴 토큰·비용, 병합 여부를
  확인할 수 있어야 한다.
- **중첩 분기**: 첫 버전은 한 단계 분기만 지원해도 되지만 데이터 모델은 부모 브랜치 ID와 기준
  이벤트 ID를 가져 중첩을 막지 않는다.
- **작업 부작용 격리**: 질문용 분기가 같은 작업공간을 수정하면 `폐기`가 거짓말이 된다. 기본
  분기는 읽기 전용으로 두고, 편집 도구가 필요한 분기는 별도 worktree 등 파일 변경까지 격리하는
  정책을 명시적으로 선택하게 한다.

## 완료 조건

- [ ] 메시지나 선택 영역에서 분기 인스턴스를 만들고 원래 대화와 나란히 오갈 수 있다.
- [ ] 분기에서 주고받은 내용이 병합 전에는 본 에이전트의 트랜스크립트와 다음 턴 입력에 포함되지
      않음을 실제 하네스 세션으로 검증한다.
- [ ] 분기를 폐기·보관하거나, 선택한 메시지/결론만 미리보기와 편집을 거쳐 본류에 합칠 수 있다.
- [ ] 병합된 컨텍스트에 원본 분기와 기준점의 출처가 표시되며 복사하고 다시 열 수 있다.
- [ ] 분기별 모델·토큰·비용과 현재 상태를 표시한다.
- [ ] 앱 재시작 뒤에도 부모-분기 계보와 병합 상태가 복구된다.
- [ ] 읽기 전용 분기가 파일을 바꾸지 못하며, 변경 가능한 분기는 파일 부작용의 격리 범위를
      사용자에게 분명히 보여준다.
- [ ] 생성·조회·병합·폐기 기능이 같은 AppController 동작을 사용하는 로컬 자동화 HTTP API로
      제공되고 실제 앱 E2E로 검증된다.

## 제외 범위와 미결 사항

- 하네스가 네이티브 대화 fork를 지원하는지, 앱이 기준점까지의 입력을 새 세션에 재구성해야 하는지
  하네스별 확인이 필요하다. 네이티브 분기가 아닌 것을 같은 기능인 것처럼 숨기지 않고 생성 전에
  방식과 비용 차이를 표시한다.
- 본류가 아직 턴을 실행 중일 때 어느 시점의 스냅샷을 기준으로 삼을지 결정해야 한다. 기준 이벤트
  ID는 고정되어야 하며 이후 본류 메시지가 분기에 자동 유입되면 안 된다.
- 생성된 결론을 어느 모델이 요약할지, 원문 선택과 요약 중 무엇을 기본값으로 둘지 결정해야 한다.
- 같은 분기를 여러 번 병합할 때 이미 들어간 내용을 중복 주입하지 않도록 병합 이력을 관리해야
  한다.
- 대화 컨텍스트 병합과 코드 변경 병합은 별개다. 첫 버전은 대화 컨텍스트만 다루고, 코드 변경은
  기존 worktree·diff 검토 흐름에 맡긴다.
