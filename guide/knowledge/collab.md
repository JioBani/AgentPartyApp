# 멤버 간 협업

멤버 간 직접 메시지 전송은 이 앱의 핵심 기능이다.
사용자가 멤버 A의 답변을 멤버 B에게 직접 전달하지 않아도 되도록 하는 것이 목적이다.

## 메시지 전달

- **직접 전송** — 대상 멤버를 지정하여 메시지를 보낸다.
- **전체 방송** — 발신자를 제외한 모든 멤버에게 메시지를 보낸다. 멤버별 전송 성공 여부가 각각 표시된다.
- 대화 기록에는 **발신·수신 구분**과 **발신자→수신자** 경로가 함께 표시된다.

⚠ 전체 방송은 현재 로컬 HTTP API와 에이전트용 파티 도구를 통해 주로 제공된다.

### 수신 멤버가 작업 중인 경우

- **기본값: 대기** — 현재 턴이 끝난 후 메시지를 확인한다.
- **interrupt** — 현재 작업을 중단하고 메시지를 즉시 전달한다. 긴급한 정정 사항을 전달할 때 사용한다.
- 수신 멤버에 **활성 세션이 없으면** 전송 실패로 기록되며, 기록에서 실패 여부를 확인할 수 있다.

기본 전송 방식은 작업 안정성을 위해 대기로 설정되어 있다. 다만 작업 시간이 긴 멤버는
**상당한 시간이 지난 후** 메시지를 확인할 수 있으므로, 이전 지시에 따라 작업을 계속할 수 있다.
메시지를 즉시 확인해야 하는 경우 interrupt를 사용한다.

## Message Gate — 발신 메시지 검사

멤버가 **다른 멤버에게** 보내는 메시지는 전달 전에 경량 심사 모델이 지정된 규칙에 따라 검사한다.

- 검사를 통과한 메시지는 그대로 전달된다.
- 반려된 메시지는 **전달되지 않으며**, 반려 사유와 위반 규칙이 발신 멤버의 대화에 카드로 표시된다.
- 필요한 경우 **강제 전송**할 수 있으며, Message Gate를 우회한 사실이 함께 표시된다.

⚠ 사용자가 보내는 메시지는 심사 대상이 **아니다.** 멤버 간 발신 메시지만 검사한다.
⚠ 심사 모델 실행에 실패하면 메시지를 차단하지 않고 **경고와 함께 전달한다**(fail-open).
Message Gate 오류로 파티 전체의 작업이 중단되는 것을 방지하기 위한 방식이다.
⚠ Message Gate가 켜져 있어도 규칙이 비어 있으면 메시지를 검사하지 않는다. 앱에서 해당 상태를 경고한다.

**설정 순서**: 파티 단위로 Message Gate를 켜고 규칙을 입력한다. 이후 멤버별로 Inherit / On / Off 설정을 적용할 수 있다.
심사 모델(리뷰어) 설정은 멤버 → 파티 → 앱 전역 순으로 상속된다. 변경 사항은 즉시 반영된다.
새 파티는 **꺼진 상태**로 시작한다.

사용 예: "오케스트레이터를 거치지 않고 담당자에게 직접 전달할 것", "보고는 세 줄 이내로 작성할 것".

## 서브에이전트

멤버는 하위 작업을 수행할 서브에이전트를 생성하여 작업을 분담할 수 있다.
대화창 아래 **도크**에는 생성된 서브에이전트 수와 각 서브에이전트의 실행 중·완료·실패·대기 중 상태가 표시된다.

항목을 선택하면 위임 내용, 답변, 도구 실행 결과, 소요 시간 등 상세 정보를 확인할 수 있다.
상단 breadcrumb(상위 멤버 → 서브에이전트)를 사용하여 기존 대화로 돌아갈 수 있다.

## AI의 앱 직접 조작

멤버 세션의 AI는 다음과 같은 앱의 파티 기능을 직접 실행할 수 있다.
파티·멤버 조회, 멤버 생성·삭제, 다른 멤버에게 메시지 전송, 상태 조회, 작업 중단, 전체 방송,
권한 변경, Message Gate 변경.

AI가 수행한 조작 중 **멤버 생성·삭제 내역은 전용 카드로 대화에 기록되며,** 사용자가 이후에 확인할 수 있다.

## Discord를 통한 원격 확인

Discord 봇을 연결하면 각 멤버가 전용 Discord 스레드를 생성하여 보고 채널로 사용할 수 있다.
사용자가 해당 스레드에 작성한 메시지는 멤버 세션으로 전달된다. 멤버가 유휴 상태이면 세션을 활성화하고, 작업 중이면 대기열에 추가한다.
메시지에는 처리 상태를 나타내는 이모지가 표시된다 — 📨 전달됨 · ⚙️ 처리 중 · ✅ 완료 · ⚠️ 지연.

`!`로 시작하는 제어 명령(상태·연결·중단·재시작 등)은 **LLM을 거치지 않고 처리된다.**
멤버가 응답할 수 없는 상태에서도 제어 명령은 실행된다.

⚠ 허용 사용자 ID 목록이 **비어 있으면 모든 사용자의** 메시지 전송이 차단된다. 빈 목록은 "전체 허용"을 의미하지 않는다.
⚠ 메시지는 최대 2,000자, 이미지는 최대 10MB까지 전송할 수 있다. 제한을 초과한 항목은 잘리지 않고 전송이 거부된다.
