# 기획 노트 — 비주얼 파티 블루프린트

> 상태: 아이디어 브레인스토밍

## 1. 한 문장 정의

사용자가 캔버스에 멤버 노드를 추가하고 협업 관계를 연결해, 파티의 구성과 소통 규칙을 시각적이고
감각적으로 설계·관리하는 기능.

## 2. 사용자 가치

현재 사용자는 멤버를 한 명씩 만들고 텍스트로 역할을 적은 뒤, 실제로 대화를 주고받으며 파티 구조를
머릿속에서 조립한다. 멤버 수가 늘어나면 누가 누구와 소통해야 하는지, 어떤 역할과 위계가 있는지,
보고가 어디로 모이는지 한눈에 알기 어렵다.

비주얼 블루프린트에서는 팀을 문서처럼 설명하는 대신 **직접 배치하고 연결하면서 구성**한다.

- 멤버와 역할을 한눈에 이해한다.
- 협업 관계와 소통 규칙을 연결선으로 확인한다.
- 잘못되거나 빠진 관계를 시각적으로 발견한다.
- 파티 구조를 바꾸고 결과를 즉시 확인한다.
- 실행 중에는 설계한 구조 위에서 실제 협업 흐름을 이해한다.

## 3. 기본 사용자 경험

1. 빈 캔버스 또는 기존 파티의 블루프린트를 연다.
2. 노드를 추가해 멤버를 만든다.
3. 노드에 이름, 역할과 맡은 일을 정한다.
4. 멤버 노드를 연결하고 그 관계의 목적과 소통 규칙을 정한다.
5. 팀 구조가 잘 보이도록 노드 위치를 자유롭게 배치한다.
6. 파티를 실행한 뒤 같은 화면에서 멤버 상태와 실제 협업 흐름을 본다.
7. 필요하면 노드와 연결을 수정해 파티 운영 방식을 바꾼다.

## 4. 화면의 핵심 요소

### 멤버 노드

- 멤버 이름
- 역할과 맡은 과업
- 현재 상태
- 다른 멤버와의 연결
- 선택 시 상세 설정과 기존 멤버 탭으로 이동

### 협업 연결선

연결선은 단순히 “메시지를 보낼 수 있음”만 의미하지 않는다. 두 멤버가 어떤 관계로 협업하는지를
사용자가 이해할 수 있어야 한다.

예시:

- 구현 담당이 기획 담당에게 요구사항을 질문한다.
- 구현 담당이 완료 결과를 검토 담당에게 보낸다.
- 테스트 담당이 실패를 구현 담당에게 돌려보낸다.
- 각 담당자가 진행 상황을 과업 관리자에게 보고한다.

연결의 방향, 목적, 허용되는 소통과 보고 규칙을 어느 수준까지 사용자가 직접 정할지는 미결정이다.

### 자유 배치

노드 위치 자체가 팀 구조를 이해하는 수단이다. 사용자는 위계, 업무 단계나 협업 묶음이 잘 보이도록
위치를 바꾼다. 자동 정렬을 제공하더라도 사용자의 수동 배치를 덮어쓰지 않아야 한다.

## 5. 실행 흐름 보기

블루프린트는 파티를 만들 때만 쓰는 정적 편집 화면에 머물지 않는다. 이후에는 같은 노드와 연결 위에
실제 활동을 겹쳐 보여주는 현황판으로 확장한다.

- 현재 작업 중인 멤버
- 멤버 간 질문·보고·인계
- 과업의 이동과 진행 상태
- 막힘, 승인 필요와 실패
- 사용자 질문이 어느 멤버에게 전달됐는지

설계된 관계와 실제 흐름을 함께 보면, 파티가 의도대로 협업하는지 사용자가 직관적으로 확인할 수 있다.

## 6. 제품 원칙

1. **그래프를 만드는 도구가 아니라 파티를 만드는 도구다.** 범용 노드 타입과 프로그래밍 개념을
   늘리기보다 멤버·역할·소통·보고처럼 협업에 필요한 개념만 제공한다.
2. **텍스트 설정을 그림으로 옮기는 데 그치지 않는다.** 연결하고 배치하는 행동 자체가 파티 구성으로
   이어져야 한다.
3. **보기와 편집을 분리하지 않는다.** 구조를 보다가 바로 멤버와 관계를 수정할 수 있어야 한다.
4. **설계와 실제 흐름을 연결한다.** 파티 실행 후에도 같은 블루프린트가 현황판으로 이어진다.
5. **단순하게 시작한다.** 노드 추가, 연결, 역할 확인, 자유 배치를 먼저 제공하고 복잡한 규칙 편집과
   실행 흐름 시각화는 단계적으로 확장한다.

## 7. 단계적 범위

### 최소 기능

- 기존 파티 멤버를 노드로 표시
- 캔버스에서 멤버 노드 추가
- 노드 연결과 연결 목적 표시
- 노드 위치 자유 배치와 저장
- 노드 선택 시 역할 확인·수정

### 확장

- 연결별 소통·보고 규칙 편집
- 역할·위계·과업 관계를 서로 다른 시각 언어로 구분
- 실제 멤버 간 메시지와 과업 진행 흐름 표시
- 막힘·승인·실패 강조와 현황판 인터랙션
- 재사용 가능한 파티 블루프린트 템플릿

## 8. 미결정 질문

- 연결선 하나가 어떤 사용자 개념을 의미해야 하는가?
- 사용자가 소통 규칙을 얼마나 세밀하게 설정해야 하는가?
- 위계, 과업 의존성과 메시지 흐름을 한 화면에서 어떻게 구분할 것인가?
- 기존 목록·마법사 방식과 블루프린트 방식을 함께 유지할 것인가?
- 정적 설계와 실행 중 현황을 같은 모드에서 보여줄 것인가?
- 파티 구성을 템플릿으로 저장·복제·공유할 것인가?

## 9. 연관 기능과 구분

- **파티 현황판**: 만들어진 파티의 현재 상태와 실제 흐름을 관찰하고 개입한다.
- **멤버 소통·작업 다이어그램**: 관측된 멤버 활동을 시각화한다.
- **파티 멤버 라우팅**: 하나의 통합 채팅에서 적절한 담당 멤버에게 사용자 입력을 전달한다.
- **비주얼 파티 블루프린트**: 파티 구성, 협업 관계와 규칙을 시각적으로 만들고 수정한다.

이 기능들은 같은 노드·관계·상태 정보를 공유할 수 있지만 사용자 목적이 다르므로 기획상 구분한다.
