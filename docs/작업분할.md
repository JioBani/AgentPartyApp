## 4. 공유 파일 규칙과 병합 순서

`src/renderer/App.tsx` 는 **네 레인이 모두 조금씩 건드리는 유일한 파일**이다. 소유권을 나눌 수 없으므로 순서로 푼다.

| 레인 | App.tsx 에서 건드리는 지점 |
|---|---|
| W1 | `:607-610` `sessionIdFor`, `:666-671` compact, `:904-907` 권한 호출 |
| W2 | `:749`, `:765` 사용자 블록 삽입 |
| W3 | `:754` sendMemberMessage 호출, `:957` 설정 저장 |

⚠️ **W2 와 W3 는 `749~765` 구간에서 실제로 겹친다.**

**병합 순서: W4 → W1 → W2 → W3**

- W4 가 먼저 — `styles.css` 를 독점하므로 뒤 레인이 rebase 할 때 CSS 충돌이 남지 않는다
- W1 이 그다음 — `memberStatus.ts` 를 W2 와 공유하고, App.tsx 지점이 가장 흩어져 있다
- W2 → W3 순서는 **협상 불가**: W3 의 `:754` 수정이 W2 의 `:749/:765` 수정 위에 얹혀야 한다

각 레인은 **자기 차례가 오면 main 의 지시에 따라 `master` 를 rebase** 한 뒤 typecheck·테스트를 다시 통과시킨다.
병합은 main 이 한다. 레인이 직접 `master` 에 머지하지 않는다.

## 5. 모든 레인 공통 규칙

1. **자기 워크트리 밖의 파일을 건드리지 않는다.** 다른 레인 소유 파일이 필요하면 main 에게 보고.
2. **근본 원인을 고친다.** 우회·임시방편·조용한 fallback 금지 (AGENTS.md).
3. **완료 기준** — 항목 하나를 끝낼 때마다:
   - `npm run typecheck` 통과
   - 관련 단위/렌더 테스트 통과 (예: `test:cursor`, `test:member-wizard`, `test:layout`, `test:composer-vision`, `test:markdown`, `test:stall-status` 등 해당하는 것)
   - **실제 앱 전체 프로세스 E2E 로 사용자 동선을 확인** (AGENTS.md + 프로젝트 관행). 여러 레인이 동시에 앱을 띄우므로 반드시 `AGENTPARTY_ALLOW_MULTI_INSTANCE=1` 를 설정하고, **포트를 고정하지 말고** 인스턴스 파일 발견을 쓸 것. 자세한 건 `docs/E2E_TESTING.md`
   - 항목 단위로 커밋 (한 커밋에 여러 항목을 섞지 않는다)
4. **새 QA 스크립트나 `/api` 엔드포인트를 추가하면 같은 변경에서 문서도 갱신** (`docs/E2E_TESTING.md` 표 / `apiSpec.ts` + `docs/API.md`).
5. **막히면 즉시 보고한다.** 30분 이상 같은 자리에서 헤매지 말 것.
6. 항목 하나가 끝날 때마다 main 에게 **한 줄 보고** (무엇을·어디를·어떻게 검증했는지).
