## 4. 공유 파일 규칙과 병합 순서

`src/renderer/App.tsx` 는 **네 레인이 모두 조금씩 건드리는 유일한 파일**이다. 소유권을 나눌 수 없으므로 순서로 푼다.

| 레인 | App.tsx 에서 건드리는 지점 |
|---|---|
| W1 | `:607-610` `sessionIdFor`, `:666-671` compact, `:904-907` 권한 호출 |
| W2 | `:749`, `:765` 사용자 블록 삽입 |
| W3 | `:754` sendMemberMessage 호출, `:957` 설정 저장 |

⚠️ **W2 와 W3 는 `749~765` 구간에서 실제로 겹친다.**

**병합 순서: W4 → W1 → W2 → W3**

- W4 가 먼저 — `styles.css` 를 독점하므로 뒤 레인이 rebase 할 때 CSS 충돌이 남지 않는다
- W1 이 그다음 — `memberStatus.ts` 를 W2 와 공유하고, App.tsx 지점이 가장 흩어져 있다
- W2 → W3 순서는 **협상 불가**: W3 의 `:754` 수정이 W2 의 `:749/:765` 수정 위에 얹혀야 한다

각 레인은 **자기 차례가 오면 main 의 지시에 따라 `master` 를 rebase** 한 뒤 typecheck·테스트를 다시 통과시킨다.
병합은 main 이 한다. 레인이 직접 `master` 에 머지하지 않는다.

### 사람 손이 필요한 확인 (자동화 불가)

| 항목 | 확인할 것 | 왜 자동화가 안 되나 |
|---|---|---|
| [P-3]10 파일 드롭 | 실제 파일을 입력창에 **끌어다 놓고** 경로가 텍스트로 들어오는지 | OS 드래그앤드롭은 자동화 API 로 합성 불가(키 입력과 달리 드래그 이벤트가 없다). 페이지 안에서 만든 파일은 디스크에 없어 경로가 정당하게 비어 나온다 → jsdom 은 그 지점을 목으로 둘 수밖에 없다. 배선이 깨지면 앱이 죽는 종류라 기존 E2E 가 빨개지긴 하지만, "진짜 경로가 진짜로 들어온다"는 증명되지 않는다 |
| [P-3]9 이미지 복사 | 첨부 썸네일의 **복사 버튼 모양·위치** | 첨부가 붙은 상태를 자동으로 만들 수 없다. **클립보드에 실제로 써지는 것 자체는 실앱에서 검증됨** — 남은 건 외형뿐 |

> 둘 다 앱에서 30초면 확인된다. W3 가 앱을 띄워둘 수 있다.

**참고 — 앞으로 nativeImage 경로를 테스트할 사람을 위해**: Electron 33 의 이미지 디코더는 **1x1 PNG 를 거부한다**(16x16 은 정상). 구조적으로 멀쩡한 PNG 인데도 그렇다. 이 프로젝트의 여러 테스트가 1x1 PNG 를 픽스처로 쓰고 있어서 "내 바이트가 깨졌나"로 헤매기 쉽다. (W3 발견, 해당 코드 주석과 E2E 에 기록됨)

- **`✗` 를 찍고도 exit 0 이 되는 스크립트는 없다.** 상상 가능한 최악(`test:ui` 가 통째로 거짓 초록)이 실재하지 않는다. 71개 전수 확인, 첫 grep 의 후보 7개는 전부 오탐으로 판명

## 4-3. 검증이 스스로 만료를 말하게 할 것 (2026-08-01 확립)

e2e 는 **"지금 도는 빌드가 내 워크트리다"를 스크립트 자체로 단언**한다. 창구는 레인 성격에 따라 다르다.

| 형태 | 방법 | 유효기간 |
|---|---|---|
| **실행 루트 필드** | 상태 응답의 실행 루트를 자기 `import.meta.url` 기준 루트와 대조 | **항상 유효** (W1 이 추가) |
| spec 엔드포인트 | `/api/spec` 에 자기 브랜치에만 있는 라우트가 있는지 | ⚠️ **병합 전에만.** 병합되면 모두가 갖게 되어 항상 통과 |
| DOM 클래스 | 자기 브랜치에만 있는 셀렉터를 capture click 으로 (없으면 요청이 실패한다) | ⚠️ **병합 전에만.** 위와 같음 |

⚠️ **아래 두 형태는 병합 후 조용히 "항상 통과하는 장식"이 된다.** 이번 사이클에 우리가 잡은 죽은 노브들
(`AGENTPARTY_WORKSPACE`, `sdkLoader`, `ALLOW_MULTI_INSTANCE`)과 **같은 궤적**이다 — 전부 처음엔 진짜로 작동했다.

**그래서 규칙**: 만료되는 단언은 **그 단언 바로 옆 주석에 만료 조건을 적는다.**
> 예: `// 이 클래스가 master 에 병합되는 순간 이 단언은 변별력을 잃는다 — 실행 루트 필드로 갈아타라`

문서에만 적으면 다음 사람이 문서를 안 읽고 그대로 산다. 이번 사이클에 우리를 문 게 전부 **주석이 코드보다
좋게 말한 경우**였는데, 이건 반대로 **주석이 자기 만료를 미리 말하게** 하는 것이다. (W2 제안)

## 5. 모든 레인 공통 규칙

1. **자기 워크트리 밖의 파일을 건드리지 않는다.** 다른 레인 소유 파일이 필요하면 main 에게 보고.
2. **근본 원인을 고친다.** 우회·임시방편·조용한 fallback 금지 (AGENTS.md).
3. **완료 기준** — 항목 하나를 끝낼 때마다:
   - `npm run typecheck` 통과
   - 관련 단위/렌더 테스트 통과 (예: `test:cursor`, `test:member-wizard`, `test:layout`, `test:composer-vision`, `test:markdown`, `test:stall-status` 등 해당하는 것)
   - **실제 앱 전체 프로세스 E2E 로 사용자 동선을 확인** (AGENTS.md + 프로젝트 관행). 여러 레인이 동시에 앱을 띄우므로 반드시 `AGENTPARTY_ALLOW_MULTI_INSTANCE=1` 를 설정하고, **포트를 고정하지 말고** 인스턴스 파일 발견을 쓸 것. 자세한 건 `docs/E2E_TESTING.md`
   - 항목 단위로 커밋 (한 커밋에 여러 항목을 섞지 않는다)
4. **새 QA 스크립트나 `/api` 엔드포인트를 추가하면 같은 변경에서 문서도 갱신** (`docs/E2E_TESTING.md` 표 / `apiSpec.ts` + `docs/API.md`).
5. **막히면 즉시 보고한다.** 30분 이상 같은 자리에서 헤매지 말 것.
6. 항목 하나가 끝날 때마다 main 에게 **한 줄 보고** (무엇을·어디를·어떻게 검증했는지).
