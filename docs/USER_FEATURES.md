이 문서는 AgentParty Desktop이 현재 제공하는 기능을 사용자 관점에서 정리한다.
화면에 직접 노출된 기능뿐 아니라 동일한 사용자 기능을 제어하는 로컬 자동화 HTTP API도 함께 다룬다.

AgentParty는 로컬 작업공간에서 Claude Code, Codex, Cursor CLI를 실행하고 여러 AI 멤버를 파티 단위로 운영하는 데스크톱 워크벤치다. 사용자는 멤버마다 하네스, 모델, 추론 강도, 권한을 지정하고 여러 대화를 탭과 분할 패널에서 동시에 관리할 수 있다.

## 기능 지도

- **I. 시작과 환경**
  - 인증과 제공자 연결
  - 기본 탐색과 창
  - 작업공간과 다중 창
- **II. 파티와 작업 화면**
  - 파티
  - 멤버 생성과 관리
  - 멀티패널과 탭
- **III. 대화와 세션**
  - 메시지 작성과 전송
  - 대화 기록
  - 승인과 사용자 질문
  - 세션 생명주기
- **IV. AI 실행과 협업 제어**
  - 모델과 런타임
  - 권한과 안전 정책
  - 컨텍스트와 압축
  - Message Gate
  - 멤버 간 통신
  - 서브에이전트
  - MCP 서버
- **V. 운영과 자동화**
  - 계정 사용 한도
  - 전역 런타임 설정
  - 자동화와 로그
  - 현재 UI 노출 범위와 제약

## I. 시작과 환경

### 1. 인증과 제공자 연결

#### 1.1 AgentParty 계정

- AgentParty 자체 회원가입이나 자체 계정 로그인은 제공하지 않는다.
- 실제 인증은 Claude, Codex, Cursor, OpenRouter 등 모델 제공자별로 이루어진다.
- 좌측 하단의 `JD` 아바타는 현재 표시 요소이며 별도 계정 메뉴는 연결되어 있지 않다.

#### 1.2 Claude 구독 연결

- `인증` 화면에서 Claude 구독 연결을 시작할 수 있다.
- 연결을 시작하면 시스템 기본 브라우저에서 OAuth 승인을 진행한다.
- 승인 진행 중에는 `인증 대기` 상태와 진행 표시가 나타나며 연결 버튼이 비활성화된다.
- 기본 브라우저의 계정이나 프로필이 맞지 않는 경우를 위해 OAuth URL을 직접 선택하고 복사할 수 있다.
- 승인이 완료되면 Claude 모델을 Claude Code와 Codex 하네스 양쪽에서 사용할 수 있다.
- 저장된 refresh token을 재사용하므로 앱을 다시 실행할 때마다 로그인할 필요가 없다.
- 로컬 구독 브리지는 앱 시작 시 자동으로 시작되며 연결 상태가 지속적으로 감시된다.
- 브리지가 설치되지 않은 경우 공식 Windows 바이너리를 다운로드하고 GitHub에 게시된 SHA-256 값으로 검증한 뒤 설치한다.
- 다운로드 실패, 무결성 검증 실패, 실행 실패는 사용자에게 오류로 표시되며 다른 제공자로 자동 대체되지 않는다.

#### 1.3 Claude 연결 해제

- 백엔드와 로컬 HTTP API는 Claude 구독 연결 해제를 지원한다.
- 연결을 해제하면 Claude 자격 증명을 브리지가 감시하는 디렉터리에서 제거한다.
- 자격 증명은 즉시 영구 삭제되지 않고 앱 데이터의 복구 가능한 백업 위치로 이동한다.
- 연결 해제 후 모델 검색을 다시 실행하여 Claude 모델이 실제로 더 이상 제공되지 않는지 확인한다.
- 다른 자격 증명 소스가 Claude 모델을 계속 제공하면 연결 해제가 완료된 것으로 처리하지 않고 오류를 반환한다.
- 현재 인증 화면에는 Claude용 `연결 끊기` 버튼이 노출되지 않아 이 동작은 로컬 HTTP API를 통해서만 실행할 수 있다.

#### 1.4 Codex/ChatGPT 구독 연결

- `인증` 화면에서 Codex 구독 연결을 시작할 수 있다.
- 시스템 기본 브라우저에서 OAuth 승인을 진행한다.
- 진행 중 상태, OAuth URL 복사, 완료 후 자동 상태 갱신은 Claude 연결과 동일한 방식으로 동작한다.
- 한 번 연결하면 GPT 모델을 Codex와 Claude Code 하네스 양쪽에서 사용할 수 있다.
- 선택된 브리지 계정의 인증 정보는 로컬 및 WSL Codex 엔진의 네이티브 인증 저장소에도 반영된다.
- OAuth 토큰 원문은 UI나 HTTP API 응답으로 노출되지 않는다.

#### 1.5 Codex 연결 해제

- Codex가 연결된 상태에서는 인증 화면에 `연결 끊기` 버튼이 표시된다.
- 첫 번째 클릭은 확인 대기 상태로 전환하고, 두 번째 클릭에서 실제 연결 해제를 실행한다.
- 버튼이 포커스를 잃으면 확인 대기 상태가 해제된다.
- 처리 중에는 진행 표시와 연결 해제 중 상태가 나타난다.
- 자격 증명은 복구 가능한 백업 위치로 이동된다.
- 모델 검색을 다시 수행하여 Codex 모델이 실제로 사라졌는지 확인한다.
- 인증 변경은 활성 로컬 및 WSL 엔진에도 전파된다.
- 유휴 세션은 Codex app-server를 재시작하고 기존 스레드를 즉시 이어서 연다.
- 응답 생성 중인 세션은 현재 턴이 끝난 뒤 인증 재시작을 수행한다.
- 영향을 받은 세션에는 인증 변경 진단 메시지가 표시된다.
- 자격 증명이 없거나 다른 자격 증명 소스가 모델을 계속 제공하면 오류가 표시된다.

#### 1.6 Cursor 인증

- AgentParty 내부에는 Cursor 로그인 또는 로그아웃 버튼이 없다.
- 로컬 Cursor Agent CLI에 로그인된 계정을 그대로 사용한다.
- Cursor CLI 설치와 실행 파일 탐지 결과가 인증 상태에 반영된다.
- CLI가 없거나 실행할 수 없으면 미설정 상태 또는 진단 오류가 표시된다.
- CLI가 설치되어 있어도 Grok 4.5 사용 가능 여부는 로그인한 Cursor 플랜에 따라 달라진다.

#### 1.7 OpenRouter API 키

- 인증 화면의 비밀번호 입력란에 OpenRouter API 키를 입력할 수 있다.
- 공백만 입력한 경우 저장 버튼이 활성화되지 않는다.
- 저장된 키는 마스킹된 형태로 표시된다.
- `테스트` 버튼으로 OpenRouter 모델 API를 호출하여 키의 유효성을 확인할 수 있다.
- 테스트 결과는 정상, 유효하지 않음, 네트워크 오류로 구분된다.
- 앱 설정에 저장된 키가 없으면 `OPENROUTER_API_KEY` 환경 변수도 사용할 수 있다.
- 키가 없는 상태에서 OpenRouter 모델을 시작하면 명시적인 오류가 발생한다.
- HTTP API는 키 삭제를 지원하지만 현재 인증 화면에는 키 삭제 버튼이 없다.

#### 1.8 인증 상태 표시

제공자별로 다음 상태를 구분하여 표시한다.

- 사용 가능
- 설정됨
- 정상
- 인증 대기
- 미설정
- 유효하지 않음
- 네트워크 오류

### 2. 기본 탐색과 창

#### 2.1 기본 화면

좌측 탐색에서 다음 화면으로 이동할 수 있다.

- `Workbench`: 파티와 멤버의 실제 작업 화면
- `세션`: 활성 세션과 재개 가능한 이전 세션
- `인증`: 제공자 로그인과 API 키 관리
- `런타임`: 모델, 하네스, 권한 등의 전역 기본값
- `자동화`: 로컬 HTTP API와 로그 정보

#### 2.2 메뉴와 단축키

- `Ctrl/Cmd+1`: Workbench
- `Ctrl/Cmd+2`: 세션
- `Ctrl/Cmd+3`: 인증
- `Ctrl/Cmd+4`: 런타임
- `Ctrl/Cmd+5`: 자동화
- `Ctrl/Cmd+N`: 새 파티
- `Ctrl/Cmd+Shift+N`: 새 창
- File 메뉴에서 새 창, 작업공간 선택, 창 닫기를 실행할 수 있다.
- View 메뉴에서 새로고침과 개발자 도구 열기를 실행할 수 있다.

#### 2.3 창 제어

- 제목 표시줄에서 창을 최소화할 수 있다.
- 최대화 버튼으로 최대화와 원래 크기를 전환할 수 있다.
- 닫기 버튼으로 현재 창을 닫을 수 있다.

#### 2.4 테마

- 제목 표시줄의 테마 버튼으로 밝은 테마와 어두운 테마를 순환한다.
- 선택한 테마는 로컬 저장소에 저장되어 앱을 다시 실행한 뒤에도 유지된다.

#### 2.5 대화 글자 크기

- 세션 또는 대화 영역 위에서 `Ctrl+마우스 휠`을 사용해 transcript 글자 크기를 조절할 수 있다.
- 배율은 설정에 저장되며 다음 실행에서도 복원된다.
- 일반 브라우저 확대가 아니라 대화 텍스트에만 적용된다.

### 3. 작업공간과 다중 창

#### 3.1 작업공간 선택

- 상단 `작업공간` 버튼 또는 File 메뉴에서 작업할 폴더를 선택할 수 있다.
- 작업공간을 변경하면 해당 작업공간의 파티, 멤버, 세션 상태를 불러온다.
- 상태는 작업공간의 `.agent_party_app` 디렉터리에 저장된다.
- 이전 `.agentparty` 저장소도 호환을 위해 읽을 수 있다.

#### 3.2 로컬 작업공간

- 일반적인 Windows 절대 경로를 작업공간으로 사용할 수 있다.
- 멤버 세션은 선택한 프로젝트 루트에서 시작한다.
- 멤버별 역할 파일은 별도 멤버 디렉터리에 저장되지만 실제 AI 작업 디렉터리는 프로젝트 루트다.

#### 3.3 WSL 작업공간

- `wsl+<distro>:/path` 형식의 작업공간을 지원한다.
- `\\wsl$\<distro>\...`와 `\\wsl.localhost\<distro>\...` 형식도 WSL 경로로 인식한다.
- WSL 작업공간에서는 화면 상단에 배포판 이름이 포함된 WSL 배지가 표시된다.
- WSL 엔진의 작업 디렉터리는 Linux 경로를 그대로 사용한다.
- 해석할 수 없는 상대 경로나 잘못된 실행 인자를 임의의 경로로 조용히 바꾸지 않고 경고로 표시한다.

#### 3.4 다중 창

- 하나의 앱 프로세스에서 여러 창을 열 수 있다.
- 각 창은 서로 다른 작업공간을 볼 수 있다.
- 같은 작업공간을 여러 창에서 열면 동일한 파티 상태를 공유하고 변경 사항을 실시간으로 갱신한다.
- 로컬 자동화 API는 창 ID를 지정하여 특정 창의 작업공간과 화면을 제어할 수 있다.

## II. 파티와 작업 화면

### 4. 파티

#### 4.1 파티 생성

- 사이드바의 파티 이름 입력란을 통해 새 파티를 만들 수 있다.
- `+` 버튼을 누르면 Message Gate 설정을 포함한 새 파티 모달이 열린다.
- 이름이 비어 있으면 파티를 만들 수 없다.
- 파티 생성 시 `main` 멤버가 자동 생성된다.
- `main`은 슬래시 명령과 스킬 목록을 준비하기 위해 초기 세션 시작을 시도한다.
- 초기 시작에 실패하더라도 실패를 숨기지 않고 파티 명령 결과와 로그에 표시한다.

#### 4.2 파티 생성 시 Message Gate

- 새 파티의 Message Gate는 기본적으로 꺼져 있다.
- 생성 시 Gate를 켜고 파티 전체에 적용할 통신 규칙을 입력할 수 있다.
- 리뷰어는 런타임 설정의 Message Gate 기본 모델과 effort를 사용한다.
- 새 파티 모달은 바깥 영역 클릭으로 닫히지 않으며 Cancel 또는 닫기 버튼으로 종료한다.

#### 4.3 파티 목록과 선택

- 파티 목록에서 현재 작업공간의 파티를 확인할 수 있다.
- 현재 선택된 파티에는 선택 표시가 나타난다.
- 활성 파티에는 전체 멤버 수와 작업 중인 멤버 수가 표시된다.
- 다른 파티를 선택하면 해당 파티의 멤버와 저장된 패널 배치를 불러온다.

#### 4.4 파티 삭제

- 파티 행의 우클릭 메뉴에서 삭제할 수 있다.
- 첫 번째 동작에서 삭제 확인 상태로 전환되고, 다시 선택해야 실제 삭제가 실행된다.
- 삭제 시 파티가 소유한 모든 활성 세션을 닫는다.
- 파티의 멤버, 메시지, 역할 파일과 디스크 저장소를 삭제한다.
- 활성 파티를 삭제하면 다른 파티가 선택되며 남은 파티가 없으면 무선택 상태가 된다.
- 파티 삭제는 영구적 동작이다.

### 5. 멤버 생성과 관리

#### 5.1 멤버 생성 마법사

멤버 생성은 다음 순서로 진행된다.

1. 이름
2. 하네스
3. 모델
4. 추론
5. 권한
6. 역할 및 최종 확인

#### 5.2 멤버 이름

- 이름은 영문자로 시작해야 한다.
- 이후에는 영문자, 숫자, `_`, `-`를 사용할 수 있다.
- 이름이 유효하지 않으면 다음 단계로 진행할 수 없다.
- 같은 파티 안에서 중복되는 이름은 생성 오류로 처리된다.

#### 5.3 하네스

다음 실행 환경을 선택할 수 있다.

- Claude Code
- Codex
- Cursor CLI

하네스는 실제로 AI 세션을 실행하는 프로세스를 의미한다. 모델 제공자와는 별개이므로 Claude Code 하네스에서 GPT 모델을 사용하거나 Codex 하네스에서 Claude 모델을 사용하는 것도 가능하다.

#### 5.4 모델

- 선택한 하네스에서 실행 가능한 모델만 표시된다.
- 모델은 Claude, Codex, Cursor, OpenRouter 등 제공자별로 그룹화된다.
- 모델별 성능, 비용, 컨텍스트 크기, 이미지 입력 지원 여부를 확인할 수 있다.
- 사용할 수 없는 모델은 비활성화된다.
- Codex 계정 모델을 불러오는 동안 로딩 상태가 표시된다.
- 모델 검색이 실패하면 정적 기본 모델과 오류 내용을 표시하고 `다시 시도` 기능을 제공한다.
- 검색 실패를 다른 제공자의 모델로 조용히 대체하지 않는다.

#### 5.5 추론

선택한 모델이 지원하는 경우 다음 항목을 설정할 수 있다.

- Effort: low, medium, high, xhigh, max 등
- Thinking: adaptive, enabled, disabled
- Thinking token budget

지원하지 않는 옵션은 표시하지 않는다.

#### 5.6 초기 권한

Claude Code 계열 멤버는 다음 단일 권한 모드를 사용한다.

- Default
- Accept edits
- Plan
- Auto
- Don’t ask
- Bypass permissions

Codex 계열 멤버는 샌드박스와 승인 정책을 함께 사용한다.

- Read Only
- Auto
- Full Access
- Custom
- Guardian 활성화 여부

#### 5.7 역할과 생성 확인

- 멤버가 담당할 역할 또는 요구사항을 입력한다.
- 역할이 비어 있으면 멤버를 생성할 수 없다.
- 마지막 단계에서 이름, 하네스, 모델, 추론 설정, 권한을 확인한다.
- 생성된 멤버는 별도의 새 패널에 자동으로 열린다.

#### 5.8 멤버 열기

- 사이드바의 멤버를 클릭하거나 키보드 Enter/Space로 열 수 있다.
- 이미 열려 있는 멤버라면 기존 탭과 패널에 포커스한다.
- 아직 열리지 않은 멤버라면 현재 패널에 새 탭으로 추가한다.
- 화면에 열린 활성 멤버는 명령 팔레트를 준비하기 위해 세션을 미리 시작할 수 있다.
- 명시적으로 닫힌 멤버는 자동 사전 시작으로 다시 열리지 않는다.

#### 5.9 멤버 상태

사이드바와 패널에서 다음 상태를 구분한다.

- 시작 전
- 준비 또는 유휴
- 요청 중
- 응답 중
- 중단 중
- 닫힘
- 오류
- 승인 대기
- 읽지 않은 메시지 수

#### 5.10 멤버 삭제

- 멤버 행의 우클릭 메뉴에서 멤버를 완전히 삭제할 수 있다.
- `main` 멤버는 삭제할 수 없다.
- 멤버 삭제는 활성 세션, 멤버 등록 정보, 역할 스캐폴드를 제거하는 파괴적 동작이다.

### 6. 멀티패널과 탭

#### 6.1 탭

- 한 패널 안에 여러 멤버 탭을 둘 수 있다.
- 탭을 클릭해 활성 멤버를 변경한다.
- 탭의 닫기 버튼은 화면 탭뿐 아니라 해당 멤버의 활성 세션도 닫는다.
- 멤버 등록 정보는 유지되므로 사이드바에서 다시 열 수 있다.
- 패널의 `+` 버튼으로 아직 열리지 않은 멤버를 추가할 수 있다.

#### 6.2 패널 분할

- 패널의 분할 버튼으로 오른쪽에 새 패널을 만들 수 있다.
- 분할된 새 패널은 현재 활성 멤버로 시작한다.
- 탭을 새 패널 영역으로 드래그해 별도의 패널을 만들 수도 있다.

#### 6.3 탭 드래그

- 같은 패널 안에서 탭 순서를 변경할 수 있다.
- 탭을 다른 패널로 이동할 수 있다.
- 이동 결과 기존 패널이 비면 해당 패널은 자동 제거된다.
- 드래그 중 이동 대상 패널과 새 패널 생성 영역이 시각적으로 표시된다.

#### 6.4 패널과 사이드바 크기

- 패널 사이 구분선을 드래그해 인접 패널의 너비를 조절한다.
- 패널이 너무 작아지지 않도록 최소 비율이 적용된다.
- 패널 폭에 따라 wide, mid, narrow 밀도로 UI가 변경된다.
- 파티 사이드바를 접거나 다시 열 수 있다.
- 사이드바 구분선을 드래그해 너비를 조절할 수 있다.

#### 6.5 레이아웃 저장

- 파티마다 열린 탭, 패널 구성, 활성 탭, 패널 비율을 저장한다.
- 파티를 다시 선택하거나 앱을 다시 열면 마지막 레이아웃을 복원한다.
- 삭제된 멤버의 탭은 복원 과정에서 자동으로 제거된다.
- 사이드바 열림 상태와 너비도 로컬에 저장된다.

## III. 대화와 세션

### 7. 메시지 작성과 전송

#### 7.1 텍스트 입력

- 멤버마다 별도의 메시지 입력창을 제공한다.
- 넓은 패널에서는 여러 줄 textarea가 내용에 맞춰 자동으로 커진다.
- 최대 높이를 넘으면 입력창 내부가 스크롤된다.
- 넓은 입력창에서는 `Ctrl/Cmd+Enter`로 전송한다.
- 좁은 패널에서는 한 줄 입력창으로 바뀌고 Enter로 전송할 수 있다.
- 텍스트와 첨부 이미지가 모두 없으면 전송되지 않는다.
- 전송 직후 사용자 메시지를 대화에 먼저 표시한다.

#### 7.2 최초 메시지와 세션 시작

- 아직 세션이 없는 멤버에게 메시지를 보내면 해당 멤버의 저장된 하네스, 모델, effort, 권한으로 세션을 자동 시작한다.
- 전역 기본값이 이미 저장된 멤버 고유 설정을 덮어쓰지 않는다.
- 동시에 여러 시작 요청이 들어와도 중복 세션을 만들지 않는다.
- 저장된 하네스 thread ID가 있으면 기존 모델 대화를 이어간다.

#### 7.3 이미지 첨부

- 클립보드 붙여넣기로 이미지를 첨부할 수 있다.
- 이미지 파일을 입력창에 드래그 앤 드롭할 수 있다.
- 전송 전 미리보기를 확인하고 이미지를 개별 제거할 수 있다.
- 모델별 최대 이미지 수와 이미지당 최대 크기를 적용한다.
- 이미지 읽기 실패, 크기 초과, 개수 초과는 사용자에게 오류로 표시한다.
- 이미지 미지원 모델에서는 첨부를 거절하고 이유를 표시한다.
- 이미지 지원 여부가 불명확한 모델은 첨부를 허용하되 실제 제공자 오류가 발생하면 진단 카드로 표시한다.
- 저장된 이전 대화는 저장 용량을 줄이기 위해 이미지 원본 대신 이미지 이름만 복원할 수 있다.

#### 7.4 응답 중지와 강제 종료

- 멤버가 응답 중일 때 Send 버튼은 Stop 버튼으로 바뀐다.
- Stop은 현재 턴에 interrupt 요청을 보낸다.
- 정상 중단이 완료되면 세션이 유휴 상태로 돌아간다.
- 중단 요청이 약 5초 이상 처리되지 않으면 같은 버튼이 `강제 종료`로 바뀐다.
- 강제 종료는 하네스가 끝내지 않은 앱 측 턴을 해제하여 뒤에 대기 중인 메시지를 처리할 수 있게 한다.
- 강제 종료는 하네스 프로세스 자체를 종료하는 기능은 아니다.

#### 7.5 슬래시 명령 팔레트

- 입력 시작 위치에서 `/`를 입력하면 하네스별 명령 팔레트가 열린다.
- Commands, Skills, Agents, MCP prompts, Plugins, AgentParty 범주로 명령을 구분한다.
- 명령 이름과 설명을 기준으로 검색할 수 있다.
- 위/아래 키로 이동하고 Enter로 선택하며 Escape로 닫을 수 있다.
- 명령의 설명, 인자 형식, 출처를 표시한다.
- git 필요, 읽기 전용, 파일 수정, 백그라운드, 클라우드, 인증 필요, 파괴적 기능 등의 속성을 배지로 표시한다.
- 실제 하네스가 보고한 명령, 플러그인, 스킬, MCP 프롬프트가 목록에 반영된다.
- 일부 항목은 텍스트 삽입 대신 즉시 compact, restart, interrupt 동작을 실행한다.
- Cursor에서는 컨텍스트 압축 명령으로 `/compress`를 사용한다.

### 8. 대화 기록

#### 8.1 사용자와 AI 메시지

- 사용자 메시지, 첨부 이미지, 전송 시간을 표시한다.
- AI 응답은 Markdown과 GitHub Flavored Markdown으로 렌더링한다.
- 코드 블록, 표, 링크, 목록 등을 표시할 수 있다.
- 긴 메시지는 일부만 미리 표시하고 `전체 보기` 모달에서 전체 내용을 확인할 수 있다.

#### 8.2 추론

- 모델이 제공한 reasoning은 접을 수 있는 별도 카드로 표시한다.
- 사용자는 필요할 때 추론 내용을 펼쳐서 확인할 수 있다.

#### 8.3 도구 실행

- 도구명, 도구 출처, 주요 인자를 표시한다.
- 명령 원문, 작업 디렉터리, 종료 코드, 실행 시간을 표시할 수 있다.
- 스트리밍 출력과 최종 결과를 표시한다.
- 실패한 도구 실행은 실패 스타일로 구분한다.
- 긴 명령과 결과는 미리보기와 전체 보기 모달로 나누어 표시한다.

#### 8.4 계획과 파일 변경

- Codex 계획을 단계별 체크리스트로 표시한다.
- 대기, 진행 중, 완료 상태를 구분한다.
- 파일 변경 수와 전체 추가/삭제 줄 수를 표시한다.
- 파일별 생성, 수정, 삭제 상태와 diff를 펼쳐 볼 수 있다.

#### 8.5 진단

다음과 같은 문제를 별도 진단 배너로 표시한다.

- 모델 재라우팅
- 사용 한도
- 인증 변경
- Guardian 또는 권한 설정
- 샌드박스 문제
- MCP 문제
- Cursor CLI 문제
- 이미지 입력 미지원
- 복구 가능한 문제의 해결 안내

동일한 진단이 반복되면 반복 횟수를 표시할 수 있다.

#### 8.6 대량 기록

- 멤버당 저장 가능한 transcript 블록 수를 제한하여 UI가 무한히 커지지 않게 한다.
- 처음에는 최근 150개 블록만 렌더링한다.
- `이전 기록 보기`를 통해 150개씩 추가로 확인할 수 있다.
- 이전 기록을 추가해도 사용자가 읽던 스크롤 위치를 유지한다.
- 사용자가 대화 하단을 보고 있을 때만 새 응답에 맞춰 자동 스크롤한다.

### 9. 승인과 사용자 질문

#### 9.1 일반 승인

- 도구명, 설명, 실행 명령을 승인 카드에 표시한다.
- 사용자는 요청을 거부하거나 이번 한 번만 허용할 수 있다.
- 처리 후 승인됨 또는 거부됨 상태가 카드에 남는다.
- 승인 대기 중인 멤버는 사이드바에도 승인 배지가 표시된다.

#### 9.2 Codex 승인

요청이 지원하는 경우 다음 결정을 제공한다.

- 이번 한 번 허용
- 현재 세션 동안 허용
- 같은 command prefix 규칙을 항상 허용
- 거부

승인 카드에는 명령 원문, 작업 디렉터리, 파일 diff, 요청 사유, 항상 허용될 규칙을 표시할 수 있다.

#### 9.3 모델의 사용자 질문

- 선택지형 질문을 대화 안의 카드로 표시한다.
- 단일 선택과 다중 선택을 지원한다.
- 선택지별 설명을 표시한다.
- 기타 또는 직접 입력 답변을 지원한다.
- 선택지 없는 자유 입력 질문을 지원한다.
- 비밀 입력 질문은 password 입력으로 표시한다.
- 여러 질문은 한 단계씩 이동하며 이전, 다음, 건너뛰기, 답변 보내기를 제공한다.
- 필요한 답변이 모두 입력되기 전에는 최종 전송 버튼이 활성화되지 않는다.
- 응답 완료 후 질문과 선택한 답변의 요약을 남긴다.

### 10. 세션 생명주기

#### 10.1 활성 세션

- `세션` 화면에서 현재 활성 세션과 상태를 볼 수 있다.
- 활성 세션 항목을 선택해 Workbench에서 열 수 있다.
- 세션 목록에서 활성 세션을 닫을 수 있다.

#### 10.2 이전 세션

- 현재 작업공간에서 재개할 수 있는 Claude Code 세션을 조회한다.
- 목록을 수동으로 새로고침할 수 있다.
- 세션 제목, 첫 프롬프트 또는 요약, 최근 수정 시간, Git 브랜치를 표시한다.
- 이전 세션을 선택해 다시 열 수 있다.
- 조회 실패는 오류로 표시하고, 기록이 없으면 빈 상태를 표시한다.

#### 10.3 대화를 유지하는 세션 재시작

- 패널 메뉴의 `세션 재시작`은 현재 세션을 새로 만들면서 기존 하네스 스레드를 이어간다.
- 모델 컨텍스트와 저장된 transcript를 유지한다.
- 변경된 모델 설정과 MCP 구성을 다시 읽는다.
- 서로 다른 하네스로 변경하는 경우 대화 ID가 호환되지 않으므로 새 스레드로 시작한다.

#### 10.4 하드 재시작

- 멤버 우클릭 메뉴의 하드 재시작은 하네스를 같은 자리에서 다시 시작한다.
- 멤버 등록과 세션 슬롯은 유지하지만 대화 맥락은 초기화한다.
- 활성 세션이 없는 멤버에서는 실행할 수 없다.

#### 10.5 닫기와 삭제의 차이

- 세션 닫기: 멤버 설정과 저장된 기록을 유지하고 활성 실행만 종료한다.
- 멤버 삭제: 멤버 등록, 활성 세션, 역할 파일을 제거한다.
- 파티 삭제: 파티와 모든 멤버, 메시지, 디스크 저장소를 제거한다.

## IV. AI 실행과 협업 제어

### 11. 모델과 런타임

#### 11.1 멤버별 Runtime

멤버의 Runtime 모달에서 다음 항목을 변경할 수 있다.

- 모델
- 하네스
- Effort
- Thinking 모드
- Thinking token budget
- 디버그 로그
- Auto-compact

#### 11.2 하네스 변경

- 아직 대화가 시작되지 않은 멤버는 하네스를 변경할 수 있다.
- 첫 턴 또는 기존 사용자/AI 메시지가 있으면 다른 하네스 선택이 잠긴다.
- 같은 하네스 안에서는 모델과 제공자를 변경할 수 있다.
- 실제 하네스가 바뀌면 세션을 재생성한다.

#### 11.3 교차 라우팅

- Claude Code 하네스에서 GPT 모델을 사용할 수 있다.
- Codex 하네스에서 Claude 구독 모델을 사용할 수 있다.
- Claude Code 하네스에서 Cursor 구독 모델("Grok 4.5 (Cursor)")도 사용할 수 있다.
- 권한 체계는 모델 제공자가 아니라 실제 실행 하네스를 따른다.
- Claude Code+GPT는 Claude Code 권한 모드를 사용한다.
- Codex+Claude는 Codex 샌드박스와 승인 정책을 사용한다.
- Claude Code+Cursor 구독도 Claude Code 권한 모드를 사용하며, 도구 호출은
  로컬 MCP 릴레이를 거쳐 실제 하네스 도구로 왕복 실행된다.
- Claude Code+Cursor 구독의 Grok 4.5는 항상 Effort: High, Tier: Fast 한
  조합만 제공하며 다른 조합은 선택할 수 없다.
- 로그인되지 않은 Cursor 계정으로 이 모델을 시작하면 자동으로 다른 모델로
  바뀌지 않고 명시적인 오류가 표시된다.

#### 11.4 Cursor 모델

- `Auto`는 Cursor가 실제 모델을 선택한다.
- `Grok 4.5`는 low, medium, high effort에 해당하는 Cursor 모델을 사용한다.
- Grok 모델에 플랜 또는 계정 오류가 발생해도 Auto로 자동 대체하지 않고 오류를 표시한다.
- Cursor chat ID를 저장하여 이후 턴과 세션 재개에서 같은 대화를 이어간다.

#### 12.2 Codex 권한

Approval:

추가 기능:

### 13. 컨텍스트와 압축

#### 13.1 컨텍스트 사용량

- 멤버 상단에 현재 컨텍스트 사용량을 도넛 형태로 표시한다.
- 사용 토큰과 전체 컨텍스트 크기를 표시할 수 있다.
- 사용률에 따라 경고 색상을 적용한다.
- 전체 컨텍스트 크기를 알 수 없으면 토큰 수만 표시하고 임의의 비율을 만들지 않는다.
- 닫힌 멤버에는 마지막으로 알려진 사용량을 흐리게 표시하고 `~`로 오래된 값임을 나타낸다.

#### 13.2 수동 압축

- 컨텍스트 도넛을 클릭해 Auto-compact 및 수동 압축 모달을 연다.
- 현재 사용량과 자동 압축 임계 위치를 확인할 수 있다.
- `지금 압축 실행`으로 즉시 컨텍스트 압축을 요청할 수 있다.
- 세션이 없으면 압축하지 않고 사용자에게 이유를 알린다.

#### 13.3 자동 압축

- 멤버별로 자동 압축을 켜고 끌 수 있다.
- 임계값을 백분율과 예상 토큰으로 설정한다.
- 설정 범위는 10~95%이며 1% 단위로 조절한다.
- 컨텍스트 사용률이 임계값을 넘으면 세션을 한 번 자동 압축한다.
- 전체 컨텍스트 크기를 알 수 없으면 자동 압축하지 않는다.
- 멤버별 설정이 없으면 앱의 전역 기본값을 상속한다.
- 새 설치의 전역 기본값은 꺼짐이며 저장된 기준값은 80%다.

### 14. Message Gate

#### 14.1 목적

- 멤버가 다른 멤버에게 보내는 메시지를 전달 전에 별도 리뷰어 모델로 심사한다.
- 사용자가 직접 멤버에게 보내는 메시지는 Gate 심사를 받지 않는다.
- 리뷰어는 별도 UI 세션이나 하네스를 만들지 않는 헤드리스 실행이다.

#### 14.2 파티 전역 설정

- 파티별 Gate 활성화 또는 비활성화
- 파티 통신 규칙 입력
- 파티 전용 리뷰어 모델과 effort 선택
- Gate가 적용되는 멤버 수 표시
- 멤버별 실효 상태 표시
- 설정 변경 즉시 반영

#### 14.3 멤버별 설정

- `Inherit`: 파티 설정 상속
- `On`: 멤버 Gate 강제 활성화
- `Off`: 멤버 Gate 강제 비활성화
- 멤버별 통신 규칙 재정의
- 파티 규칙으로 초기화
- 멤버별 리뷰어 모델과 effort 지정
- 별도 리뷰어가 없으면 파티 또는 앱 전역 기본값 사용
- Gate가 켜져 있지만 규칙이 비어 있으면 실제 심사를 수행하지 않는다는 경고 표시

#### 14.4 심사 결과

- 승인: 메시지를 정상 전달한다.
- 반려: 메시지를 전달하지 않고 반려 사유와 위반 규칙을 표시한다.
- 강제 전송: 한 번 Gate를 우회했음을 표시한다.
- 리뷰 실패: fail-open 방식으로 메시지를 전달하되 심사 실패 경고를 표시한다.
- 결과는 메시지를 보낸 멤버의 transcript에 별도 카드로 남는다.

### 15. 멤버 간 통신

#### 15.1 직접 메시지

- 멤버가 다른 멤버에게 메시지를 보낼 수 있다.
- 대화 카드에 발신자와 수신자 경로를 표시한다.
- 수신 메시지와 발신 메시지의 방향을 구분한다.
- 대상 멤버의 활성 세션이 없으면 전달 실패 상태를 기록한다.
- 작업 중인 수신자에게 보내는 메시지는 기본적으로 현재 턴 뒤에 대기할 수 있다.
- interrupt 옵션을 사용하면 현재 작업을 중단하고 메시지를 즉시 주입할 수 있다.

#### 15.2 전체 방송

- 발신자를 제외한 파티의 모든 멤버에게 같은 메시지를 보낼 수 있다.
- 멤버별 전달 성공 및 실패 결과를 반환한다.
- 작업 중인 모든 수신자를 먼저 중단한 뒤 방송하는 옵션을 지원한다.
- 현재는 주로 로컬 HTTP API와 에이전트용 파티 도구에서 제공된다.

#### 15.3 에이전트의 파티 제어

세션 안의 AI 멤버도 AgentParty 도구를 이용해 다음 기능을 실행할 수 있다.

- 파티와 멤버 조회
- 멤버 생성과 삭제
- 다른 멤버에게 메시지 보내기
- 멤버 상태 조회
- 현재 작업 중단
- 전체 방송
- 권한 변경
- Message Gate 변경

AI가 수행한 멤버 생성과 삭제는 대화에 전용 액션 카드로 표시된다.

### 16. 서브에이전트

#### 16.1 서브에이전트 도크

- 상위 멤버가 생성한 서브에이전트 수를 표시한다.
- 실행 중, 완료, 실패, 대기 상태를 색상과 점으로 표시한다.
- 전체 상태 요약을 표시한다.
- 도크를 접거나 펼칠 수 있다.
- 접힘 상태는 로컬에 저장된다.

#### 16.2 상세 보기

- 서브에이전트 행을 선택해 상세 화면으로 들어갈 수 있다.
- 상위 멤버와 서브에이전트의 경로를 breadcrumb로 표시한다.
- 위임된 작업 내용을 표시한다.
- 서브에이전트의 응답, 상태, 도구 실행 결과, 실행 시간을 표시한다.
- 뒤로 버튼을 사용해 상위 멤버의 대화로 돌아간다.

### 17. MCP 서버

#### 17.1 서버 목록

- 활성 세션에 연결된 MCP 서버를 조회한다.
- 연결됨, 연결 중, 실패, 인증 필요, 비활성화, 알 수 없음 상태를 구분한다.
- 서버명, transport, scope, 버전과 오류 내용을 표시한다.
- 서버가 제공하는 도구 수와 도구명을 펼쳐 볼 수 있다.
- 서버 이름으로 검색할 수 있다.
- 전체, 연결됨, 실패, 인증 필요 상태로 필터링할 수 있다.
- 전체 서버 수, 연결 수, 실패 수, 인증 필요 수, 도구 수를 표시한다.

#### 17.2 서버 동작

하네스가 실제로 지원하는 기능만 화면에 표시한다.

- 개별 서버 재연결
- 가능한 서버 모두 재연결
- 서버 활성화와 비활성화
- OAuth 인증 시작
- 목록 새로고침
- 인증 URL을 시스템 브라우저에서 열기

#### 17.3 하네스별 차이

- Claude Code는 재연결과 활성화/비활성화를 지원한다.
- Claude Code의 MCP OAuth는 대화형 `/mcp` 흐름을 사용한다.
- Codex는 재연결과 OAuth 시작을 지원한다.
- Codex의 활성화/비활성화는 설정 파일 기반이므로 라이브 토글을 제공하지 않는다.
- 세션이 없으면 먼저 세션을 시작해야 한다는 안내를 표시한다.
- 조회와 동작 실패는 오류 배너로 표시한다.

## V. 운영과 자동화

### 18. 계정 사용 한도

#### 18.1 제목 표시줄

- Claude와 Codex 계정의 5시간 사용률을 미니 도넛으로 표시한다.
- 제공자 데이터나 관련 멤버가 전혀 없으면 사용 한도 표시 자체를 숨긴다.
- 사용률이 높으면 강조 색상을 적용한다.
- 알 수 없는 값을 임의로 0%라고 표시하지 않는다.

#### 18.2 상세 정보

사용 한도 표시를 열면 다음 정보를 확인할 수 있다.

- 제공자별 5시간 사용률
- 주간 사용률
- 초기화까지 남은 시간
- 해당 제공자를 사용하는 멤버 수
- 즉시 새로고침
- 런타임 설정 화면으로 이동

#### 18.3 백그라운드 갱신

- 활성 세션이 있으면 해당 세션의 이벤트로 사용량을 갱신한다.
- 마지막 세션이 닫혀도 해당 제공자를 사용하는 멤버가 있으면 경량 백그라운드 연결이 사용량을 주기적으로 갱신한다.
- 제공자 연결에 실패하면 잘못된 값을 생성하지 않고 데이터 없음 상태를 유지한다.

### 19. 전역 런타임 설정

#### 19.1 새 멤버 기본 하네스

- 새 멤버가 기본으로 사용할 하네스를 Claude Code, Codex, Cursor 중에서 선택한다.
- 각 하네스는 서로 독립적인 기본 프로필을 가진다.

#### 19.2 하네스별 기본값

하네스마다 다음 값을 저장할 수 있다.

- 기본 모델
- 기본 effort
- 기본 thinking 모드
- Claude 계열 권한 모드 또는 Codex 안전 정책
- 저장 완료 상태 표시

#### 19.3 Message Gate 기본값

- 앱 전체에서 사용할 Gate 리뷰어 모델과 effort를 설정한다.
- 멤버와 파티에 별도 리뷰어가 없을 때 이 값을 사용한다.

#### 19.4 Auto-compact 기본값

- 별도 설정이 없는 멤버가 상속할 자동 압축 기본값을 변경한다.
- 켜기 또는 끄기와 임계 백분율을 설정한다.

#### 19.5 라우터와 디버그

- 현재 로컬 모델 라우터 URL을 표시한다.
- 라우터 URL을 클립보드에 복사할 수 있다.
- 디버그 로그를 켜거나 끌 수 있다.

### 20. 자동화와 로그

#### 20.1 자동화 화면

- 로컬 자동화 API 주소를 표시한다.
- API 스펙 URL을 표시한다.
- 현재 로그 파일 경로를 표시한다.
- API 스펙 URL을 클립보드에 복사할 수 있다.
- 디버그 로그를 켜거나 끌 수 있다.

#### 20.2 로컬 HTTP API

- 기본 주소는 `http://127.0.0.1:47831`이다.
- 기본 포트가 사용 중이면 사용 가능한 다른 로컬 포트를 선택한다.
- 외부 네트워크가 아니라 loopback 주소에만 바인딩한다.
- UI 기능과 HTTP API는 동일한 애플리케이션 컨트롤러 경로를 사용한다.
- 상태, 인증, 모델, 사용량, 세션, 파티, 멤버, MCP, 창, 화면 이동 기능을 자동화할 수 있다.
- 모든 API 호출은 앱 로그에 기록된다.

#### 20.3 화면 캡처와 로그

- 현재 Electron 창을 PNG 파일로 캡처할 수 있다.
- 현재 로그 파일 경로를 조회할 수 있다.
- 로그는 Electron user-data 디렉터리에 NDJSON 형식으로 저장된다.

#### 20.4 자동화 전용 보조 기능

일부 기능은 일반 UI보다 로컬 HTTP API와 에이전트 도구에서 더 직접적으로 제공된다.

- Claude 구독 연결 해제
- OpenRouter API 키 삭제
- 멤버와 기존 세션 바인딩
- 멤버 전체 상태 조회
- 모든 작업 중인 멤버 중단
- 파티 전체 방송
- Gate를 한 번 우회하는 강제 전송
- 특정 창 지정과 새 창 생성
- 특정 창의 작업공간 변경

#### 20.5 QA 모드 지원

QA 모드에서는 실제 모델 호출 없이 사용자 화면을 구성하기 위한 전용 기능을 제공한다.

- 가상 파티와 멤버 생성
- transcript 이벤트 주입
- 승인 요청과 사용자 질문 주입
- 서브에이전트 시나리오 주입
- 임의 패널과 탭 배치
- 사용 한도 데이터 주입
- Message Gate 화면 열기
- QA 데이터 초기화

QA 모드가 아닐 때 `/api/qa/*` 요청은 거부된다.

### 21. 현재 UI 노출 범위와 제약

- Claude 구독 연결 해제는 API에는 있지만 현재 인증 화면에는 버튼이 없다.
- OpenRouter 키 삭제는 API에는 있지만 현재 인증 화면에는 버튼이 없다.
- Cursor 로그인과 로그아웃은 AgentParty가 아닌 Cursor CLI에서 수행한다.
- 좌측 하단 `JD` 아바타는 현재 동작이 없는 표시 요소다.
- 탭 닫기는 단순 화면 닫기가 아니라 해당 멤버의 활성 세션까지 종료한다.
- 멤버의 하드 재시작은 대화 맥락을 초기화하지만 세션 재시작은 기존 대화를 이어간다.
- Message Gate 리뷰어가 실패하면 메시지를 차단하지 않고 경고와 함께 전달한다.
- 이미지 미지원, 모델 검색 실패, 인증 실패, MCP 실패는 조용한 대체 없이 사용자에게 진단으로 표시한다.
