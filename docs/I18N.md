# App localization workflow

The desktop locale is stored in `AppSettings.locale`. Renderer copy lives in
two typed catalogs:

- `src/renderer/i18n/messages.ts` contains semantic app-shell and settings keys.
- `src/renderer/i18n/auditKoMessages.ts` contains the stable `STR-xxxx` keys from
  renderer source.
- `src/shared/nonRendererKoMessages.ts` contains Korean text found in guides,
  catalogs, shared, core, main, and preload source. It stays outside the renderer
  bundle until a non-renderer call site needs locale-aware delivery.

The `STR-xxxx` catalog is generated. Do not edit it by hand. After merging copy
edits into `docs/user-facing-strings-excel.csv`, regenerate it with:

```sh
npm run i18n:apply-guide-copy
npm run i18n:sync
```

`i18n:apply-guide-copy` applies reviewed guide and presentation suggestions to
their Markdown and TypeScript sources while preserving Markdown table columns
and template placeholders. It is safe to run repeatedly; a second run must
report zero source changes.

If the CSV has a `suggested_text_ko` column, a non-empty suggestion replaces the
original `text`; an empty cell keeps the original. This lets copy editing and
source localization proceed on separate branches without changing identifiers.

Run `npm run test:i18n` after regeneration. It verifies that every high-confidence
renderer row exists in the catalog, every key used by the renderer resolves, and
no direct high-confidence JSX string has been added.

Dynamic JSX attributes keep their `${…}` slots in CSV order. The renderer passes
the corresponding values separately, so copy edits may move the surrounding
words but must not add, remove, or reorder the slots without updating the call.

The extraction keeps every Korean human-readable literal found in renderer,
shared, core, main, and preload source in the stable `STR-xxxx` inventory. This
includes backend notices that may be passed to the renderer. High-confidence
renderer JSX text and UI attributes are also replaced at their call sites.

The audit preserves existing IDs and copy-edit columns when it runs again. New
rows are appended with new IDs, while rows whose literals were already replaced
remain in the inventory. This lets copy editing continue without identifiers
changing after source refactors.
