## 🟥 A. 답만 주면 바로 착수 가능

### A-1. [#12] 사용량 표시 이상 — **가장 답이 급한 항목**

- **왜 뺐나**: 표면이 **3개**이고 각각 완전히 다른 버그 경로다. 증상 특정 없이 착수하면 7개 파일을 헛짚는다.
- **답해야 할 것 3가지**
  1. **어느 화면인가?** ① 타이틀바 한도 pill ② 사용량 대시보드 ③ 멤버별 컨텍스트 도넛
  2. **어느 하네스·프로바이더인가?** 구독(Claude/Codex) / OpenRouter / DeepSeek / Cursor
  3. **어떻게 틀리나?** 아예 안 뜸 / 0 이나 빈 값 / 갱신이 멈춤 / 값 자체가 틀림
- **참고 — 조사에서 이미 나온 의심 지점** (증상을 들으면 바로 좁혀진다)
  - OpenRouter·DeepSeek 경로는 **설계상 pill 이 아예 없다**(한도 개념이 없는 종량제라서). "안 뜬다"면 버그가 아닐 수 있다
  - Codex 는 한도 창이 비면 아무것도 emit 하지 않아 **리셋 직후 값이 굳는다**
  - Cursor 는 컨텍스트 점유량 자리에 **그 턴의 토큰 합계**를 넣고 있다 (프로젝트가 이미 한 번 밟은 함정)
- ✅ **이 중 한 건은 이미 W4 에 배정했다** — 카탈로그에 없는 모델의 비용을 `0` 으로 반환해 `≈$0.000` 으로 표시하던 것(silent fallback 위반). 나머지는 답 대기.

### A-2. [P-10] 스킬 카탈로그가 쓰기 어려움

- **왜 뺐나**: FEEDBACK 원문 자체가 "증상 특정 필요"로 열려 있다. 어디가 걸리는지 모르면 엉뚱한 걸 고친다.
- **답해야 할 것**: 스킬을 **찾는** 단계인가(목록이 길다/검색이 없다) · **고르는** 단계인가(설명만으론 판단이 안 된다) · **적용하는** 단계인가(켜고 끈 게 반영됐는지 모르겠다) · 아니면 **화면 진입 자체**가 어려운가
- 답이 오면 [P-2] 모델 카탈로그와 **같은 카탈로그 UI 패턴**으로 함께 설계하는 게 맞다

### A-3. 미분류 "compact 를 해도 무반응"

- **왜 뺐나**: 조사 결과 **원래 보고가 틀렸다.** 세션이 없으면 앱이 실제로 "세션이 없어 압축할 컨텍스트가 없습니다" 토스트를 띄운다(6초 후 자동 소멸).
- **답해야 할 것**: 그때 ① 토스트가 안 보였나(놓쳤을 수도) ② 세션은 살아 있었나 ③ 무반응이라 판단한 근거가 뭔가(진행 표시가 없었다 / 컨텍스트 수치가 안 줄었다 / 대화가 그대로였다)
- 세션이 살아있는데도 무반응이었다면 **하네스 쪽에서 compact 가 no-op 인 것**이라 조사 방향이 완전히 달라진다

## 🟧 B. 제품 결정 대기 (코드가 아니라 "어떻게 동작해야 하는가")

### B-1. 미분류 "claude code — gpt 백엔드가 동작하지 않음"

- **판정: 코드 버그가 아니다.** 경로는 완전히 존재하고, 실패 조건이 전부 환경 쪽이다 — CLIProxyAPI 미실행 / Codex 구독 미인증 / 라우터 모델 목록에 없음.
- **결정할 것**: claude-code 하네스에서 GPT 를 **정식 지원할 것인가**, 아니면 **"Codex 하네스를 쓰세요"라는 명확한 안내로 대체**할 것인가
- ✅ 진단 메시지 개선(에러가 CLIProxyAPI 를 언급하지 않아 원인 파악이 불가능한 문제)만 **W1 에 배정했다**. 정식 지원 여부는 답 대기

### B-2. [#13] 중 미룬 두 가지

이번에 W1 이 하는 건 "표시가 실제와 어긋나는 것"을 바로잡는 데까지다. 아래 둘은 **기능 신설**이라 뺐다.
- **"알 수 없음" 상태를 UI 에 새로 도입할 것인가?** — 새 상태값은 사이드바·헤더·칩·자동화 API 전부에 파급된다. [P-3] 1·2(상태 칩·상태색)와 **함께 다뤄야 할 일**
- **하네스 자식 프로세스 재부착(re-attach)을 지원할 것인가?** — 현재 구조상 불가능하다. 앱이 비정상 종료되면 자식이 고아로 남고 다시 붙을 방법이 없다. 지원하려면 별도 기능 과제

### B-3. [#16] 중 미룬 두 가지

- **Escape 키로도 닫히는 것을 막을 것인가?** — 이번엔 **막지 않기로 했다**(바깥 클릭만 차단). Escape 는 사용자가 의도적으로 누르는 키이고 일반적 관례라서. 입력 유실이 Escape 로도 실제로 발생한다면 다시 판단할 것
- **공용 `<ModalShell>` 컴포넌트로 추출할 것인가?** — 지금은 모달마다 스크림을 손으로 작성한다(공용 추상화 없음). 추출하면 재발이 원천 차단되지만 **모달 7개 파일 전부**를 건드리게 된다. 이번엔 변경 표면을 줄이려고 4곳 개별 수정으로 갔다. 별도 리팩터링 과제로 남길지 결정 필요

### B-4. [P-12] 런타임 탭 분할 + 추론 옵션 카탈로그 통합

- ✅ **오른쪽 패딩만 W4 에 배정**했다. 아래 둘은 뺐다:
  - **런타임 탭을 성격별로 분할** — 분류 기준을 먼저 정해야 한다(하네스별 기본값 / 컨텍스트·자동압축 / Message Gate·리뷰어 / 기타). **지금 화면에 뭐가 있는지 나열부터** 하고 확정하는 게 순서
  - **추론 강도·모드 선택기를 없애고 모델 카탈로그에서 함께 고르기** — [P-2] 와 같은 컴포넌트를 건드리므로 함께 해야 한다. 카탈로그 선택기가 `reasoning`(추론 모드) 축까지 다루는지 확인이 선행
