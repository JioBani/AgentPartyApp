## 복귀 대상부터 고정 (2026-09-27 기록)

**수정 없는 0.12.2로의 단순 재설치는 안전한 복귀 계약이 아니다.** 실제 앱에서
native 전환 후 보관 대화를 꺼내 사용한 다음 `0caade2`로 돌아가면, 구버전은
남아 있는 격리 DB의 `archived=1`을 읽어 대화 재개를 거절했다. 일반 대화와 신규
대화의 복귀가 통과했다는 이유로 이 경우까지 성공한다고 판단하지 않는다.

권장 후보는 두 단계다.

1. `fix/codex-storage-compat`: 0.12.2 기반 초기화 수명 수정 및 저장소 모드 읽기만
   포함한다. 모드 파일이 없으면 legacy를 사용하며 전환 worker/API가 없다.
2. `fix/codex-storage-lifecycle`: 검증된 이력 이전과 명시적 native 전환을 제공한다.
   1번 후보를 복귀 대상으로 보관한다. 복귀 시 같은 최신 저장소를 읽으므로
   새 앱의 롤백 API를 먼저 실행할 필요가 없다.

이는 **애플리케이션 버전 복귀**이며 데이터를 과거 시점으로 되감는 작업이 아니다.
DB 자체 손상, 디스크 장애, 외부 Codex의 동시 쓰기까지 구버전 실행만으로
해결된다고 보장하지 않는다. 원본 격리 DB와 일관 백업을 별도로 유지한다.
사용자가 원본 0.12.2 자체를 반드시 복귀 대상으로 요구하면 이 후보를 출시하면
안 된다. 별도 오프라인 데이터 복구 절차가 추가로 필요하다.

## 전환 방식

운영 설정, provider, 보관 상태, 대화 ID와 rollout 파일을 유지한다. 정상 실행은
Codex의 SQLite 구조를 다루지 않는다. 일회성 worker만 아래 순서로 실행한다.

1. 실행 중인 로컬 Codex를 거절하고 외부 CLI 종료 확인을 받는다. 프로세스 간
   유지보수 잠금과 WAL을 포함한 SQLite backup API를 사용한다.
2. 설치된 Codex가 읽기용 복사본을 갱신한 뒤 스키마/마이그레이션 체크섬을 대조한다. 캐시가 없으면
   격리 복사본에서 공식 Codex API로 재생성한다. 복사본에서만 보관 해제와
   모델 호출 없는 기본 provider 지정을 허용하며 원본에는 적용하지 않는다.
3. 재생성 시 원문 바이트 보존, 추가 설정 이벤트만 존재함, 항목 위치가 원문
   범위 안임, 전체 투영 및 ordinal 일치를 검증한다. 커서는 원문 끝으로 맞춘다.
4. 대상 app-server가 종료된 상태에서 이력을 단일 SQLite 트랜잭션으로 옮긴다.
   같은 위치의 상충 이력과 기존 항목 ID 손실을 거절한다. 중간 실패/프로세스
   종료는 SQLite가 롤백한다.
5. 실제 Codex API로 페이지형 대화의 항목·순서·도구/이미지 데이터를 포함해
   대조하고 메타데이터·부가 상태를 검사한다. 모두 통과해야 모드 파일을 바꾼다.

Goal ID와 누적 사용량은 사용자 합의대로 병합하지 않는다. 원본 DB는 남긴다.
지원하지 않는 데이터 구조나 충돌은 오류를 표시하고 전환하지 않는다.
Codex 버전 번호만으로 전환을 차단하지 않는다.

## 통과한 검증

| 검증 | 결과/증거 |
| --- | --- |
| 부분적으로 채워진 native DB에 일반/보관 대화 추가 | 실제 앱, 같은 ID/내용/보관 상태 유지 |
| 읽기용 캐시가 없는 보관 대화 | 복사본에서 재생성 후 실제 모델로 이전 내용 회상 |
| 재생성 이후 새 턴 | 이후 응답 2개 추가 및 전체 API 이력 확인; 커서가 새 대화를 건너뛰지 않음 |
| 빈 native DB에 809개 전체 복원 | 페이지형 135개, 보관 1개, 부모·자식 관계 18개 포함; 누락 캐시 10개 재생성 |
| 복사 중 강제 프로세스 종료 | 트랜잭션 전 내용으로 복구, 재실행 및 멱등성 통과 |
| 알 수 없는 이력 스키마 | 변경 없이 거절 |
| 수정 없는 구버전의 일반/신규 대화 복귀 | 통과; 보관 상태 변경은 실패하므로 범용 복귀 대상으로 제외 |
| 호환 복귀 후보로 정상 종료 후 복귀 | 수정/신규 대화 및 보관 해제한 대화의 최신 응답 회상 통과 |
| 복귀 후 재업데이트 | 복귀 버전에서 작성한 마지막 응답 회상 통과 |
| 새 앱 강제 종료 후 호환 후보 실행 | 롤백 API 없이 새 대화 회상 통과 |
| 패키지 실행 파일 두 개로 전체 왕복 | 누락 캐시 복원, 후속 턴, 보관 상태 변경, 정상/강제 종료 복귀, 재업데이트 모두 통과 |

실제 모델: `gpt-6-luna`, low, inherit. 멤버 작업은 실제 member-scoped MCP
transport를 사용했다. 상태 조회, fixture 준비, 닫기/재개, 창 종료, 저장소 관리는
대응 MCP 도구가 없어 HTTP를 사용했다. DB 장애 주입은 별도 저장소 검사이며
제품 E2E로 계산하지 않는다. 809개 검사는 운영 worker를 복사본에서 실행한
데이터 회귀 검사이며 제품 전체 UI 검증으로 계산하지 않는다.

재현 스크립트:

- `scripts/qa-codex-partial-storage.py`: 실제 앱 왕복. `--old-app-root`,
  `--old-commit`, `--rebuild-missing-cache` 지원. `--app-exe`와 `--old-app-exe`로
  패키지 실행 파일도 같은 흐름으로 검증한다.
- `scripts/qa-codex-history-atomicity.py --case <completed QA case>`: 장애 주입.

- 호환 복귀 후보 전체 왕복: `.tmp/partial-storage-xjt573k1`.

## 출시 전 남은 절차

소스·개발 빌드 검증을 마친 후보이며 운영 데이터 전환/설치/배포는 하지 않았다.
최종 출시 버전 번호와 호환 복귀 대상을 함께 확정하고 두 후보를 보관해야 한다.
과거 패키지 실행 파일 왕복은 위 표와 같이 통과했다.
macOS/WSL/SSH의 native 전환, 외부 CLI와의 동시 유지보수는 승인 범위가 아니다.
실행 중인 사용자 세션이 있는 현재 환경에서 운영 마이그레이션을 실행하지 않는다.

패키지는 로컬 검증용 Windows unpacked 실행 파일이며 서명/설치 관리자/자동
업데이트 경로의 검증을 대신하지 않는다. 정식 배포 시 통합 검증은 마지막에
한 번 수행하고, 별도의 배포 게이트를 통과시킨다.
