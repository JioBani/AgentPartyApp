# AgentParty 기능정의서

AgentParty 가 제공하는 기능을 **컨텐츠 > 기능 > 세부기능** 계층으로 정의한다.
사용자 요구사항(UR)은 이 문서가 담지 않는다 — 각 세부기능에 부착될 UR 은 별도로 분석해 Canopy 에 등록한다.

## 이 문서의 규칙

`C:/Project/tactica-defense-resources/docs/프로젝트 관리/` 의 기획 운영 컨벤션·작업 관리 컨벤션을 따른다.

| 계층 | 정의 | 독자 | 역할 |
|---|---|---|---|
| **컨텐츠** | 사용자가 하나의 독립된 영역으로 인지하는 최상위 묶음. 이 프로젝트에서는 **좌측 탐색의 화면**이 그 단위다. | 기획자 + 개발 | 큰 묶음 |
| **기능** | 한 컨텐츠 안에서 사용자가 구분해 인지하는 기능 단위 | 기획자 + 개발 | 큰 묶음 |
| **세부기능** | 한 기능이 제공하는 **개별 동작 단위**. **UR 부착점**이며 진행도 추적 단위 | 기획자 | 추적 단위 |
| **마스터데이터** | 테두리 안을 채우는 **구체 인스턴스**. 세부기능과 같은 tier(기능의 자식), UR 없이 작업으로 직접 fan-out | | 채울 요소 |

### 세부기능의 입자도

세부기능은 **개별 요구사항이 아니라 요구사항이 들어앉을 영역**이다. 앞으로 어떤 요구사항이 추가될지 모르므로, 새 요구사항을 만났을 때 **어디에 붙일지 헷갈리지 않을 만큼 넓게** 잡는다.

- ❌ `다중 창` — "탭을 닫으면 세션이 닫힌다"가 여기 속하는지 알 수 없다.
- ⭕ `창` / `탭` — 창에 관한 요구사항은 전자에, 탭에 관한 요구사항은 후자에 붙는다.

한 세부기능 안에서 요구사항이 많아져 묶고 싶어지면 그때 **요구사항 그룹**(4계층, 선택)으로 묶는다. 세부기능을 더 쪼개지 않는다.

### 작성 원칙

- 세부기능은 **동작 영역**으로 이름 붙인다. 명사형으로 쓰고, 설명하는 문장을 제목으로 쓰지 않는다.
- 각 세부기능은 **한 줄 정의** + **다루는 범위**(UR 분석의 입력이 될 재료)로 적는다.
- **자기완결** — 다른 항목을 해독하거나 점프하지 않고 위에서 아래로 한 번 읽어 이해되어야 한다.
- `⚠` 는 현재 확인된 **제약**이다. 진행 상태·잔여 작업·버그는 이 문서가 담지 않는다 — 그건 Canopy 가 정본이다.

| 컨텐츠 | 범위 |
|---|---|
| **1. 워크벤치** | 파티·멤버가 실제로 동작하는 영역. 기능의 대부분이 여기 속한다. |
| **2. 통계** | 모델 사용량·비용 집계. |
| **3. 인증** | 모델 제공자 계정 연결·해제. |
| **4. 런타임** | 신규 멤버와 입력창의 전역 기본값. |
| **5. 설정** | 자동화 API·로그·QA, 앱 셸 조작. |

# 1. 워크벤치

## 1-1. 작업공간

### 1-1-1. 작업공간 지정
어느 폴더에서 일할지 정하고 그 폴더의 파티·멤버·세션 상태로 전환하는 동작 영역.
- 범위: 진입 경로(상단 버튼·File 메뉴) · 폴더 지정과 전환 · 로컬 절대 경로 · WSL 경로(`wsl+<distro>:/path`, `\\wsl$\`, `\\wsl.localhost\`) · 배포판 배지 표시 · 세션 작업 디렉터리 결정(프로젝트 루트) · 해석 불가 경로 처리
- ⚠ 해석 불가 경로를 임의 경로로 대체하지 않고 경고로 표시한다.

### 1-1-2. 작업공간 저장소
파티 상태를 작업공간 안에 보관해 폴더 이동·백업과 함께 따라가게 하는 동작 영역.
- 범위: `.agent_party_app` 저장 위치 · 레거시 `.agentparty` 읽기 호환 · 멤버 역할 파일의 별도 보관

## 1-2. 창

### 1-2-1. 창
앱 창을 열고 닫고 표시 상태를 바꾸는 동작 영역.
- 범위: 창 추가 생성 · 창 닫기 · 최소화 · 최대화/복원 전환 · 제목 표시줄 조작

### 1-2-2. 창별 작업공간
창마다 서로 다른 작업공간을 보게 하고 같은 작업공간을 공유할 때 어긋나지 않게 하는 동작 영역.
- 범위: 창별 작업공간 바인딩 · 동일 작업공간 공유 시 실시간 상태 동기화 · 창 지정 조작

## 1-3. 파티

### 1-3-1. 파티 편성
파티를 만들고 초기 구성을 갖추는 동작 영역.
- 범위: 사이드바 즉시 생성 · 모달 생성 · 이름 유효성 · `main` 멤버 자동 생성 · `main` 초기 세션 사전 기동과 실패 노출 · 생성 시 Message Gate 초기 설정
- ⚠ 생성 모달은 바깥 클릭으로 닫히지 않는다(입력 유실 방지).

### 1-3-2. 파티 선택과 현황
현재 작업공간의 파티를 오가며 가동 상태를 파악하는 동작 영역.
- 범위: 목록 표시와 선택 표시 · 활성 파티 전환 · 멤버·패널 배치 복원 · 전체 멤버 수와 작업 중 멤버 수 표시

### 1-3-3. 파티 삭제
파티와 그에 속한 자산을 제거하는 동작 영역.
- 범위: 진입 경로와 2단 확인 · 활성 세션 일괄 종료 · 멤버/메시지/역할 파일/디스크 저장소 삭제 · 활성 파티 삭제 시 선택 이전
- ⚠ 되돌릴 수 없다.

## 1-4. 멤버 편성

### 1-4-1. 멤버 생성
새 멤버를 정의해 파티에 추가하는 동작 영역.
- 범위: 생성 마법사 단계 진행(이름 → 하네스 → 모델 → 추론 → 권한 → 역할·확인) · 이름 형식과 파티 내 유일성 · 역할·요구사항 입력 · 최종 확인 · 생성 후 새 패널 자동 개방

### 1-4-2. 실행 구성 선택
멤버가 무엇으로 어떻게 실행될지 고르는 동작 영역.
- 범위: 하네스 선택(Claude Code·Codex·Cursor CLI) · 하네스별 실행 가능 모델 필터와 제공자 그룹핑 · 모델 메타(성능·비용·컨텍스트·이미지 지원) 비교 표시 · 불가 모델 비활성 · 모델 조회 로딩·실패·재시도 · 추론 설정(Effort·Thinking 모드·Thinking 토큰 예산)과 미지원 항목 비노출
- ⚠ 모델 조회 실패를 다른 제공자 모델로 대체하지 않는다.

### 1-4-3. 권한 구성 선택
멤버가 시작할 때 적용될 권한 수준을 고르는 동작 영역.
- 범위: Claude Code 계열 단일 권한 모드(Default·Accept edits·Plan·Auto·Don't ask·Bypass permissions) · Codex 계열 샌드박스와 승인 정책 · 프리셋(Read Only·Auto·Full Access·Custom) · Guardian 사용 여부

## 1-5. 멤버 관리

### 1-5-1. 멤버 개방
멤버를 화면에 올리고 필요한 시점에 세션을 준비하는 동작 영역.
- 범위: 진입 경로(클릭·Enter/Space) · 기존 탭 포커스와 중복 개방 방지 · 미개방 시 현재 패널에 탭 추가 · 활성 멤버 세션 사전 기동 · 명시적으로 닫은 멤버의 사전 기동 제외

### 1-5-2. 멤버 상태 표시
멤버가 지금 어느 상태인지 식별하게 하는 동작 영역.
- 범위: 시작 전 · 준비/유휴 · 요청 중 · 응답 중 · 중단 중 · 닫힘 · 오류 · 승인 대기 · 읽지 않은 메시지 수 · 사이드바와 패널 양쪽 표시

### 1-5-3. 멤버 삭제
멤버와 그 자산을 파티에서 제거하는 동작 영역.
- 범위: 진입 경로 · 활성 세션 종료 · 등록 정보와 역할 스캐폴드 삭제 · `main` 삭제 불가

## 1-6. 화면 배치

### 1-6-1. 탭
한 패널 안에서 여러 멤버를 탭으로 두고 다루는 동작 영역.
- 범위: 탭 전환 · 패널 `+` 로 미개방 멤버 추가 · 탭 닫기와 그에 따른 세션 종료 · 패널 내 순서 변경 · 패널 간 이동 · 드래그 중 대상 표시
- ⚠ 탭 닫기는 화면만 닫는 것이 아니라 해당 멤버의 활성 세션까지 종료한다(등록 정보는 유지).

### 1-6-2. 패널
화면을 나눠 여러 멤버를 동시에 보게 하는 동작 영역.
- 범위: 분할로 우측 패널 생성 · 신규 패널의 초기 멤버 · 탭 드롭으로 패널 생성 · 빈 패널 자동 제거 · 패널 구분선 드래그와 최소 비율 · 사이드바 접기/펴기와 너비 조절

### 1-6-3. 레이아웃 저장·복원
파티별 화면 배치를 기억했다가 되살리는 동작 영역.
- 범위: 열린 탭·패널 구성·활성 탭·패널 비율 저장 · 파티 재선택과 앱 재실행 시 복원 · 삭제된 멤버 탭 정리 · 사이드바 개폐 상태와 너비 저장

### 1-6-4. 반응형 밀도
좁은 폭에서도 쓸 수 있도록 표현을 조정하는 동작 영역.
- 범위: 패널 폭 기준 wide·mid·narrow 밀도 전환 · 밀도별 UI 표현 변경

## 1-7. 메시지 전송

### 1-7-1. 입력과 전송
작성한 내용을 멤버에게 보내는 동작 영역.
- 범위: 멤버별 독립 입력창 · 내용 기반 자동 확장과 최대 높이 내부 스크롤 · 전송 키(전역 설정을 따름) · 빈 전송 차단 · 전송 직후 사용자 메시지 선반영 · 세션 없는 멤버에 대한 자동 세션 시작
- ⚠ 전송 키 동작은 패널 폭과 무관하게 일관된다.

### 1-7-2. 첨부
텍스트 외의 자료를 함께 보내는 동작 영역.
- 범위: 클립보드 붙여넣기 · 파일 드롭 · 전송 전 미리보기와 개별 제거 · 모델별 최대 개수·장당 크기 · 읽기 실패/크기 초과/개수 초과 오류 · 미지원 모델 첨부 거절 · 지원 불확실 모델의 사후 진단 · 저장 기록 복원 시 원본 대신 이름만 남는 경우

### 1-7-3. 턴 중단
진행 중인 응답을 멈추는 동작 영역.
- 범위: 응답 중 Send → Stop 전환 · 현재 턴 중단 요청과 유휴 복귀 · 미처리 시 강제 종료로 전환 · 앱 측 턴 점유 해제와 대기 메시지 처리 재개
- ⚠ 강제 종료는 하네스 프로세스 자체를 종료하지 않는다.

## 1-8. 명령 팔레트

### 1-8-1. 명령 탐색
하네스가 제공하는 명령을 찾아 고르는 동작 영역.
- 범위: 입력 시작 위치 `/` 로 열기 · 이름·설명 검색 · 상하 이동·Enter 선택·Escape 닫기 · 범주 구분(Commands·Skills·Agents·MCP prompts·Plugins·AgentParty) · 하네스가 실제 보고한 항목 반영

### 1-8-2. 명령 정보 표시
실행 전에 명령의 성격과 사용법을 파악하게 하는 동작 영역.
- 범위: 설명·인자 형식·출처 표시 · 속성 배지(git 필요·읽기 전용·파일 수정·백그라운드·클라우드·인증 필요·파괴적)

### 1-8-3. 명령 실행
고른 명령을 실제로 적용하는 동작 영역.
- 범위: 입력창 텍스트 삽입 · 즉시 실행 명령(compact·restart·interrupt) · 하네스별 명령 차이(Cursor 압축은 `/compress`)

## 1-10. 사용자 개입

### 1-10-1. 실행 승인
AI 의 실행을 사람이 허가하거나 막는 동작 영역.
- 범위: 승인 카드(도구명·설명·실행 명령) · 거부와 이번 한 번 허용 · Codex 결정 범위(이번 한 번·현재 세션·동일 command prefix 항상·거부) · 명령 원문/작업 디렉터리/파일 diff/요청 사유/항상 허용될 규칙 표시 · 처리 후 상태 유지 · 사이드바 승인 배지

- 범위: 단일·다중 선택과 선택지 설명 · 기타/직접 입력 · 자유 입력 · 비밀 입력 · 다중 질문 이전/다음/건너뛰기 · 필수 항목 미충족 시 전송 차단 · 응답 요약 기록

## 1-12. 멤버 런타임

### 1-12-1. 런타임 변경

- 범위: 모델·하네스·Effort·Thinking 모드·Thinking 토큰 예산·디버그 로그·Auto-compact 변경 · 하네스 교체 시 세션 재생성 · 동일 하네스 내 모델·제공자 변경
- ⚠ 첫 턴이 실행됐거나 기존 메시지가 있으면 다른 하네스 선택이 잠긴다.

### 1-12-2. 교차 라우팅
하네스와 모델 제공자를 서로 다른 조합으로 실행하는 동작 영역.
- 범위: Claude Code + GPT · Codex + Claude 구독 · Claude Code + Cursor 구독(도구 호출 로컬 릴레이 왕복) · Cursor 모델 선택(`Auto`·`Grok 4.5`)과 chat ID 저장에 의한 대화 연속
- ⚠ Claude Code + Cursor 구독의 Grok 4.5 는 Effort High · Tier Fast 조합만 제공된다.
- ⚠ 미로그인 계정·플랜 오류 시 다른 모델로 대체하지 않고 오류를 표시한다.
- 🔒 **베타 잠금(2026-08-08).** 위 세 교차 조합은 베타 기간 동안 선택할 수 없다. 모델 목록에 `베타 잠금` 배지와 이유가 함께 표시되고, 멤버 생성·하네스 교체·모델 변경이 모두 거부된다. 실행 코드는 그대로 두고 판정 한 곳(`shared/modelIdentity.ts` 의 `crossHarnessLockReason`)만 막았으므로 정식 공개 때 되돌린다. → `docs/베타 공개 준비/B-12 교차 하네스.md`
- ⚠ **자체 하네스가 없는 제공자의 모델은 교차 라우팅이 아니다.** OpenRouter(GLM·Kimi·Grok·Gemini·Qwen 등)·DeepSeek 을 Claude Code 나 Codex 에서 실행하는 것은 그 모델의 유일한 실행 경로이며 잠금 대상이 아니다. 잠금은 **자체 하네스를 가진 제공자(Anthropic·OpenAI·Cursor)의 모델이 다른 하네스에서 실행될 때만** 적용된다.

## 1-13. 세션 수명주기

### 1-13-1. 세션 시작

- 범위: 저장된 하네스/모델/effort/권한으로 기동 · 전역 기본값이 멤버 고유 설정을 덮어쓰지 않음 · 동시 요청 시 중복 세션 방지

### 1-13-2. 세션 재시작
실행을 다시 세우는 동작 영역.

- ⚠ 하네스가 바뀌는 재시작은 대화 ID 비호환으로 새 스레드가 된다.

### 1-13-3. 세션 종료
실행만 멈추고 나머지는 남기는 동작 영역.
- 범위: 활성 실행 종료 · 멤버 설정과 저장 기록 보존 · 세션 종료·멤버 삭제·파티 삭제의 파괴 범위 구분

### 1-13-4. 대화 연속성
이전 모델 대화를 이어 붙이는 동작 영역.
- 범위: 하네스 thread ID 저장과 재사용 · 세션 재개 시 동일 대화 연결 · Cursor chat ID 연속

- ⚠ 전체 컨텍스트 크기를 모르면 토큰 수만 표시하고 비율을 만들지 않는다.

- ⚠ 전체 컨텍스트 크기를 모르면 자동 압축하지 않는다.

## 1-16. Message Gate

### 1-16-1. 게이트 구성

### 1-16-2. 메시지 심사

- ⚠ 리뷰어 자체가 실패하면 차단하지 않고 경고와 함께 전달한다(fail-open).

# 부록 A. 구조 제안 — 마스터데이터 후보

컨벤션상 **마스터데이터**는 세부기능과 같은 tier(기능의 자식)이며, UR 없이 작업으로 직접 fan-out 되는 **구체 인스턴스**다. AgentParty 에서 이에 해당하는 후보는 하나다.

- **모델 카탈로그** — 저장소가 직접 관리하는 모델 인스턴스 목록(모델별 성능·비용·컨텍스트·이미지 지원·추론 축). `1-4-2 실행 구성 선택`이 소비하는 재료이며, 항목을 추가·갱신하는 일은 기능 동작이 아니라 **인스턴스를 채우는 일**이다.

`1-4. 멤버 편성` 아래 마스터데이터로 둘 것을 제안한다. 채택 여부는 검토받는다.

# 부록 B. 이 문서가 담지 않는 것

- **사용자 요구사항(UR)** — 각 세부기능에 부착될 UR 은 별도 분석 산출물이며 Canopy 가 정본이다.
- **진행 상태·잔여 작업·버그** — Canopy 프로젝트 `AgentParty` 가 정본이다. 같은 사실을 두 곳에 적으면 반드시 어긋난다.
- **Discord 브리지** — 요청에 따라 제외했다. 실제로는 출시된 기능이므로 나중에 컨텐츠 편입 여부를 결정해야 한다.
- **세션 화면** — 독립 기능이 없다는 판단으로 제외했다. 세션 시작·재시작·종료는 `1-13 세션 수명주기`에 있다.
