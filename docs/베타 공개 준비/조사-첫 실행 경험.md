## 🔴 최우선 — 기본 작업공간이 `process.cwd()` 다

**`src/main/settings.ts:42`** — `workspacePath: process.cwd()`

개발 중에는 이게 저장소 폴더라 자연스럽다. **그런데 설치된 앱에서 `process.cwd()` 는
사용자의 프로젝트가 아니다** — 바로가기가 가리키는 곳, 대개 **앱 설치 폴더**(`C:\Program Files\…`)나
시스템 폴더다.

즉 새 사용자의 **첫 작업공간이 앱 설치 폴더가 될 수 있다.** 그러면:
- `.agent_party_app/` 가 **설치 폴더 안에** 생긴다.
- 그 폴더는 쓰기 권한이 없을 수 있다 → **파티 생성이 실패한다.**
- 성공하더라도 **앱을 업데이트·재설치하면 파티가 날아간다.**
- 멤버(=AI 에이전트)의 작업 디렉터리가 **앱 설치 폴더**가 된다.

**⚠️ 이건 F-02(자동 업데이트)와 정면으로 부딪힌다.** 업데이트가 설치 폴더를 갈아엎으면
거기 있던 파티가 사라진다.

**확인 필요**: 패키징된 빌드에서 실제로 `process.cwd()` 가 무엇이 되는지 **실측**할 것.
(NSIS 설치본 바로가기 / portable 실행 / 파일 탐색기에서 더블클릭 — 셋이 다를 수 있다.)
그리고 경로가 **쓰기 가능한지 검증하지 않는다**(`workspaceManager.ts:52-60` 은 어떤 경로든
조용히 컨텍스트를 만든다).

→ **첫 실행에서 작업공간을 고르게 하거나, 최소한 사용자 문서 폴더 같은 안전한 기본값**으로.

## 첫 메시지까지 실제 걸음 수

Claude Code 가 이미 설치·로그인돼 있다고 **가정해도** 6단계다:

1. 파티 만들기 (눈에 안 띄는 입력칸)
2. 멤버 만들기 (마법사 — 하네스·모델·추론·이름)
3. 멤버 클릭 → 탭 열기
4. 입력창에 타이핑
5. 전송 → 세션 시작
6. 응답 대기

**조용히 실패할 수 있는 지점이 4곳**(2·2·3·5). 그리고 위 가정 자체가 새 사용자에겐 성립하지 않는다.
