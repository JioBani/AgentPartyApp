# 조사 — 베타 운영과 진단

베타 사용자가 문제를 겪은 뒤 그 사실이 작성자에게 닿기까지의 경로. **지금은 이 경로가 끊겨 있다.**

---

## 🔴 앱이 죽어도 아무 흔적이 없다

**`src/main/main.ts`** — 프로세스 수준 예외 처리기가 **하나도 없다.**

- `process.on("uncaughtException")` **없음**
- `process.on("unhandledRejection")` **없음**
- 렌더러에 React **error boundary 없음** (`src/renderer/App.tsx`)
- 있는 것은 시작 시 오류만 잡는 `app.whenReady().then(bootstrap).catch()` (`main.ts:933-936`)

**결과**: 실행 중 치명적 오류가 나면 **앱이 그냥 사라진다.** 사용자에게 아무 말도 없고,
**죽기 전에 로그가 남는다는 보장도 없다.**

베타에서 이건 단순한 안정성 문제가 아니라 **정보 손실**이다 — 가장 심각한 결함이
가장 적은 단서를 남긴다. 프로젝트 규칙("실패를 조용히 넘기지 말 것")의 최상위 위반이다.

**최소한**: 죽기 전에 로그를 남기고, **"앱이 종료됐고 기록은 여기 있다"** 를 사용자에게 알린다.

---

## 🔴 사용자가 자기 버전을 말할 수 없다

버전은 `package.json:4` 의 `0.1.0` 뿐이고 **화면 어디에도 안 나온다.**
설정의 자동화 API 화면(`src/renderer/app/secondaryViews.tsx:976`)은 로그 경로는 보여주지만
버전은 안 보여준다.

→ 제보를 받아도 **어느 빌드인지 모른다.** 재현이 불가능해진다.
→ [F-02](F-02%20자동%20업데이트.md) 의 전제이기도 하다. **버전 표시가 자동 업데이트보다 먼저다.**

---

## 🔴 로그에 손이 닿지 않는다

로그는 NDJSON 으로 남고(`src/main/logger.ts:28-38`) 경로가 설정 화면에 **글자로만** 표시된다.

- **`로그 폴더 열기` 버튼 없음** (main 에서 `shell.openPath()` 한 줄이면 된다)
- **`경로 복사` 버튼 없음** (같은 화면에 클립보드 복사가 이미 있는데 로그엔 안 붙어 있다)

→ 기술적이지 않은 사용자는 **로그를 건네줄 방법이 없다.** 스크린샷 한 장만 오고 끝난다.

---

## 사용자용 문서가 없다

| 문서 | 실제 독자 |
|---|---|
| `README.md` | **개발자** — `npm install` / `npm run build` 로 시작한다 |
| `docs/기능정의서.md` | **기획자** — UR 부착점 정의지 사용법이 아니다 |
| `docs/FEEDBACK.md` | **내부** 버그 원장 |
| `docs/베타 공개 준비/` | **내부** 준비 목록 |

**`.exe` 만 받은 사람을 위한 글이 한 줄도 없다.** 없는 것:
- 시작 안내(무엇을 미리 깔아야 하는지 — 특히 **WSL 준비물**)
- 문제 해결("X 가 안 되면 Y 를 보라")
- **제보하는 법**("로그는 여기, 버전은 저기, 이렇게 알려달라")

→ [F-09](F-09%20도움말.md) 로 간다.

---

## 제보 창구가 앱 안에 없다

- 설정 화면에 `문제 신고` 링크·버튼 **없음**
- 텔레메트리·분석 **전무** (검색 결과 0건)

텔레메트리는 **넣지 말 것을 권한다** — 베타 사용자가 소수라면 직접 소통이 낫고,
넣는 순간 동의·수집 범위 설계가 따라붙는다.

다만 **"로그 폴더 열기 + 버전 표시 + 제보 안내 한 줄"** 세 개만 있으면 창구는 선다.
이 셋은 각각 몇 줄짜리 작업이고, **셋이 같이 있어야 의미가 있다.**
