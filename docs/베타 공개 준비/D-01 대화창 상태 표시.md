# D-01. 대화창 상태 표시를 확실하게

**판정: 첫인상** · 출처: 사용자

## 무엇을

워크벤치 대화창에서 `responding`·`requesting` 같은 **지금 무슨 상태인지**가
더 확실하게 보이도록 한다.

## 왜

멤버가 여럿 동시에 도는 화면이다. 지금 누가 무엇을 하는 중인지가 흐릿하면
사용자는 **기다려야 하는지, 뭔가 잘못된 건지 판단할 수 없다.**

> 이 앱은 **훑어보는 화면**이다. 한 세션을 들여다보는 도구가 아니라
> 여러 세션의 상태를 **스캔**하는 도구다. 상태 표시는 부가 기능이 아니라 **주 기능**이다.

## ⚠️ 새 작업이 아니다 — 이미 열린 항목 셋을 묶는 일

| 항목 | 내용 |
|---|---|
| **[P-3]1·2** (OPEN 개선) | 상태 칩·상태색 |
| **[#20]** (OPEN 버그) | 패널 헤더 상태 필이 **`wide` 폭에서만** 렌더된다. 좁은 폭에서는 `working` 뿐 아니라 **`approval`(승인 대기)·`stalled`(멈춤)까지 사라진다** |
| **[F-12](F-12%20승인%20필요%20알림.md)** 1단계 | 파티 목록에 승인 대기 표시 |

**셋을 따로 하면 세 번 만든다.** 묶어서 한 번에 다시 설계한다.

### [#20] 의 최악 조합 — 알 경로가 0이 된다
> **사이드바를 접은 상태 + 좁은 패널** → 승인 대기를 알릴 경로가 **하나도 없다.**

좁은 폭에서 살아있는 표시(사이드바 점 3개, `wb-dot` 펄스, 타이핑 인디케이터, 파티 카드의
`N working`)는 **전부 "작업 중"만 알린다.** 승인 대기·멈춤을 알리는 경로가 없다.

## ⚠️ 순서 — D-03 이 먼저다

[D-03](D-03%20멤버%20색.md)(멤버별 색)을 **먼저 정해야 한다.**
상태를 색으로 알리려는데 **멤버색이 이미 색을 쓰고 있으면 두 색이 한 화면에서 싸운다.**
순서가 뒤집히면 D-01 을 두 번 하게 된다.

그리고 **[#13]/[B-05](B-05%20권한%20막힘%20침묵.md) 계열이 먼저**라는 기존 판단도 유효하다:
> 표시 형태를 고치기 전에 **표시할 상태값 자체가 정확해야** 한다.
> 순서가 뒤집히면 **틀린 값을 더 예쁘게 보여주게 된다.**

## 정해야 할 것

- **상태 어휘를 몇 개로 줄일지.** 지금 기능정의서 1-5-2 는 아홉 가지를 적어 뒀다
  (시작 전·준비/유휴·요청 중·응답 중·중단 중·닫힘·오류·승인 대기·읽지 않음).
  **훑어보는 화면에 아홉 가지는 많다.**
  → **선례**: Vibe Kanban 은 세 갈래로 묶었다 — `Needs Attention` / `Idle` / `Running`.
    **승인 대기를 1급으로 올린 것**이 핵심이다.
- **색만으로 구분하지 말 것** — 색각 차이·흑백 캡처·다크/라이트 전환에서 무너진다.
- **좁은 폭에서도 남을 표현이 무엇인지.** 이게 [#20] 의 답이다.
