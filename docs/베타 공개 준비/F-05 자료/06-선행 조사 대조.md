# 06 — 선행 조사와 대조

대상: [`docs/claude-code-ux-research/02-command-skill-palette.md`](../../claude-code-ux-research/02-command-skill-palette.md)

그 문서는 **공식 웹 문서 + `claude.cmd --help`** 로 작성됐다(문서 상단 출처 표기).
**실제 UI 를 열어 본 것이 아니다.** 이번에 실물로 대조한 결과를 남긴다.

같은 폴더의 문서를 코드와 대조했다가 F-11 이 **3/3 오탐**을 낸 전례가 있어
F-05 지시가 "출발점으로 쓰되 실물로 확인하라"고 못 박은 항목이다.

## 뒤집힌 것

| 선행 조사가 적은 것 | 실측 |
|---|---|
| "오른쪽 또는 하단 **preview pane**" — 긴 설명·입력 예시·위험/권한 영향·관련 설정·source file 을 담는 창 | **네 표면 어디에도 없다.** 미리보기 창을 가진 레퍼런스가 하나도 없었다 |
| "command row 최소 정보: icon · name · description · category/source · scope · **badge 8종**(`requires git` `read-only` `edits files` `background` `cloud` `needs auth` `disabled`) · argument signature" | **이만큼 넣는 레퍼런스가 없다.** VS Code 확장은 **이름만**, CLI 는 이름+설명 한 줄. 아이콘 없음. 배지는 Codex `@` 의 타입 배지 1종뿐 |
| "category **tabs** 또는 section headers: Commands·Skills·Agents·MCP prompts·Plugins·AgentParty" | 탭은 **Codex `@` 의 범위 탭이 유일**. Claude VSCode 는 섹션 헤더만 쓰고, 그 섹션 이름은 제안된 분류와 다르다 — **Context·Model·Customize·Slash Commands·Settings·Support** (기능 분류가 아니라 **하려는 일** 기준) |
| "disabled item 은 왜 disabled 인지 보여준다" | **실측 범위에서 disabled 행 자체를 못 봤다.** 미확인 |
| "Enter: argument 가 필요하면 composer 에 command scaffold 삽입 / Tab: highlighted suggestion 적용" | **인자 입력 UI 를 네 표면 모두에서 관측하지 못했다.** Codex `/` 는 설명 문장에 `<absolute_path>` 라고 적어 둘 뿐이다. Tab 동작 미확인 |

## 여전히 쓸모 있는 것

- **분류 체계** — built-in control command / built-in skill / user·project custom command /
  MCP prompt / AgentParty command. 인벤토리를 나누는 축으로 유효하다
- **명령별 UX 요구** — `/model` `/permissions` `/mcp` `/agents` `/tasks` `/diff` `/context` 가
  각각 무엇을 하는지. 실제로 Claude VS Code 확장의 `Customize` 섹션이
  (Agents · Hooks · Memory · Permissions · MCP servers · Manage plugins) 그 목록과 겹친다
- **"현재 멤버에 실행" vs "새 멤버로 dispatch" 구분** — 레퍼런스에 없는 축이지만
  우리 전제(멀티 멤버)에서는 실제로 필요한 지적이다

## 교훈

선행 조사의 **분류·기능 목록은 문서로 쓸 수 있었고, UI 설계는 그러지 못했다.**
"어떤 정보를 담아야 하는가"를 문서에서 추론하면 **실제보다 훨씬 무거운 UI** 가 나온다 —
배지 8종·미리보기 창·아이콘은 전부 실물에 없었다.

**레퍼런스의 실제 선택은 일관되게 "덜 넣는 쪽"이었다.**
