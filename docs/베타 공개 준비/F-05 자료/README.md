## 한 장 요약

### 결론 1 — 셋 다 다르게 푼다. 그리고 셋 다 우리보다 적게 보여준다

| 거르는 수단 | Codex CLI | Claude CLI | Claude VSCode | **우리** |
|---|---|---|---|---|
| 트리거 분리 (`/` vs `@`) | **○** | ✗ | ✗ | ✗ |
| 섹션 헤더 | ✗ | ✗ | **○** 6섹션 | ✗ |
| 범위 탭 (←/→) | **○** | ✗ | ✗ | ✗ |
| 타입 배지 | **○** | 설명 앞 태그 | 이름 접두 | ✗ |
| 설명까지 검색 | ✗ | ✗ | **○** | ✗ |

> 우리는 다섯 개 중 **하나도 없다.** 60~86행을 한 목록에 쏟고 이름으로만 거른다.

### 결론 2 — ⭐ "한 컴포넌트로 묶기"는 우리 발명이 아니다

Claude Code VS Code 확장은 `/` 팝업 **하나**에 이미 다 넣어 놨다.

```
## Context         파일 첨부 · 파일 멘션 · 대화 비우기 · Rewind
## Model           모델 바꾸기 (Opus (1M context)) · Effort (High) · Thinking · …
## Customize       Output styles · Agents · Hooks · Memory · Permissions · MCP · 플러그인
## Slash Commands  /… (104개, 알파벳순)
## Settings        계정 전환 · 설정 · Remote Control
## Support         도움말 · 문제 신고 · v2.1.220
```

F-05 가 묶으려는 **[P-2](모델) · [P-10](스킬) · [P-11](자동완성) · [P-20](하네스·모델)** 이
그대로 이 구조에 들어간다. `Model` 섹션 = P-2/P-20, `Customize` 섹션 = F-07(플러그인)·권한 UI 입구.

### 결론 3 — "Claude 처럼"에는 정답이 하나가 아니다

**같은 제품이 표면에 따라 정반대로 판단했다.**

| | Claude **CLI** | Claude **VS Code 확장** |
|---|---|---|
| 행에 설명 | **인라인으로 다 보여준다** | **DOM 에 아예 없다** (title 툴팁만) |
| 설명까지 검색 | **안 한다** | **한다** |
| 그룹 | 없음 | **섹션 6개** |

→ 베낄 하나를 고르는 문제가 아니라 **우리가 골라야 하는 문제**다.
무엇을 고를지는 [05-비교와 결정 지점.md](05-비교와%20결정%20지점.md).

### 결론 4 — 아무도 안 하는 것

- **미리보기 창(preview pane) 을 가진 레퍼런스가 하나도 없다.** 선행 조사가 제안했던 구조다
- **결과 개수 상한을 두는 곳이 없다.** 넷 다 전부 렌더하고 스크롤에 맡긴다
- **퍼지(부분수열) 매칭은 Codex `@` 하나뿐.** 나머지 셋은 부분 문자열
- 즐겨찾기·최근 사용(MRU) 을 쓰는 곳을 **관측하지 못했다**

## 미확정 — 추가 실측 필요

- **인자를 받는 명령을 어떻게 채우는가.** 네 표면 모두에서 인자 입력 UI 를 관측하지 못했다.
  F-05 가 "정해야 할 것"으로 지목한 항목이라 설계 전에 다시 재야 한다
- **비활성(disabled) 행**을 어떻게 보여주는가. 실측 범위에서 disabled 행 자체를 못 봤다
- Claude Code **데스크톱 앱**은 이 PC 에 없다(로그 폴더만 존재) → 범위 밖
- **Cursor** 팔레트는 미측정
