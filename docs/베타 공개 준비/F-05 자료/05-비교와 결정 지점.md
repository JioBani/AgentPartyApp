### 네 표면이 전부 같은 것

- ↑↓ 이동 · **Enter 선택** · **Esc 닫기**
- **결과 개수 상한 없음** — 전부 렌더하고 스크롤에 맡긴다
- **검색 입력이 별도 필드가 아니다** — 컴포저에 이어 친 글자가 필터
- **미리보기 창(preview pane) 없음**
- **즐겨찾기·최근 사용(MRU) 관측되지 않음**

### 아무도 안 하는 것

## 두 갈래 설계 — 레퍼런스는 둘로 갈린다

### A안 · Codex형 — **쪼갠다**

트리거를 나눠 각 목록을 짧게 만든다. `/`=명령(≈35), `@`=자산(스킬·플러그인·파일).
표면의 목적에 따라 **매칭 규칙도 다르게** 한다 — 명령은 엄격, 자산은 퍼지.
범위 탭(←/→)과 우측 타입 배지로 한 번 더 거른다.

- **강점**: 어느 목록도 길지 않다. 오타로 엉뚱한 명령이 실행될 위험이 낮다
- **대가**: 사용자가 트리거 두 개를 외워야 한다.
  ⚠️ **하네스마다 `@` 의 뜻이 다르다** — Claude 에서 `@` 는 파일 멘션이다.
  멀티 하네스인 우리 앱에서는 이게 그대로 충돌한다

### B안 · Claude VSCode형 — **합치고 섹션으로 나눈다**

한 팝업에 명령·스킬·모델·설정·액션을 다 넣고 섹션 헤더로 구분한다.
설명은 행에 안 그리고 툴팁으로 밀어 밀도를 확보한다(27px, 11행).
이름과 설명을 모두 검색해 발견성을 채운다.

- **강점**: **F-05 가 묶겠다고 한 P-2·P-10·P-11·P-20 이 한 번에 해결된다.**
  트리거가 하나뿐이라 하네스 차이와 무관하다
- **대가**: 목록이 133행까지 길어진다. 설명이 안 보여 **처음 보는 스킬이 뭔지 모른다**

## 우리 전제와의 충돌 — 레퍼런스에 없는 조건

레퍼런스 넷은 전부 **단일 하네스 · 단일 세션**이다. 우리는 아니다.

1. **멀티 하네스** — 같은 팔레트가 Claude · Codex · Cursor 멤버에서 다르게 채워진다.
   `/compact` 는 Codex 에 없고 Cursor 는 `/compress` 다.
   **레퍼런스에 선례가 없다.** 자체안이 필요한 유일한 지점으로 보인다
2. **`@` 의 의미 충돌** — A안을 그대로 쓰면 Claude 멤버에서 `@` 가 파일 멘션과 겹친다
3. **멤버가 여럿** — "현재 멤버에 실행" vs "다른 멤버로 보내기" 구분이 필요할 수 있다
   (선행 조사가 지적한 것. 레퍼런스에는 없는 축)

## 결정 지점 — 각각의 대가

### 결정 1. 행에 설명을 그리나

| | 내용 | 대가 |
|---|---|---|
| ⓐ | **안 그린다** (VSCode) | 27px·11행으로 밀도 최고. **처음 보는 스킬이 뭔지 알 수 없다** — 우리 사용자는 스킬 41개를 직접 만든 사람이 아니다 |
| ⓑ | **항상 그린다** (CLI) | 발견성 최고. 행이 2배라 한 번에 5~6행. 86행에서 스크롤이 길어진다 |
| ⓒ | **선택 행만 그린다** | 둘 다 취함. **레퍼런스에 선례가 없어 우리가 검증해야 한다** |

### 결정 2. 스킬을 `/` 에 두나 `@` 로 빼나

| | 내용 | 대가 |
|---|---|---|
| ⓐ | 한 목록 + 섹션 (Claude) | 구현 단순, 외울 게 하나. 여전히 86행 |
| ⓑ | 트리거 분리 (Codex) | 각 목록이 짧다. **하네스마다 `@` 뜻이 다름** · 둘을 외워야 함 |

### 결정 3. 설명까지 검색하나

| | 내용 | 대가 |
|---|---|---|
| ⓐ | 이름 + 설명 (VSCode) | 이름을 몰라도 하려는 일로 찾는다. 결과가 늘어난다(`/c`→126행) |
| ⓑ | 이름만 (CLI 둘 다) | 예측 가능·결과 짧음. **이름을 모르면 못 찾는다** |

### 결정 4. 퍼지 매칭을 넣나

| | 내용 | 대가 |
|---|---|---|
| ⓐ | 부분 문자열만 | 레퍼런스 4개 중 3개. 예측 가능 |
| ⓑ | 퍼지 부분수열 | 오타에 강함. `xlsx` 가 `CodexPermissionControl.tsx` 를 부른다 |

### 결정 5. 모델·설정까지 넣나 (P-2·P-20 통합 여부)

| | 내용 | 대가 |
|---|---|---|
| ⓐ | 넣는다 (VSCode) | **F-05 의 원래 목표가 한 번에 달성된다** |
| ⓑ | 명령만 | 변경 범위가 작다. **P-2·P-20 을 따로 만들게 된다 — F-05 가 경고한 "네 번 만든다"** |

### 결정 6. 하네스 차이를 어떻게 드러내나 (선례 없음)

ⓐ 없는 건 안 보여준다 · ⓑ 보여주되 비활성 + 사유 · ⓒ 하네스 배지로 구분
