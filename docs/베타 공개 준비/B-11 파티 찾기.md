# B-11. 파티를 찾으려면 cwd 를 전부 뒤져야 한다

**판정: 차단 유력** · **조사·설계 완료** · 갈래: *작성자가 안 쓰는 경로가 비어 있다*

## 무엇이 문제인가

앱은 **cwd(작업공간) 기준으로** 열린다. 그래서 사용자가 *"내 파티가 어디 있더라"* 를 알려면
**작업공간을 하나씩 열어봐야 한다.** 전체를 보는 자리가 없다.

**자기가 만든 것을 다시 못 찾는 것**은 새 사용자가 **두 번째 실행**에서 바로 부딪히는 벽이다.
첫 실행은 "만들기"라 문제가 안 드러나고, 두 번째 실행에서야 드러난다 — 그래서 작성자는
잘 안 밟는다(항상 같은 폴더에서 열기 때문).

## ⚠️ 이건 버그가 아니라 설계의 결과다

*"작업공간 = cwd, 파티 저장소는 `.agent_party_app/` 안에 둔다"* 는 **의도된 설계**다
(기능정의서 1-1-1·1-1-2). 폴더를 옮기거나 백업하면 파티가 따라오는 장점이 여기서 나온다.
**그 장점을 버리지 않으면서** 찾기 문제만 푸는 것이 과제다.

## 조사 결과 — 18개 도구 대조

Google Antigravity · Sculptor(Imbue) · Conductor · Crystal · Vibe Kanban · Onlook · Orca ·
VS Code · JetBrains · Zed · Warp · GitHub Desktop · GitKraken · Sourcetree · Fork · Tower ·
Sublime Merge · LazyGit · (+ Obsidian, Lightroom)

### 결론 ①: 지금 설계가 옳은 쪽이다 — 바꾸지 않는다

- **12개 이상이 같은 하이브리드** — 정본은 폴더 안, 앱은 경로 색인만 갖는다.
  VS Code · JetBrains · Zed · Orca · Claude Code · Obsidian · 그리고 git 클라이언트 5종 전부
  (`.git/` + 북마크 목록).
- **중앙 저장만 쓰는 쪽은 3개**(Conductor · Crystal · Vibe Kanban)인데,
  **Vibe Kanban 은 사용자들이 프로젝트 안 설정을 달라고 요청하고 있다**(#1820).
  시장이 이 앱의 모델 쪽으로 오고 있지 반대가 아니다.

**→ 이 앱은 이미 옳은 쪽에 있다. 색인 절반만 안 만들었을 뿐이다.**

### 결론 ②: 식별자를 폴더 안에 넣는다 (Obsidian 모델)

⚠️ **1차 결론을 정정한다.** 처음엔 Antigravity 사례를 보고 *"UUID 로 키잉하지 말고 경로를
키로 쓰라"* 고 적었는데, **절반만 맞았다.**

- Antigravity 가 깨진 진짜 이유는 UUID 를 써서가 아니라 **UUID 가 폴더 안에 없어서**다.
  중앙에서 발급하니 폴더를 옮기면 **새 ID 를 다시 만들어** 옛 것과 연결이 끊긴다
  → **파일은 멀쩡한데 UI 엔 아무것도 안 보인다.**
- 경로를 유일 키로 쓰는 쪽도 똑같이 깨진다. GitHub Desktop 은 경로가 기본 키(`&path` 유니크)라
  **옮기면 사람이 일일이 다시 찾아줘야** 한다.

**정답은 Obsidian 모델** — 이 앱과 구조가 가장 똑같은 선례다(볼트 = `.obsidian/` 을 품은 폴더):

> **식별자를 폴더 안에 넣고, 색인은 `식별자 → {경로, 시각, …}` 로 매핑한다.**

- 파티 생성 시 `.agent_party_app/` 안에 **`partyId`(UUID)를 쓴다.** 폴더를 옮기면 ID 가 따라간다.
- 색인은 `partyId` 로 키잉하고 **`path` 는 바뀔 수 있는 속성**으로 둔다.
- 어떤 경로로든 파티를 열면 그 `partyId` 의 `path` 를 갱신하고 중복 항목을 합친다
  → **폴더를 옮긴 뒤 탐색기에서 그냥 열면 저절로 낫는다.**

**이 결정 하나가 Claude Code · Vibe Kanban(#2993) · VS Code · JetBrains 가 공유하는
"경로가 기본 키라 옮기면 조용히 고아가 된다" 결함 계열 전체를 비껴간다.**

### 결론 ③: 사라진 항목을 조용히 지우지 않는다

**8개 도구 중 자동으로 지우는 곳은 LazyGit 하나뿐**이고, 그건 항목이 그냥 최근 목록이라
잃을 게 없어서 성립한다. 이 앱은 다르다(이름·분류·설정이 붙는다).

**왜 안 되는지 — JetBrains 가 명시한 근거:**
> **마운트 안 된 네트워크 드라이브·암호화 파티션·잠든 외장 디스크는 "삭제됨"과 구분이 안 된다.**

즉 존재 확인 실패는 *"없다"* 가 아니라 *"지금 확인할 수 없다"* 이다.

⚠️ **이 앱엔 더 절실하다 — WSL 경로를 정식 지원한다.** WSL 이 안 떠 있으면 경로가 통째로
안 보인다. 자동 삭제를 넣으면 **WSL 작업공간이 앱을 껐다 켤 때마다 사라질 수 있다.**

### 결론 ④: Orca 가 이미 코드로 구현해 뒀다 (MIT, `stablyai/orca`)

경로 상태를 **불린이 아니라 사유가 붙은 값**으로 둔다:

```
'missing' | 'not-directory' | 'unavailable' | 'ambiguous-connection'
```

- **`missing`·`not-directory` 만 "확실히 없음"으로 인정**한다(`isConfirmedStaleFolderPathStatus`).
- `unavailable` 은 **"지금 확인할 수 없음"** 이라 부재로 치지 않는다.
- 상태는 10초 캐시. 확실히 stale 인 항목은 **목록엔 남기되 열기를 막는다.**
- (`src/shared/folder-workspace-path-status.ts`)

정리도 하긴 한다 — 단 **로컬 항목만, 30일 무활동 유예 뒤에.**
즉 실제 관행은 *"안 지운다"* 가 아니라 **"확신이 설 때까지 안 지운다"** 이다.

### 결론 ⑤: 스캔하지 않는다

- GitHub Desktop · Sculptor · Conductor · Onlook · Crystal · Vibe Kanban · Sublime Merge —
  **스캔이 아예 없다.** 연 적 있는 것만 쌓인다.
- 스캔이 있는 쪽(GitKraken · Fork · Tower)도 **문제를 하나 안고 있다**:
  Fork 는 **재스캔이 사용자가 손으로 만든 분류를 덮어써 버린다**(미해결 불만).
- Tower 의 스캔은 그나마 낫다 — **훑어서 후보 체크리스트를 보여주고 사용자가 고른다.**

**→ 규칙 하나로 압축된다: 앱은 추가도 제거도 "제안"만 하고, 어느 쪽도 혼자 실행하지 않는다.**

### 결론 ⑥: 색인 파일은 JSON + 롤링 백업

- GitHub Desktop 은 목록을 IndexedDB(LevelDB) **단일 바이너리 덩어리**에 넣었다가
  업데이트·손상 때 **목록이 통째로 날아가는 사고**가 반복 보고됐다.
  Sourcetree 도 색인 파일을 손으로 지우는 것 말고 방법이 없던 이력이 있다.
- Orca 는 `orca-data.json` 하나에 넣고 **1시간 이상 간격으로 최대 5개 백업**(`.bak.0~4`)을 굴린다.
- **한 항목이 깨져도 나머지가 뜨도록** 읽는다. (LazyGit 은 최근 항목이 없으면 **크래시**했다.)

## 그래서 만들 것

**색인은 캐시이지 정본이 아니다.** 지워도 "폴더 열기"로 다시 쌓이면 된다.

1. **`.agent_party_app/` 안에 `partyId`(UUID)** 를 쓴다.
2. **앱 사용자 영역에 색인 파일** — `{ partyId, path, displayName, lastOpenedAt, pinned }`.
   JSON + 롤링 백업. 항목 수 상한(VS Code 는 500).
3. **목록 화면** — 최근 활동순 + 검색. 행에는 이름 · 흐린 전체 경로 · 마지막 연 시각 ·
   **파티 수 · 작업 중 멤버 수 · 승인 대기**(← 이 앱만의 것).
4. **들어오는 길 셋** — 폴더 열기 / 드래그 드롭 / (선택) 부모 폴더 훑어 **후보 체크리스트**.
5. **없음 상태** — 사유가 붙은 경로 상태를 쓰고, 확실한 것만 "없음"으로 표시.
   행동은 **`위치 찾기…` · `목록에서 치우기` · `무시`**.
6. **일괄 재지정** — 여러 항목이 같은 상위 경로 아래서 한꺼번에 사라지면
   *"…아래 전부 다시 지정"* 을 준다. **이건 아무도 안 풀었다**(GitHub Desktop #17793,
   Sourcetree 요청 모두 미해결). Lightroom 의 *"근처의 사라진 사진 찾기"* 가 유일한 선례다.
7. **AGENTS.md 규칙대로** `AppController` + `apiSpec.ts` + `API.md` 에 등록한다.

## ⚠️ 함정

1. **"목록에서 치우기" ≠ "파티 삭제"** — Sourcetree 는 북마크 `Delete` 가 **실제 폴더를 지워서**
   오래된 불만이 됐다. 이 앱은 파티 삭제가 **되돌릴 수 없으므로**(기능정의서 1-3-3)
   **두 동작을 절대 같은 버튼으로 두지 말 것.** Obsidian 은 *"목록에서 제거해도 폴더는 그대로
   둔다"* 를 문구로 명시한다 — 그대로 따른다.
2. **죽은 항목에 방어적이지 않으면 시작 자체가 깨진다** — Sourcetree 는 옮겨진 저장소 때문에
   **시작 시 크래시**가 났다.
3. **"처음 여는 폴더" 신뢰 확인을 검토할 것** — JetBrains 의 *Trust Project* 가 선례다.
   이 앱에서 파티를 연다는 건 **그 폴더에 대해 권한을 가진 에이전트를 돌린다**는 뜻이라,
   특히 스캔으로 발견한 폴더엔 방어가 정당하다.

## ⚠️ 이 조사가 F-08 로 넘긴 위험

**하네스는 자기 대화 기록을 절대 경로로 키잉한다.** Vibe Kanban 이 정확히 이걸로 깨졌다 —
작업공간 이름을 바꾸자 경로가 바뀌어 **`~/.claude/projects/` 의 키가 무효**가 되고
**Claude Code 세션 resume 이 끊겼다**(#2993). 후속 결함(#3255)도 열려 있다.

**이 앱에 그대로 걸린다.** [#26] 조사에서 *"대화 인계는 하네스 원본을 쓴다"* 고 결정했기 때문이다.
사용자가 프로젝트 폴더를 옮기면:
- 앱 상태(`.agent_party_app/`)는 **따라간다** — 설계대로 무사하다.
- **하네스 원본은 옛 경로에 묶여 따라오지 않는다.**

→ **"폴더를 옮겨도 파티가 따라온다"는 이 앱의 장점이 대화 연속성에서는 성립하지 않을 수 있다.**
**F-08 방침을 정할 때 반드시 확인할 것** — 지금은 검증되지 않은 가정이다.
