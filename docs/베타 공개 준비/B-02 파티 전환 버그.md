# B-02. 파티 전환 시 자잘한 버그

**판정: 부분 해소 — 대화 정합성 수정, 대규모 파티 전환 성능은 개선 대기** · 출처: 사용자

## 무엇을

파티를 오갈 때 자잘한 결함이 있는 것 같다. 확인하고 수정한다.

## ⚠️ 같은 계열의 선례가 둘 있다 — 재발 여부부터

- **[#5]** (FIXED) — 파티 간 이동 시 **다른 파티의 대화가 그대로 남았다.**
- **[#7]** (FIXED) — 멤버를 삭제하고 같은 이름으로 재생성하면 **이전 대화가 남아 보였다.**

**둘 다 근본 원인이 같았다**: 렌더러의 복원 캐시(`restoredByMember`)가
**멤버 이름만으로 키잉**돼 있었다. 모든 파티가 `main` 을 가지므로 이름은 파티 간 유일하지 않다.
→ 캐시 키를 **`(partyId, name, createdAt)`** 로 바꿔서 고쳤다(`memberKey`).

**디스크 저장소는 원래부터 정상이었다** — 정본은 멀쩡한데 **화면 캐시만 어긋났던** 것이다.

→ **지금 보고된 것이 같은 계열의 재발인지, 다른 것인지부터 가른다.**
같은 계열이면 **"이름으로 키잉한 자리가 또 있는가"** 를 찾으면 된다.

## 필요한 것 — 증상 목록

- **무엇이 어긋나는가** — 대화 내용 / 열린 탭·패널 배치 / 활성 탭 / 멤버 상태 / 사이드바 상태
- **언제** — A→B 전환 직후 / 다시 A 로 돌아왔을 때 / 앱 재시작 후
- **지속되는가** — 잠깐 깜빡이고 정상으로 오는가, 계속 틀린 채 남는가
  (⚠️ 깜빡임이면 [#19] 계열의 **세션 목록 경합**일 수 있다 — `sessionListRouting.ts` 참고)

## 2026-09-11 후속 — 대화 정합성 수정과 남은 성능 개선

- **수정 완료:** 다른 파티에서 응답이 끝나고 세션이 sleep·종료된 뒤 원래 파티로
  돌아오면 기존 창만 대화를 갱신하지 않던 문제. 비활성 파티 소유자의 복원 캐시도
  갱신 대상으로 표시하고, 복귀 시 메인 프로세스의 저장본을 한 번 다시 읽도록 했다.
- **오해 제외:** 파티를 전환할 때마다 디스크에서 대화를 다시 읽는 구조는 아니다.
  살아 있는 세션의 후속 스트림은 IPC로 메모리에 계속 추가되고, 세션이 실제로
  종료된 예외 경로에서만 복귀 시 한 차례 다시 읽는다.
- **개선 대기:** 멤버와 대화가 많은 대규모 파티는 전환 시 짧은 버벅임이 체감된다.
  원인을 디스크 재조회로 가정하지 말고, 파티 전환 구간에서 패널 재구성, React 커밋,
  대화 블록 마운트, 살아 있는 세션 로그의 메모리 점유를 각각 계측한다.
- **완료 조건:** 실제 앱에서 소규모·대규모 파티의 전환 시간을 같은 측정 지점으로
  비교하고, 가장 큰 구간을 특정한 뒤 수정 전후 프레임 정지 시간과 메모리 변화를
  함께 검증한다.
