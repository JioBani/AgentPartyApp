# B-06. 하네스별 권한 렌더링 확인

**판정: ✅ 이상 없음 (2026-08-08 실측)** · 출처: 사용자

---

## ✅ 결론 — 뭉개진 것 없음. 코드 변경 0건.

### 핵심 걱정(공통화가 하네스 차이를 뭉갰나) — **아니었다**
`6386a27` 이 만든 `HarnessPermissionControl` 은 **공통 컨트롤이 아니라 분배기**다.
하네스별로 **다른 컴포넌트**를 고른다. 주석에도 명시돼 있다 —
*"a union of the three, not a lowest common denominator"*.
Codex 는 이름이 아니라 **capability(`twoAxisPermission`)로** 선택된다.

### 실행 중인 앱 DOM 실측 (설정 → 런타임 → 하네스 기본값)

| 하네스 | 실제로 렌더된 것 | 기능정의서 1-4-3·1-11-1 대조 |
|---|---|---|
| **Claude Code** | 단일 select 6개 — Default · Accept edits · Plan · Auto · Don't ask · Bypass | ✅ 일치 |
| **Codex** | **select 2개**(샌드박스 × 승인 정책) + 프리셋 3개 + **Guardian 토글** | ✅ **2축 안 접힘** |
| **Cursor CLI** | select 2개 — (Agent/Ask/Plan) × (Allowlist/Auto-review/Run Everything) | ✅ 별도 정책 유지 |

- **없는 옵션이 새는 경우 0건** — Claude 카드에 샌드박스 없음, Cursor 카드에 Guardian 없음 ✅
- **있는 옵션 누락 0건** ✅

### Guardian — 있다 ([F-11](F-11%20Claude%20Codex%20격차.md) 오탐 확정)
UI 스위치 `CodexPermissionControl.tsx:102-107`, DOM 실측 `guardianToggle: 1`.
끝까지 연결돼 있다: UI → `codexPolicy.guardian` → `codexAdapter` 의
`approvalsReviewer: guardian ? "auto_review" : "user"`(3곳) →
`partyBridge` 스키마 `required: [sandbox, approval, guardian]`.

### 프리셋 정합성 — 값은 정확, 표시에 흠 하나
축을 실제로 움직여 쟀다:
```
기본(workspace-write + on-request)  → 프리셋 "Auto" 활성       ✅ 정확
커스텀(workspace-write + untrusted) → 활성 프리셋 없음 (빈 스트립)
```

**값 매핑은 정확하다.** 다만 프리셋에 안 맞는 조합에서 **스트립이 통째로 비어 보인다.**

⚠️ `codexPresetOf()` 는 **이미 `"custom"` 을 반환하고** 타입에도 `CodexPreset = … | "custom"` 이
있는데 **화면에 표시할 자리가 없다.** 기능정의서 1-4-3 의 프리셋 목록도
**`Read Only · Auto · Full Access · Custom` 4개인데 UI 는 3개다.**

→ **문서·코드 어긋남이므로 결정 사항이 아니라 규칙 준수다.** 표시하는 것으로 확정.
심각도는 낮다(바로 위 select 두 개가 실제 값을 정확히 보여줘 **권한을 오해할 위험은 없다**).
다만 *"아무것도 선택 안 된 것처럼 보여 고장으로 읽히는"* 패턴에는 해당한다.

### 이번에 못 본 것
**멤버 설정 저장·복원(1-11-2)** — 멤버를 닫았다 재실행하며 권한이 유지되는지.
**[B-13](B-13%20권한%20승인%20UI%20QA.md) 동선에서 자연스럽게 걸리므로 거기서 함께 본다.**

## 무엇을

하네스마다 권한 체계가 다른데, **화면에 맞게 렌더되고 있는지** 확인한다.

## 하네스별로 다른 것

| 하네스 | 권한 체계 (기능정의서 1-4-3 · 1-11-1) |
|---|---|
| **Claude 계열** | 단일 권한 모드 — Default · Accept edits · Plan · Auto · Don't ask · Bypass permissions |
| **Codex** | **두 축** — 샌드박스(read-only · workspace-write · danger-full-access) × 승인 정책(untrusted · on-request · never) + 프리셋 |
| **Cursor** | 별도 정책 |

⚠️ **적용 기준은 "실행 하네스"이지 "모델 제공자"가 아니다**(기능정의서 1-11-2).
교차 라우팅([B-12](B-12%20교차%20하네스.md))에서 이게 헷갈리기 쉽다.

## 왜 지금 보는가

**최근에 세 표면의 권한 컨트롤을 하나로 합치는 작업이 있었다:**
- `6386a27` — *"tab the runtime settings screen, share one permission control"*
- `6d6b290` — *"one reviewer control for all three Message Gate surfaces"*

**합치는 과정에서 하네스별 차이가 뭉개졌을 수 있다.**
공통화는 좋지만, **원래 달라야 하는 것까지 같아지면** 사용자가 없는 옵션을 보거나
있는 옵션을 못 본다.

## 볼 것

- 각 하네스에서 **그 하네스에 없는 옵션이 보이지 않는지**
- **있는 옵션이 다 보이는지** (특히 Codex 의 두 축이 하나로 접히지 않았는지)
- **프리셋**(Read Only · Auto · Full Access · Custom)이 실제 값과 맞는지
- **Guardian** — 기능정의서에 있는데 **UI 토글이 없는 것으로 조사됐다**
  ([F-11](F-11%20Claude%20Codex%20격차.md)). 문서·코드 어긋남인지 확인
- 멤버 설정 저장·복원 (기능정의서 1-11-2 — 닫기·재실행 후 복원)
