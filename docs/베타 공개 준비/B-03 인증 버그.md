# B-03. 인증 쪽 버그

**판정: 차단 유력** · 출처: 사용자 · [조사-첫 실행 경험](조사-첫%20실행%20경험.md)

## 무엇을

인증(구독 연결·해제, 키 관리) 쪽에 결함이 있는 것 같다. 확인하고 수정한다.

## 왜 중요한가

인증은 **새 사용자가 가장 먼저 통과해야 하는 관문**이다.
여기서 막히면 **나머지 기능을 볼 기회조차 없다** — 베타에서 가장 비싼 실패 지점이다.

그리고 **여기서 막힌 사용자는 도우미([F-10](F-10%20앱%20도우미%20세션.md))에게 물을 수도 없다** —
도우미도 모델이 필요하기 때문이다.

## 🔴 조사에서 확인된 구체 증상 — "available" 이 로그인을 뜻하지 않는다

**`src/main/authService.ts:71-85`**

Claude·Codex 를 `available` 로 보고하는 것은 **CLI 가 있다는 뜻**이지
**로그인돼 있다는 뜻이 아니다.**

사용자가 보는 것:
> 인증 화면에 Claude `available`, Codex `available`

→ **준비됐다고 믿는다.** 그리고 멤버를 만든다. 멤버 생성도 **성공한다.**
→ **첫 메시지에서** *"subscription required"* 류로 실패한다.

**이건 silent fallback 은 아니지만 같은 계열의 거짓말이다** — 상태 표시가 실제와 다르다.
기능정의서 3-5-1 은 상태 어휘를 *"사용 가능 · 설정됨 · 정상 · 인증 대기 · 미설정 ·
유효하지 않음 · 네트워크 오류"* 로 정의해 뒀는데, **"CLI 는 있는데 로그인 안 됨"이 그중
어디에도 없다.** 어휘 자체에 구멍이 있다.

→ **"사용 가능"과 "인증됨"을 화면에서 구분해야 한다.**

## 나머지 증상 — 특정 필요

사용자 보고는 *"인증 쪽 버그가 있는 것 같다"* 수준이라 특정이 필요하다.

**받아야 할 것**:
- 어느 제공자 — Claude 구독 / Codex 구독 / Cursor / OpenRouter
- 어느 동작 — 연결 / 해제 / 상태 표시 / 갱신
- 무슨 증상 — 실패하는가, 성공했는데 반영이 안 되는가, 상태가 틀리는가

**참고할 기존 이력**: `docs/BUG-REPORT-2026-08-06-WINDOWS-CLAUDE-SUBSCRIPTION-LOGIN.md`
— Windows Claude 구독 로그인 관련 보고서가 이미 있다. **같은 건인지 먼저 확인할 것.**

## 볼 만한 자리 (기능정의서 3장 기준)

- **3-1-2 구독 브리지** — 앱 시작 시 자동 기동, 미설치 시 공식 바이너리 다운로드 + SHA-256 검증.
  **다운로드·검증·실행 실패 경로**가 새 PC 에서 자주 밟힌다.
- **3-2-2 인증 변경 전파** — 로컬·WSL 활성 엔진 전파, 응답 중 세션은 턴 종료 후 재시작.
- **3-5-2 가용성 검증** — 연결·해제 후 모델 검색 재실행.
