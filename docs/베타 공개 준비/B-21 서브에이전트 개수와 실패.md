# B-21. 서브에이전트 개수 카운트가 이상하고, 실패 원인이 앱일 수 있다

**판정: 미정 — 증상 특정 필요** · 출처: 사용자 (2026-08-08) · **소유자: 미정**

두 건이지만 **같은 코드 경로(귀속)를 공유**하므로 한 항목으로 둔다.

## ① 개수 카운트가 이상하다

기능정의서 1-17-1 은 서브에이전트 도크에 **생성 수**와 **실행 중/완료/실패/대기 상태**,
그리고 **전체 상태 요약**을 표시한다고 정의한다. 그 숫자가 맞지 않는다.

**특정이 필요하다** (사용자에게 받거나 실측으로):
- **어디의 숫자인가** — 도크의 생성 수 / 상태별 개수 / 전체 요약 중 무엇
- **어떻게 틀린가** — 많은가 적은가, 안 늘어나는가 안 줄어드는가, 중복으로 세는가
- **어느 하네스인가** — Claude 와 Codex 는 **활동 채널이 다르다**(아래)
- **언제인가** — 실행 중 / 완료 후 / 세션 재시작 후 / 앱 재실행 후

### 귀속 구조 (알려진 사실)
- 귀속 로직은 `src/core/subagentTracker.ts` 에 **격리**돼 있다
- **Claude**: `task_*` 이벤트 (`task_id` / `tool_use_id` / `last_tool_name`)
- **Codex**: **자식 threadId**. ⚠️ `subAgentActivity` 는 **오지 않는다** — 실제 채널은
  **`collabAgentToolCall`** 이다([B-16](B-16%20Codex%20트랜스크립트%20미표시.md) 실측)
- `scripts/qa-subagent-tracker.mjs` 가 **실트래픽을 재생해 검증**한다.
  fixture: `scripts/fixtures/subagents/codex-gptmini-2subagents.jsonl`

→ **재생 검증이 통과하는데 실사용에서 틀리다면, fixture 가 덮지 못하는 상황이 있다는 뜻이다.**
그 상황이 무엇인지가 이 조사의 핵심이다.

## ② 서브에이전트 실패가 이 앱 때문인가

사용자 관찰: 서브에이전트가 실패하는데 **앱이 원인일 가능성**이 있다.

### 확인할 것
- **실패가 하네스에서 난 것인가, 앱이 유발한 것인가** — 원본 트래픽(RawLogger)에
  하네스가 낸 실패가 있는지, 아니면 앱 개입 뒤에 끊겼는지
- **인터럽트 경로** — `[#24]`: 인터럽트 전달이 멤버 쪽에 **에러로 보인다**(정상 동작인데).
  서브에이전트가 도는 중에 부모 턴이 중단되면 어떻게 되는가
- **권한 전파** — 부모 멤버의 권한이 서브에이전트에 어떻게 적용되는가.
  권한으로 막히면 [B-05](B-05%20권한%20막힘%20침묵.md) 처럼 **조용히 실패**할 수 있다
- **턴 상태** — `[#4]` 계열(턴 상태 고착)이 서브에이전트 경로에도 있는가
- **표시만 실패인가, 실제로 실패인가** — 귀속이 틀려서 **성공한 것을 실패로 표시**할 수도 있다.
  ①과 같은 뿌리일 수 있으므로 먼저 가릴 것

⚠️ **①과 ②를 먼저 가른다.** 귀속이 틀린 것이면 ②는 표시 문제이고, 아니면 실제 실행 결함이다.
**성격이 완전히 다르다.**
