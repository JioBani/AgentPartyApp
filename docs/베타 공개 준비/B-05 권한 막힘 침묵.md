# B-05. 권한이 막혔을 때 조용히 실패하거나 `responding` 에 갇힌다

**판정: 차단** · 갈래: *조용히 실패한다* · 출처: 사용자

## 증상 (사용자 보고)

하네스에서 **권한 때문에 실행이 막히면**
- **아무 말 없이 실패**하거나
- **계속 `responding` 상태로 남는다.**

## 왜 심각한가

**두 겹으로 나쁘다.**

1. **프로젝트 규칙 정면 위반** — AGENTS.md 의 *"silent fallback 금지"*.
2. **사용자는 영원히 기다린다** — 멈춘 줄도 모르고, 이유도 모르고, 다음에 뭘 해야 할지도 모른다.
   `responding` 은 *"일하는 중"* 이라는 뜻이므로, **기다리는 것이 올바른 행동처럼 보인다.**

그리고 **새 사용자가 이 경로를 밟을 확률이 특히 높다.** 처음 온 사람은 AI 에게 권한을 다 주지
않으므로 제한된 권한에서 시작하고, 그러면 막히는 일이 잦다.
→ **작성자가 안 밟는 경로 = 신규 사용자의 기본 경로**라는 이 문서 전체의 주제가 여기서도 반복된다.

## 기대 동작

권한으로 막힌 것은 **정상적인 거절**이다. 실패로 조용히 삼키지 말고:

- **무엇이** 막혔는지 (어떤 도구·명령)
- **왜** 막혔는지 (어느 권한 때문에)
- **어떻게 풀 수 있는지** (어느 권한을 올리면 되는지)

를 대화 안에 드러내고 **턴을 닫는다.** `responding` 을 붙잡아 두지 않는다.

## ⚠️ 접근 방법 — 코드 검색으로는 안 잡힌다

**조사 에이전트가 이 결함을 찾지 못했다.** *"코드가 침묵을 명시적으로 거부한다"* 고 보고했다.
**하지만 사용자는 실제로 겪었다.**

> 코드를 읽어 못 찾았다는 것은 **없다는 뜻이 아니라, 코드 읽기로는 안 잡힌다는 뜻**이다.

같은 함정이 [#21] 에서 이미 있었다 — **검증 수단이 실제 죽음을 만들지 못해** 결함이
드러나지 않았고, *"테스트가 관찰한 게 아니라 답을 알려준"* 경우였다.

**→ 재현부터 한다. 재현 절차 없이는 착수하지 않는다.**

받아야 할 것:
- **어느 하네스**에서 (Claude / Codex / Cursor)
- **어떤 권한 설정**으로 (권한 모드 / 샌드박스 / 승인 정책)
- **무슨 작업**을 시켰을 때
- **정확히 무엇이 보였는지** (아무 일도 안 일어남? 오류 문구? `responding` 고착?)
