# B-01. 메시지 큐 버그 다수

**판정: 미정 — 증상 특정 필요** · 출처: 사용자

## 무엇을

메시지 큐(대기열) 기능에 **버그가 많다.** 모아서 수정한다.

## 맥락 — 최근 기능이고 이미 결함이 여럿 잡혔다

큐 UI 는 [P-3]4 로 최근에 들어왔다. 그 과정에서 나온 것:

- **[#22]** (FIXED) — **대기 메시지가 조용히 사라지는 경로 3건**
  1. 멤버가 보낸 대기 메시지가 저장 충돌로 유실
  2. 중단·에러로 끝난 턴 뒤에는 **큐가 영영 안 나감**(정상 완료에만 반응했다)
  3. `broadcast` 가 "대기 중"을 "실패"로 보고 → 발신자가 **중복 재전송**
- **[#23]** (OPEN, 표시로만 완화) — 앱과 하네스의 busy 판정이 달라
  **취소할 수 없는 구간**이 생긴다. *"지금 바로 처리"* 로 보낸 메시지는 **매번** 그렇게 되고,
  **Discord 브리지는 항상 이 옵션을 쓴다.**

⚠️ **[#22] 는 "대기열 UI 를 만들다가 발견"됐다.** 큐가 막으려던 실패가 **이미 실제로
일어나고 있었는데 화면에 큐가 없어서 아무도 몰랐던** 것이다.
→ **큐 관련 결함은 눈에 안 띄는 성질이 있다.** 사용자가 "많다"고 느끼는 것이 타당하다.

## 필요한 것 — 증상 목록

*"버그가 많다"* 로는 착수할 수 없다. **재현 경로별로 쪼개야 고칠 수 있다.**

받아야 할 것 (각 증상마다):
- **언제** — 보낼 때 / 대기 중 / 취소할 때 / 순서 바꿀 때 / 합칠 때 / 앱 재시작 후
- **무엇이** — 사라지는가 / 안 나가는가 / 순서가 틀리는가 / 개수가 안 맞는가 / 화면만 이상한가
- **어느 경로로 보냈나** — 입력창 / 다른 멤버 / HTTP API / Discord
  (⚠️ **Discord 는 항상 인터럽트 경로**라 다르게 동작한다)
- **인터럽트 옵션** 여부

## 먼저 확인할 것

- **[#23] 의 남은 근본 작업**(busy 판정을 한 곳으로 통일)이 안 된 상태다.
  보고된 증상 중 상당수가 **여기서 파생됐을 수 있다.**
- **[#22] 의 3건이 정말 다 막혔는지** — 같은 계열의 네 번째 경로가 있을 수 있다.
