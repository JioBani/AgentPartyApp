# F-04. 멤버 생성을 빠르게 — 기본값·저장된 구성 불러오기

**판정: 첫인상** · 갈래: *작성자가 안 쓰는 경로가 비어 있다* · 출처: 사용자

## 무엇을

새 멤버를 만들 때 **기본값을 그대로 쓰거나**, **저장해 둔 설정을 불러와 적용**해서
빠르게 끝낼 수 있게 한다.

## 왜

지금은 멤버 하나를 만들 때마다 하네스·모델·추론·권한·역할을 매번 고른다.

> **같은 구성의 멤버를 반복해서 만드는 것이 이 앱의 정상 사용 형태**다.
> 파티를 짤 때마다 비슷한 역할이 다시 필요한데, 그 반복이 전부 수작업이다.

새 사용자가 **처음 멤버를 만드는 화면**이라 첫인상 비중도 크다.

## 지금은

- 전역 기본값은 **이미 있다** — 런타임 화면의 `신규 멤버 기본값`
  (기능정의서 4-1-1: 하네스별 모델·effort·thinking·권한 프로필).
  → **재료는 있고, 생성 화면에서 그걸 한 번에 타는 길이 없다.**
- 생성은 최근 3단계로 정리됐다 (`31ded70`, `6225b5e`).
- **이름 붙인 구성(프리셋)을 재사용하는 개념은 없다.**

## ⚠️ 두 가지를 나눌 것 — 비용이 크게 다르다

### ⓐ "기본값 그대로, 이름만 정하고 만들기" ← **먼저**
전역 기본값을 그대로 태우고 이름만 받는다.
**재료가 다 있어서 싸게 끝난다.** 효과는 ⓑ 의 절반 이상이다.

### ⓑ "이름 붙인 구성을 저장했다 불러오기"
사실상 **멤버 템플릿**이다. 범위가 커진다.

- **역할 텍스트까지 포함할 것인가** — 포함하면 완전한 템플릿이 된다
- **저장 범위** — 작업공간별인가 앱 전역인가
- 목록이 늘어나면 **고르는 UI** 가 필요해진다
  → [F-05](F-05%20스킬%20커맨드%20팔레트.md) 의 공통 카탈로그 표면을 탄다
