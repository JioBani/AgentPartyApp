# B-15. 기본 작업공간이 `process.cwd()` 다

**판정: 차단** · 갈래: *작성자가 안 쓰는 경로가 비어 있다* · 출처: [조사-첫 실행 경험](조사-첫%20실행%20경험.md)

## 무엇이 문제인가

**`src/main/settings.ts:42`** — `workspacePath: process.cwd()`

개발 중에는 이게 저장소 폴더라 자연스럽다. **작성자는 항상 저장소에서 `npm start` 로 띄우므로
이 기본값이 틀렸다는 것을 겪을 일이 없다.**

**그런데 설치된 앱에서 `process.cwd()` 는 사용자의 프로젝트가 아니다.**
바로가기가 가리키는 곳 — 대개 **앱 설치 폴더**(`C:\Program Files\…`)이거나 시스템 폴더다.

## 무슨 일이 벌어지는가

새 사용자의 첫 작업공간이 **앱 설치 폴더**가 되면:

1. `.agent_party_app/` 가 **설치 폴더 안에** 생긴다.
2. 그 폴더는 **쓰기 권한이 없을 수 있다** → 파티 생성이 실패한다.
   (`src/main/workspaceManager.ts:52-60` 은 **쓰기 가능한지 검증하지 않고** 어떤 경로든
   조용히 컨텍스트를 만든다.)
3. 성공하더라도 **앱을 업데이트·재설치하면 파티가 통째로 사라진다.**
4. 멤버(= 파일을 읽고 쓰는 AI 에이전트)의 **작업 디렉터리가 앱 설치 폴더**가 된다.

**4번이 특히 나쁘다.** 사용자는 "내 프로젝트에서 일하는 중"이라고 믿는데 에이전트는
엉뚱한 곳을 보고 있다.

## ⚠️ F-02 와 정면으로 부딪힌다

[F-02](F-02%20자동%20업데이트.md) 의 자동 업데이트가 설치 폴더를 갈아엎으면
**거기 있던 파티가 날아간다.** 두 항목을 따로 처리하면 이 조합을 놓친다.

## ✅ 실측 완료 (2026-08-08, `beta-impl`) — **예상보다 나쁘다**

패키징 빌드(`npm run dist:win`)를 실제로 만들어 실행 경로별로 쟀다.

| 실행 경로 | 실측된 기본 작업공간 | 결과 |
|---|---|---|
| **portable exe** | `%TEMP%\<랜덤>` | 🔴 **종료 시 삭제 — 파티 100% 소실** |
| **설치본 바로가기** | **설치 폴더** (`%LOCALAPPDATA%\Programs\AgentParty`) | 🔴 업데이트·재설치 시 소실 |
| **임의 위치에서 exe 실행** | 그 위치 그대로 | 🔴 쓰기 불가면 실패 |

### 🔴 portable 은 파티가 **매번** 사라진다 — 문서 예상보다 심각
NSIS portable 은 앱을 임시 폴더에 풀고 **그 폴더를 cwd 로** 실행한 뒤,
종료 시 **`RMDir /r` 로 지운다**(`portable.nsi:39,89`).

**실증됨** — portable 로 파티 `survivetest` 생성 → `.agent_party_app/parties.json` 이 임시 폴더에
생김 확인 → 앱 종료 → **`.agent_party_app` 통째로 사라짐.**

> portable 사용자는 **껐다 켤 때마다 파티가 전부 없어지고**, 매 실행이 다른 랜덤 폴더라
> **되찾을 방법도 없다.**

### 설치본은 `C:\Program Files` 가 아니다 — 문서 예상 정정
이 앱은 **per-user 설치**(`perMachine:false`)라 `%LOCALAPPDATA%\Programs\AgentParty` 로 간다.
**→ 쓰기는 된다.** 그래서 *"권한이 없어 파티 생성 실패"* 는 설치본에서 잘 안 나고,
**진짜 문제는 업데이트 시 소실**이다. ([F-02](F-02%20자동%20업데이트.md) 와 부딪힌다는 지적은 그대로 유효.)

바로가기 근거: NSIS `CreateShortCut` 은 작업디렉터리 인자가 없고 **`$OUTDIR`** 을 쓴다.
`installSection.nsh:60` 이 `SetOutPath $INSTDIR` → **바로가기 Start in = 설치 폴더.**
등가 실측(exe 를 자기 폴더에서 실행)에서 `workspacePath = ...\win-unpacked` 확인.

### 쓰기 권한 검증 — 없음 (확인)
`WorkspaceContext` 는 경로 검증이 **0** 이다.
**`C:\Windows\System32` 를 작업공간으로 경고 하나 없이 그대로 채택**했다.
캡처: `shots/b15-nonwritable-workspace.png`

### 실측이 좁힌 것
> **portable 은 어떤 기본값을 쓰든 `cwd` 를 쓰면 안 된다.**

ⓐ/ⓑ 선택 이전에 이것부터 확정된다. 그리고 [F-03](F-03%20설치와%20배포%20방식.md) 의
*"nsis vs portable 중 하나로 좁힌다"* 판단에 무게가 실린다 —
**portable 을 내려면 이 문제를 반드시 먼저 풀어야 한다.**

### ⚠️ 실측하지 않은 것
**NSIS 설치 프로그램은 실행하지 않았다.** `customInstall` 이 사용자 PATH 와 탐색기 컨텍스트
메뉴를 건드려서, 측정 목적으로 시스템을 바꾸는 것은 범위를 넘는다고 판단했다.
바로가기 동작은 **NSIS 소스로 확정 + 등가 실측으로 뒷받침**했다.
실제 설치 검증이 필요하면 별도로 할 것.

## 원래 계획 — 실측

**추측하지 말고 패키징된 빌드에서 `process.cwd()` 가 실제로 무엇이 되는지 확인한다.**
실행 경로마다 다를 수 있다:

- NSIS 설치본의 **시작 메뉴 바로가기**
- 바탕화면 바로가기
- **portable 실행 파일** 더블클릭
- 파일 탐색기에서 `.exe` 직접 실행

**이 실측 없이 고치면 안 된다.** 셋 중 하나만 문제일 수도, 전부 문제일 수도 있다.

## ✅ 방향 확정 (2026-08-08 사용자 결정) — **디자인·기획 대기**

> **첫 실행에 작업공간을 고르는 UI 를 만든다.**
> 그리고 **[B-11](B-11%20파티%20찾기.md) 의 "최근 작업공간 목록"과 연동한다.**

### 🔴 이 화면에 셋이 모인다 — 한 번 만들면 된다

| 항목 | 이 화면에서 무엇 |
|---|---|
| **B-15** (이 문서) | 첫 실행에 작업공간을 고른다 |
| **[B-11](B-11%20파티%20찾기.md)** | **최근 작업공간 목록**을 보여준다 (조사·설계 완료 — 폴더 안 `partyId` + 사유 붙은 경로 상태) |
| **[G-1](../아이디어/아이디어.md)** | 그 작업공간에서 하던 **세션을 멤버로 반입**한다 |

**셋 다 "작업공간을 고르는 화면"이 필요하고, 재료(경로 색인)도 같다.**
따로 만들면 세 번 만든다. **디자인·기획은 셋을 같이 놓고 시작할 것.**

### 기본 제안값은 안전한 곳으로
사용자가 그냥 넘겨도 되게, **쓰기 가능하고 업데이트에 안 지워지는 곳**을 기본 제안으로 둔다
(사용자 문서 폴더 아래 등). `process.cwd()` 는 어느 경우에도 쓰지 않는다.

### 반드시 함께 — 쓰기 가능 여부 검증
지금은 조용히 컨텍스트를 만들고 나중에 실패한다. **고를 때 검증하고, 안 되면 말한다.**

### ⚠️ 디자인 전에 확인할 사실 하나
**portable 에서 `userData` 가 어디인가.**
색인(최근 작업공간 목록)은 앱 사용자 영역에 두는데, **portable 의 `userData` 도 임시 폴더면
최근 목록이 매 실행 지워진다** → 데이터는 살아도 **목록이 항상 비어 보인다.**
그러면 이 화면의 값이 절반으로 준다. **측정이 필요하다.**

## 반드시 함께 — 쓰기 가능 여부 검증

어느 쪽을 택하든 **경로가 쓰기 가능한지 확인하고, 아니면 그 사실을 말해야 한다.**
지금은 조용히 컨텍스트를 만들고 나중에 실패한다 — 이 앱의 silent fallback 금지 규칙 위반이다.
