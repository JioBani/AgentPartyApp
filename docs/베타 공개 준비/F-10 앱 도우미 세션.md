# F-10. 앱 도우미 세션 — 한 번에 띄우는 "이 앱에 대해 물어보는 멤버"

> ⚠️ **[F-15](F-15%20가이드%20—%20프레젠테이션과%20챗봇.md) 가 이 문서를 흡수했다.** 설계의 정본은 그쪽이다.
> 이 문서가 열어둔 갈림길은 이렇게 닫혔다 — **범위**는 "읽고 알려주기"(파티 도구 없음),
> **파티에 섞지 않고** 별도 창, **닭과 달걀**은 연결이 없으면 설정창으로 보내는 것으로.
> 여기서 잘라낸 "앱 상태를 읽고 고치는" 몫은 [H-1](../아이디어/아이디어.md) 로 독립했다.

**판정: 차단 유력** · 출처: 사용자

## 무엇을

이 앱 **자체**를 상대로 상호작용하는 세션을 **빠르게 만드는 전용 수단**을 둔다.
기능을 알려주고, 문제를 찾아주고, 사용자를 돕는 멤버 하나를 **버튼 하나로** 띄운다.

## F-09 와의 관계

> **[F-09](F-09%20도움말.md) 가 지식(원본)이고, F-10 이 그 지식으로 가는 입구다.**

- F-09 없이 F-10 만 만들면 → **멤버가 지어낸다.**
- F-10 없이 F-09 만 만들면 → **문서만 있고 아무도 안 읽는다.**

순서는 F-09 → F-10 이지만, **F-10 이 있어야 F-09 가 실제로 쓰인다.**

## 왜 강한가

지금 이 앱에는 **온보딩이 없다.** 처음 켠 사용자가 보는 것은
**"멤버를 클릭하라"는 안내와, 클릭할 멤버가 없는 빈 사이드바**다
([조사-첫 실행 경험](조사-첫%20실행%20경험.md)).

처음 온 사람에게 줄 수 있는 가장 값싼 안내가 **"물어볼 상대를 하나 띄워주는 것"** 이다.
**화면을 새로 설계하지 않고도 온보딩 자리를 메운다.**

## 재료 — 대부분 이미 있다

| 필요한 것 | 있는 것 |
|---|---|
| 멤버 생성·기동 | [F-04](F-04%20멤버%20생성%20빠르게.md) ⓐ "기본값으로 빠르게 만들기"와 **같은 메커니즘** |
| 앱 조작·조회 도구 | `src/core/partyBridge.ts` 의 인프로세스 MCP 표면 |
| 상태·로그·진단 조회 | 자동화 HTTP API |
| 역할 텍스트 주입 | 멤버 역할 스캐폴드 |

→ 새로 만들 것은 **"이 도우미가 무엇을 알고 무엇을 할 수 있는가"의 정의**에 가깝다.

## ⚠️ 함정 — 닭과 달걀

**도우미도 모델이 있어야 돈다.**
그런데 **도우미가 가장 필요한 순간이 바로 인증이 안 되는 순간**이다([B-03](B-03%20인증%20버그.md)).

인증 전에는 도우미가 못 뜬다. 따라서:

> **인증 이전 단계의 안내는 AI 없이도 되는 경로로 반드시 남겨야 한다.**
> (사람이 읽는 도움말 · 빈 화면 안내 · 사전 점검 메시지)

**이 하나를 놓치면 도우미가 있어도 첫 사용자를 못 구한다.**

## 정해야 할 것

### 어디까지 하게 할 것인가
| 범위 | 비용 |
|---|---|
| 알려주기만 | 싸다 |
| + 진단(로그·상태) 읽기 | 중간 — 무엇을 읽게 할지 경계 필요 |
| + 사용자 대신 **조작** | 비싸다 — 권한 설계가 붙는다 |

**1차는 "읽고 알려주기"로 좁히는 것을 권한다.**

### 파티에 섞을 것인가 따로 둘 것인가
작업용 파티에 도우미가 끼면 **방송·게이트에 걸린다.** 별도로 두는 편이 깔끔하다.

### 어느 모델로
상시 대기라면 **싼 모델**이어야 한다. 그리고 사용자가 **어떤 인증을 가졌든** 떠야 하므로
모델 선택을 고정하기 어렵다 — 위 "닭과 달걀"과 같은 문제다.
