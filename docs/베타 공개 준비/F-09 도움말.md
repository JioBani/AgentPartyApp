# F-09. 도움말 — 사람이 읽는 것 + AI 가 안내하는 것

**판정: 차단 유력** · 갈래: *작성자가 안 쓰는 경로가 비어 있다* · 출처: 사용자

## 무엇을

도움말을 갖춘다. **두 종류다** — 사람이 직접 읽는 도움말과,
**AI 멤버가 사용자에게 즉시 안내할 수 있는** 도움말. 특히 후자가 **빠르게** 되어야 한다.

## 왜 이 앱에 맞나

이 앱은 **화면 안에 이미 AI 가 앉아 있다.** 사용자가 막혔을 때 문서를 찾아 나가는 대신
**그 자리에서 멤버에게 물으면 되는** 구조다.

> 다른 앱은 이걸 하려면 챗봇을 새로 붙여야 한다.
> **여기는 붙일 것이 없다 — 이미 있다.** 정체성에 정확히 맞는 보완이다.

## 지금은 — 없다

사용자용 안내가 **한 줄도 없다.**

| 문서 | 실제 독자 |
|---|---|
| `README.md` | **개발자** (`npm install` / `npm run build` 로 시작) |
| `docs/기능정의서.md` | **기획자** (UR 부착점 정의지 사용법이 아니다) |
| `docs/FEEDBACK.md` | **내부** 버그 원장 |

그리고 **멤버는 앱을 모른다.** 파티 도구 사용법은 주입받지만 **화면·기능은 모른다.**
지금 사용자가 멤버에게 *"이거 어떻게 해?"* 라고 물으면 **멤버가 지어낼 것이다.**

## ⚠️ 핵심 설계 — 원본은 하나여야 한다

사람용과 AI 용을 **따로 쓰면 반드시 어긋난다.**
(이 저장소가 이미 겪은 실패다 — *"같은 사실을 두 곳에 적으면 반드시 어긋난다"* 가
문서 규칙으로 남아 있다.)

> **한 벌의 도움말 원본을 두고, 화면과 AI 도구가 그것을 각자 소비한다.**

## 무엇을 담는가

**우선순위가 분명하다 — 조사에서 나온 실패 지점부터 채운다.**

1. **시작하기 전에 필요한 것** — 어느 CLI 를 깔아야 하는지, **WSL 준비물**
   ([조사-첫 실행 경험](조사-첫%20실행%20경험.md): 사전 점검이 없어 첫 턴에서야 실패한다)
2. **인증** — "available" 이 로그인됐다는 뜻이 아니라는 것([B-03](B-03%20인증%20버그.md))
3. **처음 한 번 해보기** — 파티 만들기 → 멤버 만들기 → 첫 메시지
4. **막혔을 때** — 권한이 막혔을 때([B-05](B-05%20권한%20막힘%20침묵.md)), 세션이 안 뜰 때
5. **제보하는 법** — 버전·로그를 어떻게 챙기는지([F-13](F-13%20진단%20접근.md))

**4·5 가 값이 가장 크다.** 나머지는 한 번 읽고 끝이지만, 이 둘은 **실패한 순간에 필요**하다.

## AI 가 어떻게 집어 가는가

⚠️ **상시 컨텍스트에 넣으면 매 턴 비용이다.**
스티커 설계([E-3])가 이미 같은 문제를 풀었다 — **부를 때만 들어오게** 한다.
그 관례를 따르는 것이 자연스럽다(`src/core/partyBridge.ts` 에 도구를 하나 더한다).

## 정해야 할 것

- **사람용 도움말이 어디 있는가** — 앱 안 화면인지 외부 문서인지.
  ⚠️ **인증 이전 단계는 앱 밖에도 있어야 한다**([F-10](F-10%20앱%20도우미%20세션.md) 의 닭과 달걀 참고).
- **언어** — 지금 문서는 한국어이고 UI 는 한국어·영어가 섞여 있다
  ([조사-개인화 하드코딩](조사-개인화%20하드코딩.md)). 배포 대상에 맞춰 정할 것.
