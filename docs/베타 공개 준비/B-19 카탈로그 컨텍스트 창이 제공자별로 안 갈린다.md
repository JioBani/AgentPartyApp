# B-19. 카탈로그의 컨텍스트 창이 제공자별로 갈리지 않는다

**소유자: 미정** · 판정: 미정 (작음) · 출처: [B-07](B-07%20Cursor%20컨텍스트%20계산.md) 작업 중 발견 (2026-08-08)

## 사실

`src/shared/modelCatalog.json` 의 Grok 4.5 엔트리가 `context: "500K"` 다.

- **xAI 네이티브 Grok 4.5 = 500k** — 맞다 (docs.x.ai)
- **Cursor 의 Grok 4.5 = 256k** — Cursor 직원이 *"expected behavior, not a bug"* 로 확인
  (forum.cursor.com/t/why-does-grok-4-5-in-cursor-only-have-a-256k-context-window/166519).
  **별개 모델**이다.

**두 경로가 같은 `context` 문자열을 공유하는 구조**라, OpenRouter 경유는 맞고 Cursor 경유는 틀리다.

## 지금은 영향이 없다

[B-07](B-07%20Cursor%20컨텍스트%20계산.md) 수정으로 **Cursor 하네스는 컨텍스트 창을 아예 보고하지 않게** 됐다.
분자(점유량)를 못 구하므로 비율을 만들지 않고, 따라서 이 값이 쓰이지 않는다.

**→ 그래서 B-07 에서 고치지 않았다.** 판단은 맞다.

## 왜 남겨 두는가

**구조가 남아 있다.** 한 엔트리가 여러 제공자를 커버하는데 **제공자마다 창이 다를 수 있다**는 사실이
카탈로그 스키마에 반영돼 있지 않다. 지금은 Cursor 만 해당하지만:

- 다른 곳에서 이 값을 쓰기 시작하면 **조용히 틀린다**
- Cursor 가 나중에 점유량을 보내기 시작하면(ACP `usage_update`) **분모가 바로 필요해지고 그때 틀린다**
- 같은 모양의 드리프트가 다른 모델에도 있을 수 있다 — **확인 안 됨**

## 정해야 할 것

1. **스키마를 갈릴 것인가** — 엔트리에 제공자별 `context` 오버라이드를 두는가,
   아니면 제공자별로 엔트리를 나누는가
2. **지금 고칠 것인가, 필요해질 때 고칠 것인가** — 현재 영향 0 이므로 미루는 것도 방어 가능하다
3. **같은 드리프트가 다른 모델에 더 있는지 전수 확인**할 것인가
