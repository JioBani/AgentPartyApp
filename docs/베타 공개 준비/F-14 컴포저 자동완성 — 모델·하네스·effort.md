# F-14. 컴포저 자동완성 — 모델·하네스·effort

**판정: 기획 확정** · 갈래: *작성자가 손으로 외워서 치는 걸 남들은 못 친다* · 출처: 사용자 (2026-08-12)

> **현재 동작 정정 (2026-09-03)**: 멤버는 이름을 입력하면 접두어 없이 자동완성하고,
> 모델·프로바이더·하네스는 `!`로 시작할 때만 자동완성한다. 모델을 선택한 뒤
> effort·thinking·service tier가 이어지는 체인은 그대로 유지한다. 아래 `:a`·`:m`
> 설명은 최초 설계 기록이며 현재 입력 문법이 아니다.

## 무엇을

채팅 입력창에 **`a:` 를 치면 모델 목록이 뜨고**, 고르면 effort·thinking·fast 가
**이어서 뜬다.** 고른 값은 칩으로 굳고, 보낼 때 **정확한 문자열로 텍스트에 들어간다.**

멤버 멘션은 같은 모양의 **`m:`** 으로 옮긴다.

## 왜

이 앱에서는 **모델 이름을 메시지 본문에 자주 쓴다.**

> "`gpt-5.4-mini` 로 멤버 하나 만들어줘"
> "이거 `claude-opus-4-8` · effort high 로 다시 돌려봐"

지금은 그 문자열을 **외워서 손으로 친다.** 이름이 길고(`claude-haiku-4-5-20251001`),
비슷하고(`4-5` / `4-6` / `4-8`), 틀리면 AI 가 엉뚱한 모델을 고르거나 되묻는다.

작성자는 외우고 있어서 불편을 못 느낀다. **새 사용자는 카탈로그를 열어 눈으로 확인하고 옮겨 적는다.**

## ⚠️ 이것은 설정 변경이 아니다

> **아무 동작도 하지 않는다.** 모델을 바꾸지 않고, 하네스에 명령을 보내지 않는다.
> **정확한 문자열을 입력창에 넣어주는 것이 전부다.**

모델을 실제로 **바꾸는** 길은 헤더의 모델 필(`Panel.tsx:150-180`)이고 그건 그대로 둔다.
둘을 섞으면 "칩을 넣었는데 왜 모델이 안 바뀌지" / "텍스트만 쓰고 싶었는데 왜 바뀌지" 가 동시에 생긴다.

## 트리거

> ⚠️ **정정 (2026-08-12, 사용자 지시)**: 콜론이 **앞**이다. ~~`a:`~~ → **`:a`**
> 콜론이 앞이면 `C:\` · `http://` · `10:30` 과 겹칠 여지가 **구조적으로 사라진다**
> (그 콜론들은 앞에 글자가 붙어 있어 "단어 시작" 조건에서 탈락한다).

| 트리거 | 뜬다 |
|---|---|
| `:a` · `:agent` | 모델 (→ effort → thinking → fast 로 이어짐) · 하네스 |
| `:m` · `:member` | 멤버 |
| `@` | **없앤다** |
| `/` | 커맨드 팔레트 — **그대로 둔다** |

**짧은 형과 긴 형이 같은 목록을 연다.** 첫 글자가 같아서 외우기 쉽고, 긴 형은 그 자체가 설명이다.

### 왜 기호가 아니라 접두어인가

`@` 와 `/` 는 **하네스마다 뜻이 다르다** — Codex 는 `@` 가 스킬·플러그인·파일, Claude 는 파일 멘션이다.
우리가 그 기호를 점유하면 **하네스가 나중에 무엇을 가져가든 부딪힌다.**
접두어+콜론은 그 충돌에서 완전히 벗어나 있고, **무엇을 부르는지 글자로 적혀 있다.**

### 감지 규칙

`:a` 든 `:m` 이든 **콜론이 단어 시작이어야 한다.**

```
/(^|[\s(\[{"']):(agent|member|a|m)([^\s]*)$/i
```

긴 철자를 먼저 두는 게 중요하다 — 그래야 `:agent` 가 `a` + `"gent"` 가 아니라
`agent` + 빈 질의로 읽힌다.

**실측 검증** (구현 시 정규식 단독 확인):

| 입력 | 결과 |
|---|---|
| `:a` · `:ahai` · `:m` · `:malice` · `:agent` · `:member` | 걸림 |
| `hi :a` · `(:m` · `이거 :a` | 걸림 (단어 시작) |
| `C:\Users` · `http://x` · `10:30` · `x:a` · `foo:m` · `:x` | **안 걸림** |

### 한글 입력기가 켜져 있어도 걸린다 (2026-08-12 사용자 요청)

트리거는 영문인데 **입력기는 대개 한글로 켜져 있다.** 그 상태로 `:a` 를 치면 `:ㅁ` 이 되고
아무것도 안 뜬다. **사용자 눈에는 오타가 아니다** — 누른 키는 맞았고 앱이 거부한 것뿐이다.

그래서 **한글을 두벌식 키로 되돌려서** 판정한다(`hangulKeys.ts`).

| 친 것 | 실제 키 | 결과 |
|---|---|---|
| `:ㅁ` | `:a` | 모델 체인 |
| `:ㅡ` | `:m` | 멤버 |
| `:ㅁ치` | `:acl` | Claude · Claude Code · Cursor CLI 로 좁혀짐 |
| `:ㅠ` | `:b` | 트리거 아님 → 안 뜸 |

**로마자 표기가 아니다** — `ㅁ`→`a` 는 소리가 아니라 **같은 키**라서다.
질의는 **친 그대로와 변환본 둘 다** 시도하고 친 그대로가 우선이다. 그래야 이름이 한국어인
멤버(`지오`)를 `wldh` 로 찾는 사고가 안 난다.

### ⚠️ `@` 를 없애면 발견 경로가 사라진다

`@` 는 아무도 안 가르쳐줘도 쳐 보는 기호다. **`a:` 는 아니다.**
없애는 이상 **입력창이 스스로 알려줘야 한다** — placeholder 힌트든 첫 실행 안내든.
이건 선택이 아니라 **`@` 제거에 딸린 필수 조건**이다.

## `:a` 의 단계

> **정정 (2026-08-12, 사용자)**: **프로바이더가 맨 앞에 붙는다.** 66개를 한 목록에 놓으면
> 훑는 일이고, 프로바이더로 한 번 자르면 고르는 일이 된다.
> 프로바이더 행에는 **앱이 이미 쓰는 브랜드 마크**(`HarnessIcon`)를 붙인다 — 새 아이콘 셋이
> 아니라 위저드·사이드바가 쓰는 그 마크다.

```
:a
┌────────────────────────────┐
│ 프로바이더                  │  ← 1단계: 프로바이더 + 하네스
│ ◆ Codex          6         │     (아이콘 · 라우트 개수)
│ ✳ Claude         5         │
│ • OpenRouter    42         │
│ ─── 하네스 ──────────────── │
│ ✳ Claude Code              │  ← 고르면 체인 없이 끝
└────────────────────────────┘
   ↓ Claude 선택
┌────────────────────────────┐
│ 모델  ha                    │  ← 2단계: 그 프로바이더의 모델만
│ Haiku                      │     팝오버 안에서 타이핑 = 필터
└────────────────────────────┘
   ↓
│ Low · Medium · High        │  ← 3단계: effort
│ Adaptive · On · Off        │  ← 4단계: thinking
│ Standard · Fast            │  ← 5단계: serviceTier (Cursor)
```

**프로바이더도 칩으로 남는다** (2026-08-12 사용자 결정) — 결과는
`anthropic claude-haiku-4-5-20251001 effort=high` 처럼 프로바이더가 앞에 붙는다.

### 2단계부터는 팝오버 안에서 타이핑한다

1단계는 `:aclau` 처럼 **초안의 트리거 텍스트**가 필터다. 그런데 프로바이더를 고르는 순간
그 텍스트는 칩으로 바뀌어 사라진다 — **모델 단계에는 타이핑할 자리가 없다.**

그래서 모델 단계의 타이핑은 **메시지에 닿지 않고 팝오버의 필터로 들어가고, 그 질의를 제목 옆에
그려 준다**(`모델 ha`). 안 그리면 목록이 저 혼자 줄어드는 것처럼 보인다.
effort·thinking 처럼 **짧은 목록에서는 타이핑이 체인을 닫는다** — 그때의 타이핑은 문장을
계속 쓰겠다는 뜻이기 때문이다.

**단계 구성은 고른 모델이 정한다.** `route.capabilities` 에 없는 단계는 **뜨지 않는다**
(`capabilitiesFromCatalog()`, `modelRegistry.ts:796`).

- `grok` — effort·thinking 전부 미지원 → **모델만 고르고 끝**
- Cursor 모델 — `serviceTier` 가 있어 **fast 단계가 더 붙는다**
- `budget` 은 넣지 않는다 — 숫자 슬라이더는 목록으로 고를 값이 아니다

**없는 걸 보여주지 않으므로** "왜 이건 안 뜨지"가 생기지 않는다.

### 1단계에는 하네스도, 검색하면 모델도 같이 뜬다

프로바이더 섹션 아래에 **하네스 섹션**이 함께 뜬다(사용자 결정 2026-08-12).
둘 다 "모델보다 먼저 이름을 대는 것"이라 같은 화면이 맞고, `claude-code` 같은 하네스 id 야말로
이 기능이 없애려는 오타 대상이다. 하네스를 고르면 **체인 없이 즉시 끝난다** — effort 가 없다.

**모델 섹션은 무언가를 친 뒤에만 붙는다**(사용자 결정 2026-08-12).

프로바이더를 앞에 세우자 **이름을 아는 사람이 오히려 손해**를 봤다 — 전에는 `:ahai` 로 Haiku 가
바로 나왔는데 단계가 하나 늘었다. 그래서 1단계에서도 모델을 찾을 수 있게 하되,
**빈 질의에는 안 뜬다.** 66개를 처음부터 쏟으면 프로바이더를 앞에 둔 이유가 없어지기 때문이다.

- `:a` → 프로바이더 6 + 하네스 4 (짧다)
- `:ahaiku` → **모델 섹션에서 Haiku 를 바로** 고른다 → 프로바이더 칩 없이 모델부터 시작

질의가 한 섹션만 남기면 **제목이 그 섹션 이름을 쓴다** — 모델 목록 위에 "프로바이더"라고
적혀 있으면 그건 거짓말이다.

## 키 배분

| 키 | 동작 |
|---|---|
| **Enter · Tab** | 지금 항목 확정 → **다음 단계로** |
| **→** | 지금 항목 확정 → **거기서 끝** |
| **Space** | 고르지 않고 끝 + 공백 입력 |
| **Esc** | 고르지 않고 끝 |
| **Backspace** | 직전 단계로 되돌아감 |
| **↑ ↓** | 이동 |

### 왜 Space 가 "확정"이 아닌가

자동완성에서 **Space 는 거의 어디서나 닫기**다 — VS Code IntelliSense, GitHub·Slack·Notion 멘션,
그리고 지금 우리 컴포저(`Composer.tsx:269-294`)까지. 사용자가 **문장을 계속 쓰려고 누르는 키**라
여기에 확정을 걸면 원치 않는 값이 들어간다.

**그런데 이 체인에서는 관례와 의도가 어긋나지 않는다.** 2단계에 도달했다는 건 모델이 이미
칩으로 확정됐다는 뜻이라, effort 단계에서 Space 로 **닫으면 결과가 "모델만 붙고 끝"** 이다.
곧 **"거기서 끝"** 이다.

→ **새로 외울 키는 `→` 하나뿐이다.**

## 보이는 것과 나가는 것을 분리한다

**트리거는 부르는 방법일 뿐이다.** 칩과 전송 문자열은 트리거와 무관하다.

| | 화면의 칩 | 보낼 때 |
|---|---|---|
| 멤버 | `@alice` | `@alice` |
| 모델 | `Haiku 4.5` | `claude-haiku-4-5-20251001` |
| 하네스 | `Claude Code` | `claude-code` |
| effort | `High` | `effort=high` |
| thinking | `On` | `thinking=on` |

> 멤버 칩은 **지금과 똑같이 `@alice` 로 보이고 `@alice` 로 나간다.** 부르는 방법만 `m:` 으로 바뀐다.
> 그래서 **보낸 메시지의 형식도, 받는 쪽 해석도 바뀌지 않는다**(`tokenizeMessage()` 그대로).

**라벨을 그대로 보내면 안 되는 이유** — AI 가 라벨에서 id 를 다시 추측해야 하고,
짧은 별칭은 가리키는 대상이 바뀐다(`opus` 가 어느 모델인지는 시점에 따라 다르다).
**칩이 이걸 공짜로 해준다** — 표시 텍스트와 `data-*` 속성값이 이미 별개다
(`composerDraft.ts:86-100`).

**모델 칩에는 `@` 를 붙이지 않는다.** `serializeDraft()` 는 지금 무조건 `@` 를 앞에
붙이는데(`composerDraft.ts:127`), `@claude-haiku-4-5-20251001` 은 텍스트로 이상하다.
**종류에 따라 접두를 붙일지 나뉜다** — 이게 유일한 직렬화 변경점이다.

체인 결과는 공백으로 이어진다:
```
claude-haiku-4-5-20251001 effort=high thinking=on
```

**대화 기록에서 모델은 되살리지 않는다.** `@` 없는 평범한 문자열이라 **그냥 텍스트로 남는다.**
그게 맞다 — 보낸 뒤에는 진짜 그냥 텍스트다.

## 결정 — 전부 확정됨 (2026-08-12, 사용자)

| | 질문 | 결정 |
|---|---|---|
| 1 | 검색 대상 | **화면에 보이는 글자로만.** 숨은 id 는 안 훑는다. 행에 제공자가 그려지면 그건 검색된다 — **"보이는 것 = 찾을 수 있는 것"** 한 규칙으로 둔다 |
| 2 | 퍼지 매칭 | **쓴다** (부분수열). [F-05](F-05%20스킬%20커맨드%20팔레트.md) 결정 4와 **같은 구현을 공유한다**(`fuzzyMatch.ts`) |
| 3 | 쓸 수 없는 모델 | **숨긴다.** 텍스트 삽입이라 못 쓰는 모델을 지시하게 되고, 실패가 여기서 멀리 떨어진 곳에서 드러난다 |
| 4 | `@` 를 없앤 자리의 발견 경로 | **별도 안내 없음.** 팝오버가 스스로 알린다 — 제목("모델"·"멤버"·"Thinking")과 키 힌트가 뜨는 순간이 유일하게 사용자가 보고 있는 순간이다. 기존 툴바 `@` 버튼은 `:m` 을 넣도록 이어받았다 |

**검색 대상이 "보이는 글자"라서** `:a` 는 제공자로도 찾힌다 — 행이 `Haiku · Anthropic` 을
그리기 때문이다. 안 그리는 값(내부 id)으로는 못 찾는다. 규칙과 화면이 어긋나지 않는다.

## 설계에서 지킨 것

- **멤버 칩·전송 문자열 불변.** `@alice` 로 보이고 `@alice` 로 나간다. `tokenizeMessage()` 무변경
- **모델 칩은 접두 없음.** 값은 `title` 툴팁에 그대로 보인다(보내기 전 확인 가능)
- **단계는 데이터가 정한다.** 선택지가 1개뿐인 능력은 **건너뛴다** — 고를 게 없는 목록을 닫게 하지 않는다
- **체인 중 글자를 치면 체인이 끝난다.** 안 그러면 문장을 쓰는 중의 Enter 가 `effort=` 를 몰래 넣는다
- **Backspace 는 단계를 되돌리며 그 단계가 쓴 칩을 지운다.** 안 지우면 다시 고를 때 `effort=` 가 두 개 남는다

## 검증 — 실앱 수동 e2e (새 테스트 코드 없음)

실제 앱을 격리 userData·워크스페이스로 띄우고 CDP 로 **진짜 키 이벤트**를 넣어 확인.
드라이버는 스크래치패드의 일회용이고 저장소에 넣지 않았다. 캡처 7장.

```
✓ :a → 1단계 "프로바이더" + 하네스 섹션, 브랜드 아이콘 8개 렌더
✓ :aclau → ["Claude","Claude Code"] 로 좁혀짐
✓ Enter 확정 → 트리거 텍스트가 칩으로 교체됨(":a" 잔여 없음) → 모델 단계로
✓ 모델 단계가 그 프로바이더 모델만 5행
✓ 모델 단계에서 타이핑 → 메시지에 안 닿고 제목에 "모델 ha" 로 표시, 목록 ["Haiku"]
✓ 체인 결과 "anthropic haiku thinking=enabled" — 모델 토큰에 '@' 없음
✓ :m → ["@everyone","@alice"], 확정 시 @name 으로 직렬화
✓ 트리거 16가지 전부: ;a · a: · a; · :A · A: · AGENT: · agent; · ;m · m: · m; · M: · member; · ;ㅁ · ㅁ: · ㅡ; · ㅁ:치
✓ :ahaiku → 1단계에서 모델 직행, 제목이 "모델", 고르면 프로바이더 칩 없이 haiku
✓ :a (빈 질의) → 모델 섹션 안 붙음 (프로바이더 6 + 하네스 4 만)
✓ 오작동 안 함: C:\Users · http://x.com · 10:30 · 8080:8080 · wsl+Ubuntu-22.04:/home · b: · x:a · foo:m
✓ :ㅁ → 모델 체인 · :ㅡ → 멤버 (입력기 켜진 상태)
✓ :ㅁ치 → Claude · Claude Code · Cursor CLI 로 좁혀짐 (전체 목록 반환 아님)
✓ :ㅠ (= :b) → 트리거 아님, 안 뜸
✓ C:\Users · http://x.com · 10:30 — 팝오버 안 뜸
✓ / 커맨드 팔레트 그대로 열림
```

### 한글 지원이 드러낸 결함 하나 (고침)

첫 구현에서 `:ㅁ챌` 이 **프로바이더 전체**를 돌려줬다. 매처가 영숫자만 남기고 정규화하는데
한글이 전부 탈락해 **빈 질의 = 필터 없음**으로 읽힌 것이다. 같은 이유로 **이름이 한국어인 멤버는
아예 검색되지 않았다.**

두 곳을 고쳤다 — 정규화가 **한글을 남기고**, 글자가 있었는데 정규화 후 비면
"전부 일치"가 아니라 **"일치 없음"**을 돌려준다. 조용히 필터가 풀리는 쪽이 더 나쁘다.

`npm run typecheck` 통과(변경 전 기준선도 통과 확인 — 깨진 툴체인의 "통과"가 아님).

## ⚠️ 범위 밖 발견 — 카탈로그의 별칭 id (새 항목 후보)

체인 결과가 `claude-haiku-4-5-20251001` 이 아니라 **`haiku`** 로 나온다.
F-14 버그가 아니다 — **카탈로그 엔트리 자체가 별칭**이다.

```
src/shared/modelCatalog.json — 41개 중 2개가 버전 없는 별칭 id
  { id: "sonnet", label: "Sonnet 4.6", provider: "anthropic" }
  { id: "haiku",  label: "Haiku",      provider: "anthropic" }
```

**이건 이 문서가 존재하는 이유를 정면으로 깎는다** — "짧은 별칭은 가리키는 대상이 바뀐다"고
적어 두고, 그 두 모델에 대해서는 정확히 별칭을 삽입하게 된다.
[claude-cli-alias-drift] 계열의 알려진 문제이고 **카탈로그 소유자 몫**이다. F-14 는 라우트의
정본 id 를 그대로 쓰므로, 카탈로그가 고쳐지면 자동으로 따라간다.

## 남은 것

- `thinking=enabled` — 기획 예시는 `thinking=on` 이었으나 **능력 데이터의 옵션 id 가 `enabled`** 다.
  라벨(`On`)이 아니라 id 를 보내는 게 이 문서의 규칙이라 데이터를 따랐다. 문자열을 바꾸려면
  카탈로그의 옵션 id 를 바꿔야 한다
