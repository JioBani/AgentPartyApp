# F-11. Claude·Codex 대비 누락된 사용성

**판정: 조사 완료 → 채택 항목만 차단 판정** · 출처: 사용자

## 무엇을

Claude Code·Codex 가 제공하는 사용성 중 **이 앱에 빠진 것**을 조사하고,
**꼭 필요한 것만** 붙인다.

## ⚠️ "꼭 필요하면" 이 이 항목의 핵심이다

이건 **기능을 베끼는 작업이 아니다.**

> 두 도구는 **세션 하나**를 잘 쓰게 만든 도구이고, 이 앱은 **여러 멤버가 함께 도는** 도구다.
> 전제가 다르므로 **그쪽에 있다는 이유만으로 가져오면 정체성이 흐려진다.**

판단 기준 하나: **"없어서 사용자가 막히는가"** (불편한가가 아니라 **막히는가**).

## 조사 결과 — 채택할 것 셋

기존 격차 문서([claude-code-ux-research/05](../claude-code-ux-research/05-agentparty-gap-backlog.md),
[codex-ux-research/05](../codex-ux-research/05-agentparty-codex-harness-backlog.md))를
현재 코드와 대조한 결과. **조사가 BLOCKS 로 분류한 것 중 실제로 채택할 것만 남긴다.**

### ✅ 채택 ① Codex 명령이 9개로 하드코딩돼 있다
`src/core/codexAdapter.ts:92-102` — **하드코딩된 9개 명령만** 노출.
`skills/list`·`plugins/list` 등 **실제 조회를 하지 않는다.**

→ Codex 멤버는 `/goal`·`/memory`·`/review`·`/plan`·`/agent` 등
**대부분의 Codex 기능에 도달할 수 없다.** 이건 불편이 아니라 **차단**이다.

⚠️ 기능정의서 1-8-1 은 *"하네스가 실제 보고한 항목 반영"* 이라고 적었는데
**Codex 는 그렇지 않다** — 또 하나의 문서·코드 어긋남.

→ **[F-05](F-05%20스킬%20커맨드%20팔레트.md) 에 포함해 처리한다.** 별도 항목으로 세지 말 것.

### ❌ 채택 ② — **철회. 조사가 틀렸다** (2026-08-08 실측)
~~`webSearch` · `imageGeneration` · `subAgentActivity` 가 처리되지 않는다~~

**실측 결과 셋 다 이미 그려진다.** 상세: [B-16](B-16%20Codex%20트랜스크립트%20미표시.md)

조사는 `transcriptEvents.ts` 와 `Transcript.tsx` **두 파일만** 보고 *"이름이 없으니 처리 안 함"*
으로 결론냈다. 그런데 **`codexAdapter` 가 범용 `tool_call` 로 변환해서 올린다**
(`codexAdapter.ts:1353-1372`). `subAgentActivity` 는 애초에 Codex 가 보내지 않고
실제 채널은 `collabAgentToolCall` 이다.

> ⚠️ **이 조사 전체의 신뢰도에 대한 경고다.** 같은 방식(양 끝 파일만 읽고 변환 계층을 건너뜀)으로
> 나온 다른 판정도 같은 오류일 수 있다.
> **아래 나머지 항목도 착수 전에 실측으로 확인할 것.** 특히 "MISSING" 판정들.

### ❌ 채택 ③ — **철회. 이것도 틀렸다** (2026-08-08 실측)
~~Guardian 토글·결과 표시가 없다~~

**Guardian 토글은 있다.** `CodexPermissionControl.tsx:102-107` 에 실제 스위치가 있고,
`codexAdapter` 의 `approvalsReviewer: guardian ? "auto_review" : "user"` 까지 연결돼 있다.

## 🔴 이 조사는 폐기한다 — 채택 3건이 **전부 오탐이었다**

| 채택 항목 | 실측 결과 | 못 본 것 |
|---|---|---|
| ① Codex 명령 9개 하드코딩 | ❌ **오탐** — `refreshInventory()` 가 실제 조회·병합. 팔레트에 **60행** | 병합 함수 (`codexAdapter.ts:858-866`) |
| ② Codex 트랜스크립트 미표시 | ❌ **오탐** — 이미 그려진다 ([B-16](B-16%20Codex%20트랜스크립트%20미표시.md)) | 어댑터 변환 (`:1353-1372`) |
| ③ Guardian 토글 없음 | ❌ **오탐** — 있다 | `CodexPermissionControl.tsx:102-107` |

**3/3.** 실패 모드가 셋 다 똑같다 — **찾는 이름이 있는 파일만 보고, 그 아래·옆의 중간 계층을
안 봤다.** 상수 배열을 보고 그 밑의 병합을 안 보고, 렌더러를 보고 어댑터 변환을 안 보고,
`Transcript` 를 보고 `CodexPermissionControl` 을 안 봤다.

**공통 실패 모드**: 조사가 **양 끝 파일만 읽고 중간 계층을 건너뛰었다.**
- ② 는 `codexAdapter` 의 변환(`tool_call` 로 바꿔 올림)을 못 봤다
- ③ 은 `CodexPermissionControl` 을 안 봤다

> **"파일에서 이름을 못 찾았다"를 "기능이 없다"로 읽으면 안 된다.**
> 이 조사는 그 오류를 **세 번 중 두 번** 저질렀다.

### ⚠️ 채택하지 않았던 항목들도 믿지 마라
아래 "베타 범위 밖" 표의 `MISSING` 판정들은 **같은 방식으로 나왔다.**
그중에 **실제로는 있는 기능**이 섞여 있을 것으로 봐야 한다.
백로그로 보낼 때 *"없다"* 가 아니라 **"없다고 조사됐으나 미검증"** 으로 적을 것.

### 이 조사에서 남길 것 — 결과가 아니라 방법론이다

> **이 저장소에서 "파일에서 이름을 못 찾았다"는 "기능이 없다"가 아니다.**
> 변환 계층·병합·capability 분배가 많은 구조라 **양 끝만 보면 반드시 틀린다.**

- 격차 판정은 **실측이 붙기 전까지 가설로만** 취급한다.
- 실측 비용은 생각보다 낮았다 — 실앱 띄우고 DOM 한 번 재면 끝나는 것들이었다.
  **3건 전부 몇 분짜리 확인으로 뒤집혔다.**
- 반대 방향 교훈도 같이 기억할 것: [B-05](B-05%20권한%20막힘%20침묵.md) 는 **코드 읽기가
  없는 결함을 못 찾은** 사례다. 코드 읽기는 **양쪽으로 다 틀린다.**

## ❌ 채택하지 않는 것 — 베타 범위 밖

조사가 BLOCKS 로 분류했지만 **판단 기준을 엄격히 적용하면 새 기능이다.**
[아이디어 백로그](../아이디어/아이디어.md)로 보낸다.

| 항목 | 왜 지금 아닌가 |
|---|---|
| Peek 드로어 (사이드바 호버로 최근 출력 훑기) | **새 기능.** 다만 "여러 멤버를 훑는다"는 이 앱의 정체성에 맞아 **백로그 상위**로 |
| Agent view / dispatch (프롬프트 → 멤버 자동 생성) | **새 기능.** [F-04](F-04%20멤버%20생성%20빠르게.md) 와 같은 방향이나 훨씬 크다 |
| Diff 패널 선택 수락/거부 (hunk 단위) | **새 기능.** 범위가 크고 정체성과 직접 관련 없다 |
| 트랜스크립트 보기 모드 (Normal/Verbose/Summary) | 불편 수준. 단 [F-08](F-08%20세션%20기록%20방침.md) "무엇을 남길지"와 겹치므로 **거기서 같이 볼 것** |
| 턴 중 steer (Enter 로 즉시 주입) | 대기열이 이미 그 자리를 다르게 풀었다 |
| 스레드 fork/archive/rename | **해당 없음** — 멤버 수명주기가 이 역할을 한다 |
