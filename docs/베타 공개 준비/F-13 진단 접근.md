# F-13. 진단 접근 — 버전 표시 + 로그 폴더 열기

**판정: 차단** · 출처: [조사-베타 운영과 진단](조사-베타%20운영과%20진단.md)

## 무엇이 문제인가

베타 사용자가 문제를 겪었을 때, **작성자에게 건넬 것이 하나도 없다.**

### ① 자기 버전을 말할 수 없다
버전은 `package.json:4` 의 `0.1.0` 뿐이고 **화면 어디에도 안 나온다.**
설정의 자동화 API 화면(`src/renderer/app/secondaryViews.tsx:976`)은 로그 경로는 보여주면서
버전은 안 보여준다.

→ 제보를 받아도 **어느 빌드인지 모른다.** 베타는 계속 고치므로, 버전을 모르면
**이미 고친 것을 다시 조사하게 된다.**

### ② 로그에 손이 닿지 않는다
로그는 NDJSON 으로 남는다(`src/main/logger.ts:28-38`). 경로는 설정 화면에 **글자로만** 있다.
- **`로그 폴더 열기` 버튼 없음** — main 에서 `shell.openPath()` 한 줄이면 된다
- **`경로 복사` 버튼 없음** — **같은 화면에 클립보드 복사가 이미 있는데** 로그엔 안 붙어 있다

→ 기술적이지 않은 사용자는 로그를 건넬 방법이 없다. 스크린샷 한 장만 오고 끝난다.

### ③ 제보하는 법을 아무도 안 알려준다
앱 안에 `문제 신고` 링크·버튼이 없다. 사용자는 **어디에 무엇을 보내야 하는지 모른다.**

## 왜 하나로 묶는가

**셋은 따로 있으면 의미가 없다.** 버전만 보여도 로그를 못 주고, 로그만 줘도 버전을 모르고,
둘 다 있어도 어디로 보낼지 모르면 안 온다.

> **"버전 표시 + 로그 폴더 열기 + 제보 안내 한 줄"** 이 한 벌이다.

각각은 몇 줄짜리 작업이다. **이 문서 전체에서 비용 대비 효과가 가장 높은 항목일 가능성이 높다** —
이게 없으면 **다른 모든 항목의 버그 제보 품질이 같이 떨어지기** 때문이다.

## 무엇을 만들 것인가

한 자리에 모은다(설정 화면 안이 자연스럽다):

- **버전** — 표시 + 복사. 빌드를 구분할 수 있어야 하므로 `0.1.0` 만으로 부족하면
  빌드 식별자를 함께.
- **로그** — `폴더 열기` · `경로 복사`
- **제보 안내** — 어디로, 무엇을 첨부해서. **한 줄이면 된다.**
- (선택) **진단 복사** — 버전·OS·WSL 여부·연결된 인증·하네스 설치 상태를 한 번에 클립보드로.
  사용자가 붙여넣기만 하면 되는 형태. **이게 있으면 제보 품질이 크게 오른다.**

## ⚠️ 텔레메트리는 넣지 않는다

검색 결과 분석·추적 코드는 **0건**이다. 그대로 두기를 권한다 —
베타 사용자가 소수라면 직접 소통이 낫고, 넣는 순간 동의·수집 범위 설계가 따라붙는다.

## 규칙

AGENTS.md 대로 **UI 와 자동화 HTTP API 가 같은 `AppController` 경로**를 타야 하고,
`apiSpec.ts` + `API.md` 등록이 필요하다.
(로그 경로 조회는 이미 `/api/logs` 로 있다 — **새로 만들 것은 화면 쪽**이다.)
