# B-22. 가로 오버플로 — 계열 전수 훑기

**판정: 첫인상 (계열 점검)** · **소유자: 미정** · 출처: [B-20](B-20%20탭이%20많으면%20스크롤이%20안%20된다.md) 완료 시 인계 (2026-08-09)

## 왜 별도 항목인가

오버플로가 **같은 자리에서 네 번 뚫렸다.**

| | 축 | 자리 | 상태 |
|---|---|---|---|
| `[#11]` | 세로 | 파티·멤버 목록 | FIXED |
| `[#18]` | 가로 | 드롭다운이 창 밖으로 | FIXED |
| [D-04](D-04%20우클릭%20메뉴%20검은%20선.md) | (색) | 팝오버 계열 — **훑어서 9곳 발견** | 완료 |
| [B-20](B-20%20탭이%20많으면%20스크롤이%20안%20된다.md) | 가로 | 탭 스트립 | 완료 |

DESIGN 원칙에 *"긴 카탈로그·좁은 창에서도 오버플로 안전"* 이 있는데도 **네 번 뚫렸다.**
매번 **터진 자리 하나만** 고쳤기 때문이다.

> **D-04 가 팝오버 계열을 훑었을 때 9곳이 한꺼번에 나왔다.**
> 개별 대응이 아니라 **계열 훑기가 실제로 값이 있다는 증거**다.

B-20 문서도 *"탭 스트립만 고치지 말고 같은 축의 다른 자리도 함께 훑을 것"* 을 요구했는데
**미이행 상태로 남았다**(구현자가 명시적으로 인계).

## 훑을 자리

B-20 인계 시 지목된 것:
- **툴바**
- **상태 줄**
- **칩 나열** (배지·태그가 여러 개 붙는 자리)

추가로 볼 만한 곳:
- 패널 헤더 (모델명·effort·컨텍스트 도넛·상태 필이 한 줄에 있다)
- 사이드바 행 (멤버 이름 + 하네스 아이콘 + 배지들)
- 승인 카드의 명령 원문 (긴 명령)
- 모델 카탈로그 행 (이름 + 제공자 + 성능·비용·컨텍스트 + 배지)
- 대화창의 도구 카드 헤더

## 방법

**한 자리씩 고치지 말고 한 번에 훑는다.** D-04 가 그렇게 해서 9곳을 찾았다.

- **CDP 실측**으로 단언한다. 캡처 육안은 이 저장소에서 무음 통과 이력이 있다
- 창 최소폭(1100px) · 패널 3~5분할 · 사이드바 접힘 등 **좁은 조합**에서 잰다
- 긴 값(긴 멤버 이름 · 긴 모델명 · 긴 명령)을 넣어 본다

## ⚠️ B-20 에서 나온 교훈 — 폭 추정을 하지 마라

B-20 구현자가 탭 폭을 추정해 합산했다가 **되돌렸다.** 실측 오차가 탭당 5~12px 였고,
칩 옆에 **빈칸 102px** 이 남았다. 사용자가 바로 알아봤다 —
*"멤버가 탭에 가득차서 추가된 게 아니고, 그냥 비어있는데 +6으로 되어있잖아."*

**정확하게 고쳐도 해결되지 않는다.** "다음 항목이 안 들어가는 만큼"의 빈칸은 원리상 남고,
사람 눈에는 *자리가 남는데 왜 숨기지* 로 읽힌다.

→ **CSS 에 맡겨라.** B-20 은 추정기를 지우고 `flex: 1 1 0; min-width: 0` 패킹으로 바꿔
**줄이 항상 꽉 차게** 만들었다. 코드도 68줄 줄었다. 같은 접근을 다른 자리에도 쓴다.
