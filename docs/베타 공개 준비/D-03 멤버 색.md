# D-03. 멤버별 색 분리 방식 재고

**판정: 여유 — 단 D-01 보다 먼저 정해야 한다** · 출처: 사용자

## 무엇을

지금 멤버마다 색을 나눠 쓰고 있는데, 이 방식을 손볼 필요가 있는지 판단한다.

## 왜 지금 보는가

**색은 멤버가 몇 명이냐에 따라 완전히 다르게 동작한다.**
지금은 작성자가 쓰는 구성에 맞춰져 있고, 베타 사용자가 만들 구성(멤버 2명, 혹은 10명)에서는
다르게 보인다. → *작성자가 안 쓰는 경로* 갈래에 걸친다.

## 볼 것

### ① 멤버가 많아지면 색이 돌아 겹치는가
겹치면 **색이 식별 수단이 아니게 된다.** 몇 명부터 겹치는지 확인.

### ② 색만으로 구분하는 자리가 있는가
색각 차이 · 흑백 캡처 · 다크/라이트 전환에서 무너진다.
(⚠️ 이 프로젝트는 **캡처로 QA 를 한다.** 색만으로 구분하면 QA 자체가 어려워진다.)

### ③ 🔴 상태색과 충돌하지 않는가 — 이게 핵심이다
[D-01](D-01%20대화창%20상태%20표시.md) 에서 **상태를 색으로 알리려 하는데**,
멤버색이 **이미 색을 쓰고 있다.**

> **두 색이 같은 화면에서 경쟁한다.**
> 사용자는 어떤 색이 "누구"이고 어떤 색이 "무슨 상태"인지 구분할 수 없다.

**→ D-01 과 반드시 같이 정해야 한다. 그리고 이쪽이 먼저다.**
순서가 뒤집히면 D-01 을 두 번 만든다.

## 정해야 할 것

- **색을 자동 배정할지, 사용자가 고르게 할지.**
  자동이면 겹침 관리가 필요하고, 수동이면 만들 때 한 단계가 는다
  ([F-04](F-04%20멤버%20생성%20빠르게.md) 와 반대 방향).
- **색의 역할을 무엇 하나로 좁힐지.**
  선택지: ⓐ 색 = 멤버(상태는 다른 수단) · ⓑ 색 = 상태(멤버는 이름·아이콘) · ⓒ 영역을 나눈다.
  **⓵ ⓑ 중 하나로 좁히는 것이 가장 명확하다.**

## 참고

멤버 색은 이미 `memberColorVars`·`memberColor` 로 구현돼 있다.
색 토큰의 단일 소스는 `src/renderer/theme/themes.ts` 다 — 여기서 벗어난 하드코딩이 있는지도
같이 볼 것([D-04](D-04%20우클릭%20메뉴%20검은%20선.md) 와 같은 종류의 문제).
