# 첨부 파일 정책 (R-15 / R-16 / R-17)

붙여넣거나 끌어놓은 이미지를 **디스크상의 실제 파일**로 만들어, 세션이 파일로
다룰 수 있게 한다. 지금은 `ImageAttachment` 가 base64 바이트만 싣고 각 어댑터가
인라인 이미지 블록으로 바꾸므로, **디스크상의 위치가 애초에 없어서** 모델이
"이 이미지를 옮겨줘" 를 실행할 방법이 없다.

이 문서는 결정 사항과 그 근거, 그리고 **무엇으로 완료를 확인하는지**를 적는다.

---

## 1. 저장 위치 — 워크스페이스 안

```
<workspace>/.agent_party_app/attachments/<YYYY-MM>/<시각>-<이름>.<확장자>
```

- **워크스페이스 안(cwd 안쪽)** 에 둔다. 바깥(임시 폴더)에 두면 하네스의 권한
  정책에 막혀 모델이 못 읽는다 — 파일은 있는데 열리지 않는 최악의 결과가 된다.
- 파티별이 아니라 **워크스페이스별**로 모은다. 첨부는 멤버 사이를 오가므로
  파티에 묶으면 같은 파일이 여러 벌 생긴다. `usage/turns.jsonl` 과 같은 층위다.
- **월 단위 폴더**로 나눈다. 보존 정리를 폴더 단위로 할 수 있고, 한 폴더에
  파일이 무한히 쌓이지 않는다.

## 2. 경로 변환 (R-16) — 변환하지 않는다

WSL·원격 멤버에게 Windows 경로를 주면 못 연다. 흔한 해법은 경계에서 경로를
번역하는 것이지만, **번역은 틀릴 수 있고 틀려도 조용하다.**

대신 **읽을 쪽이 직접 쓴다**:

- 파일 쓰기는 `SessionManager.sendUserTurn` 에서 일어난다. 이 지점은 세션의
  워크스페이스를 알고, **그 세션을 소유한 엔진 안에서 실행된다.**
- 로컬 멤버 → 데스크톱 프로세스가 win32 경로로 쓴다.
- WSL 멤버 → 배포판 안의 engine-server 가 posix 경로로 쓴다
  (`engineServerEntry` 가 `--workspace <posix>` 로 뜬다).

경로는 **구조적으로** 그 세션이 열 수 있는 경로가 된다. 변환 코드가 없으므로
변환 버그도 없다.

## 3. 정리 정책 (R-17) — 지우되, 조용히 지우지 않는다

- 기본 보존 **30일**, 워크스페이스당 상한 **500MB**. 둘 다 설정에서 바꾼다.
- 정리는 앱이 워크스페이스를 열 때 한 번 돈다(상시 스케줄러 없음 — 기존
  `discovery` · Discord claim 정리와 같은 반응형 방식).
- **지운 것은 반드시 보이게 알린다.** 몇 개를 왜(기간 초과/용량 초과) 지웠는지
  진단(diagnostic)으로 띄운다. 대화 기록에 남은 옛 경로는 파일이 사라지면
  깨지는데, 그게 조용히 일어나면 나중에 원인을 찾을 수 없다.

## 4. 비전 미지원 모델 — 경로는 항상 보낸다

이미지를 못 보는 것과 파일을 못 다루는 것은 다르다. 경로만 있으면 복사·이동·
다른 도구 입력은 전부 가능하다. 그래서 **경로는 모든 하네스에 텍스트로 간다.**
이미지 블록만 비전 지원 여부에 따라 갈린다.

특히 Cursor 는 지금 이미지가 붙으면 **턴 전체를 거부**한다. 경로가 생기면
"이미지는 못 보지만 파일은 여기 있다" 로 바뀌어, 실패가 부분 성공이 된다.

---

## 5. 어떻게 확인하는가 (착수 전 결정)

"파일이 실제로 열리는가" 는 **화면 모양이 아니다.** 캡처로는 증명되지 않으므로
확인 방법을 셋으로 나눈다.

| # | 무엇을 | 어떻게 | 무엇이 통과인가 |
|---|---|---|---|
| 1 | 파일이 **생겼는가** | 자동화 API 로 이미지를 첨부해 턴을 보내고, 발표된 경로를 디스크에서 확인 | 파일이 존재하고 **sha256 이 입력 바이트와 같다** (0바이트 파일이 통과하지 않게) |
| 2 | 모델이 **열 수 있는가** | 실제 프로바이더 호출 1회. 첨부 후 *"그 파일 크기를 바이트 숫자만"* | 모델이 숫자를 답한다 = 파일 도구로 실제로 읽었다. "이미지만 받아서 위치를 모른다" 는 실패 |
| 3 | WSL 멤버도 **열 수 있는가** | 같은 것을 Ubuntu-22.04 멤버로 반복 (이 장비에 있음) | 배포판 안에서 posix 경로로 읽힌다 |

2번이 이 작업의 핵심이다. 1번만 하면 "파일은 만들었는데 모델은 여전히 못 쓴다"
를 통과로 착각한다 — 그게 원래 증상이었다.

정리(R-17)는 보존 기간을 짧게 준 워크스페이스에 오래된 파일을 심고 정리를
돌려, **지워진 사실이 진단으로 보이는지**까지 확인한다.
