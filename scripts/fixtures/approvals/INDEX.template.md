# 승인 카드 — 디자인 인계

> 이 폴더의 이미지는 **실제 하네스가 보낸 값**으로 그려졌다.
> `node scripts/demo-approval-cards.mjs` 로 언제든 다시 만들 수 있다(과금 없음).

---

## 0. 이 화면이 왜 중요한가

**AI 가 사용자 컴퓨터에서 명령을 실행하거나 파일을 고치기 직전에 멈춰 서서 묻는 화면**이다.
"허용"을 누르면 그 순간 실제로 실행된다. 되돌리는 버튼은 없다.

- **신규 사용자가 가장 많이 보는 화면이다.** 처음 온 사람은 AI 에게 권한을 다 주지 않으므로
  승인 모드가 기본 동선이 된다. (반대로 이 앱을 만든 사람은 거의 안 써서 검증이 가장 비어 있던 곳이다)
- **놓치면 작업이 멈춘다.** 사용자가 답할 때까지 AI 는 아무것도 못 한다.
  ⚠️ 지금 승인 대기를 알릴 경로가 최악의 경우 **탭의 26px 짜리 칩 하나**뿐이다
  (사이드바를 접고 패널을 나누면 나머지 표시가 전부 사라진다 — 별도 이슈).

## 1. 승인 유형 — 무엇에 대한 승인인가

하네스는 서로 다른 방식으로 묻지만 **사용자가 내리는 판단은 5가지**로 모인다.
**개별 명령이 아니라 이 유형이 디자인 단위다.**

### 유형 A. 임의의 명령 실행
> *"이 명령을 당신 컴퓨터에서 돌려도 되나?"* — **가장 흔하다**

**언제**: AI 가 셸을 써야 하는데 그 명령이 자동 허용 목록에 없거나, 샌드박스 밖으로 나가야 할 때.
**사용자의 판단**: 이 명령이 무엇을 하는가. 되돌릴 수 있는가.
**카드가 반드시 보여줄 것**: 실행될 명령 · 어느 폴더에서 · (있으면) 왜 필요한지
**인터랙션**: 위험 판단 → 재발 범위 선택(§2)

| | Claude | Codex |
|---|---|---|
| 명령 | 사람이 쓰듯 그대로 | **실행 래퍼가 붙어 온다** (`powershell.exe -Command '…'`). 읽기 좋은 형태는 따로 온다 |
| 위치 | 막힌 **파일 경로** | **작업 디렉터리** |
| 사유 | 보통 없음. AI 가 쓴 한 줄 설명은 있다 | 설정에 따라 문장으로 있거나 **아예 없다** |

### 유형 B. 파일 변경
> *"이 파일을 이렇게 고쳐도 되나?"*

**언제**: AI 가 파일을 쓰거나 수정하려 할 때.
**사용자의 판단**: 어느 파일이 어떻게 바뀌는가.
**카드가 반드시 보여줄 것**: **파일 경로 + 바뀌는 내용.** 없으면 판단 자체가 불가능하다.
**인터랙션**: 변경 내용 확인(길면 접기/펼치기) → 재발 범위 선택

| | Claude | Codex |
|---|---|---|
| 어떻게 오는가 | 편집 도구 입력에 **전/후 내용**이 들어 있다 | **승인 요청 자체는 비어 있다.** 따로 흐르는 변경 항목과 이어붙여야 내용이 나온다 |
| 여러 파일 | 한 번에 한 파일 | **한 승인에 여러 파일**이 붙을 수 있다 |

⚠️ 그래서 Codex 파일 변경 카드는 **원래 제목과 버튼만 있었다.** 이어붙이도록 고쳤다.

### 유형 C. 권한·경계 확장
> *"작업 범위 밖으로 나가도 되나?"* (네트워크, 허용되지 않은 폴더)

**언제**: AI 가 샌드박스가 막는 일을 하려 할 때.
**사용자의 판단**: 무엇을 열어주는 것인가. 얼마 동안인가.
**카드가 반드시 보여줄 것**: **무엇이 열리는지** — 어느 경로 / 어떤 네트워크

⚠️ **두 하네스가 구조적으로 다르다.**
- **Codex**: 독립된 승인 유형으로 온다.
- **Claude**: 독립 유형이 없다. **A·B 카드에 얹혀서** 온다 — 막힌 경로가 표시되고,
  해결책인 "이 폴더 허용"은 **세션 단위로만** 가능하다.

**→ 디자인 질문: Claude 는 "명령 승인"과 "폴더 허용"이 한 카드에 섞인다. 분리할 것인가?**

### 유형 D. 외부 도구(MCP)의 확인 요청
> *"연결된 외부 도구가 확인을 요청한다"*

**Codex 에만 있다.** 아직 실물을 못 봤다(§5).
**사용자의 판단**: 어느 서버가 무엇을 요구하는가.

### 유형 E. 값 요청 / 의사결정 — **승인이 아니다**
> *"어느 쪽으로 할까요?"*

**언제**: AI 가 위험한 일을 하려는 게 아니라 **진행하려면 사람의 결정이 필요할 때.**
A~D 와 성격이 완전히 다르다. **막는 게 아니라 묻는 것**이고,
거부/허용이 아니라 **고르기 · 직접 입력**이다.

**→ 디자인 질문: 같은 카드 계열로 보일 것인가, 다른 계열로 구분할 것인가?**

지원해야 하는 입력: 단일 선택 · 다중 선택 · 선택지별 설명 · 기타(직접 입력) ·
**비밀 입력(마스킹)** · 여러 질문 연속(이전/다음/건너뛰기)

| | Claude | Codex |
|---|---|---|
| 다중 선택 | 있음 | **없음** (항상 단일) |
| 직접 입력 | 항상 허용 | **질문마다 다르다** — 막힌 질문에 입력칸을 주면 거부당할 답을 유도한다 |
| 비밀 입력 | — | 질문마다 지정 |
| 자동 해소 시한 | — | **있다.** 답을 안 하면 시간이 지나 알아서 해소된다 ⚠️ 지금 남은 시간 표시가 없다 |

## 2. 재발 범위 — 유형 A~D 공통 인터랙션

승인은 "이번 건"만 정하는 게 아니라 **다음에도 물을지**를 함께 정한다. 이게 두 번째 축이다.

| 범위 | 누르면 실제로 (실측) | Claude | Codex |
|---|---|---|---|
| **거부** | 실행 안 됨. AI 에게 거부가 전달되고 보통 *"권한이 없어 못 했다"* 고 답한다 | ✅ | ✅ |
| **이번만** | 이번 건만. 같은 일을 또 하려 하면 다시 묻는다 | ✅ | ✅ |
| **이 세션 동안** | 이 대화 동안 안 묻는다. 앱을 끄면 사라진다 | **없음** | ✅ |
| **항상 (규칙)** | 규칙이 **디스크에 저장**된다. 앱을 새로 켜도 안 묻는다 | ✅ | 유형 A 만 |

**규칙이 어떻게 생겼는지가 하네스마다 크게 다르다** — 사용자가 무엇에 동의하는지 읽히느냐의 문제다.

- **Claude**: `echo one *` — **패턴이라 읽힌다.** "이걸로 시작하는 명령은 앞으로 허용"이 이해된다.
- **Codex**: 실행 경로까지 포함한 **명령 전체 한 줄.** 사실상 그 명령 하나뿐이고 **한 줄에 안 들어간다.**

⚠️ **"항상 허용"은 침묵을 약속하지 못한다.** 규칙은 저장되지만 *다른 이유*(유형 C)로 다시 물을 수 있고,
그건 세션 단위로만 허용된다. 그래서 버튼 설명이 *"앞으로 묻지 않습니다"* 가 아니라
*"'…' 규칙을 저장합니다"* 다. **실측 결과다.**

## 5. 그림이 없는 케이스 — **비워 뒀다**

실제로 본 적이 없어서 비웠다. 못 본 모양으로 카드를 그리면 추측이 그대로 스펙이 된다.
**버튼 구성은 코드상 확정**이므로 그것만 적는다.

| 케이스 | 유형 | 재발 범위 |
|---|---|---|
| Codex 권한 상승 | C | 거부 / 이번만 / 이 세션 |
| Codex 명령(규칙 제안 없음) | A | 거부 / 이번만 / 이 세션 |
| Codex 사용자 입력 | E | 질문 계열 (아직 실험 기능이라 호출되지 않는다) |
| Codex MCP 서버 요청 | D | 거부 / 이번만 / 이 세션 |
| Claude 서브에이전트 승인 | A·B | 거부 / 이번만 / 항상 — **누가 요청했는지 표시가 필요하다** |
| Cursor | — | **승인 화면 자체가 없다.** 실행 전에 미리 정해진다 |
